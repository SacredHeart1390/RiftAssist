# Riftbound Judge Assistant v0.1

로컬에서 실행하는 한국어·영어 규칙 검색/질의응답 프로토타입입니다. 공개 서비스나 계정 시스템은 포함하지 않습니다.

## 현재 기능

- Core Rules와 Tournament Rules의 영문/공식 한국어 PDF를 규칙 번호에 맞춰 로컬 색인합니다. 한국어 화면에서는 공식 한국어를 기본으로 표시하고 영문은 출처 링크로 제공합니다. 근거는 기본 접힘 상태이며 조항 번호 옆 화살표로 펼칩니다.
- RiftJudge는 질문마다 공개 검색으로 사례를 찾습니다. 한국어 한 줄 제목을 답변 생성과 함께 만들고, 사례를 처음 펼칠 때 제공된 질문/답변을 한국어로 번역합니다. 펼친 내용에는 검증 상태·룰 버전·작성일·원문 링크·사례 적용 설명을 보존합니다. 번역은 AI 번역으로 구분합니다. 원문 일부만 검색된 경우에는 그 범위만 번역합니다.
- 카드 찾기 버튼 없이 질문 입력 중 2글자 이상의 카드명 일부를 검색합니다. 이름 중간에 포함된 글자도 찾으며 최대50개 후보를 스크롤해서 고를 수 있습니다. 선택한 이름은 문장 안에서 강조하고 ID로 모델 근거에 연결합니다. 카드 검색에는 AI API를 사용하지 않습니다.
- OpenAI Responses API에 질문과 검색 근거를 보내 적용 방법과 이유를 생성합니다. 근거가 부족하거나 필요한 상황 정보가 빠지면 이를 표시합니다. 모델 출력의 조항/사례 인용은 실제 검색 결과 ID로 제한합니다.
- 이미지 첨부를 지원합니다. OpenAI API 키가 설정되고 AI 생성이 켜졌을 때만 사진을 질문과 함께 OpenAI에 보내며, RiftJudge에는 사진을 보내지 않습니다. 로컬 요청 로그에도 사진 데이터는 저장하지 않습니다.
- 질문/답변 대화 내역은 화면에 보관하지 않습니다. 기본 로그는 처리 유형·검색된 출처 ID·상태·토큰 수·처리 시간 같은 메타데이터만 기록합니다. 본문 로그는 `LOG_CONTENT=true`로 명시적으로 켠 경우에만 기록됩니다.

## 로컬 실행

Node.js 22.13 이상이 필요합니다.

```powershell
npm install
if (!(Test-Path .env)) { Copy-Item .env.example .env }
# .env를 열어 본인 OpenAI API key 입력
# 결제·한도 준비 전에는 OPENAI_GENERATION_ENABLED=false 유지
npm start
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다. 기본값 `OPENAI_GENERATION_ENABLED=false`에서는 키를 저장해도 OpenAI 생성 API를 호출하지 않으며, 공식 룰과 RiftJudge 사례 검색만 실행됩니다. 결제·사용 한도를 준비한 뒤 `true`로 바꾸고 서버를 재시작하면 생성형 답변과 사진 분석을 활성화할 수 있습니다. 키 설정과 실제 API 호출 성공은 별개입니다. 자세한 절차는 [API_SETUP.md](API_SETUP.md)를 참고하세요.


`OPENAI_API_KEY`는 브라우저 코드에 넣지 말고 로컬 `.env` 파일에만 둡니다. 모델 기본값은 `gpt-6-luna`이며, `OPENAI_MODEL`과 `OPENAI_REASONING_EFFORT`로 바꿀 수 있습니다. ChatGPT 구독과 API 사용은 별도 결제 시스템이며, 앱에는 OpenAI API 프로젝트 키와 사용 권한이 필요합니다. 자세한 내용은 [OpenAI API billing 안내](https://help.openai.com/en/articles/9039756)를 확인하세요.

## 규칙 갱신

색인 원본/링크와 규칙 조항은 `sources-manifest.json`, `knowledge/evidence.json`에서 확인할 수 있습니다. 현재 색인의 PDF 파일은 빌드 임시 폴더에 보관하지 않습니다. 색인을 새로 만들려면:

```powershell
npm run sync:rules
```

이 명령은 공식 PDF를 다시 내려받고, PDF의 조항 번호로 영문과 한국어 본문을 연결합니다. RiftJudge는 각 질문 시점에 원격 검색하므로 사이트의 최신 검색 인덱스를 사용합니다. 데이터 날짜·변경 이력을 공개 배포 전에 추가하고, 패치 노트와 정오표를 함께 확인한 뒤 최신 개정 규칙을 활성화해야 합니다.

v0.1은 수동 동기화 방식입니다. 매일 자동 확인과 변경 승인 화면은 공개 전 단계에 추가할 작업입니다.

## 로컬 로그 및 개인정보

- `logs/requests.jsonl`은 로컬 파일이며 기본값은 메타데이터만 저장합니다.
- 본문까지 기록하려면 `.env`에서 `LOG_CONTENT=true`로 바꿉니다. 사용자 질문이 다른 사람에게 공개되는 서비스 기능은 포함하지 않습니다.
- 질문은 RiftJudge 검색 API로 전송됩니다. OpenAI 키가 설정되고 AI 생성이 켜진 경우 질문과 검색 근거, 선택 첨부 사진은 OpenAI API로 전송됩니다. 모델 요청은 `store: false`를 사용합니다.
- 첨부 사진은 모델 요청이 끝나면 서버에서 저장하지 않습니다. 브라우저 미리보기는 새 질문을 누르면 지워집니다.
- API 키, OpenAI 계정, 사용 요금, 데이터 처리 조건은 OpenAI 플랫폼에서 별도로 관리합니다.

## 한국어 근거 번역과 비용

- 공식 한국어가 있는 규칙은 추가 번역 호출 없이 표시합니다. 한국어가 없는 규칙과 RiftJudge 질문/답변은 펼칠 때 번역합니다.
- `knowledge/source-translations/`에는 질문자의 입력과 별도로 공개 출처 원문 스냅샷과 번역을 저장합니다. 원문·버전·용어표·모델·번역 프롬프트 해시가 같으면 다른 질문/서버 재시작에서도 재사용합니다. 전체 RiftJudge 색인은 아닙니다.
- 번역 최초 생성은 별도 OpenAI API 사용량이 발생합니다. 동시에 같은 번역을 요청하면 호출을 합치며, 다른 자료의 번역은 최대2건 동시 처리합니다. 출력 한도는 기존 `OPENAI_MAX_OUTPUT_TOKENS`를 사용합니다.
- 실패나 출력 한도 초과 시 부분 번역을 완료본처럼 표시하지 않고 출처 링크와 수동 재시도를 제공합니다. 자동 유료 재시도는 없습니다. 생성 중지 설정은 번역에도 적용됩니다.
- 번역 호출의 출처 ID·해시·모델·토큰·처리 시간은 기존 메타데이터 로그에 별도 이벤트로 기록합니다. 캐시에는 자동 삭제 정책이 아직 없습니다.

## 데이터 파일

- `knowledge/evidence.json`: Core Rules/Tournament Rules의 영어·공식 한국어 조항 색인
- `sources-manifest.json`: 공식 문서와 RiftJudge 검색 연결 상태
- `logs/requests.jsonl`: 로컬 진단 로그 (`.gitignore` 대상)
- `tmp/pdfs/`: 규칙 PDF 동기화 중 사용하는 임시 캐시 (`.gitignore` 대상)
- `knowledge/cards.json`: 리프트나루 공개 표시 자료1,527판본의 로컬 색인. 공식 검증 전 참고 자료이며 본문1489개만 모델 입력 가능. 수집일2026-10-18.

카드 자동완성, 키보드 선택, 선택 카드 미리보기, 카드 ID/원문 연결 및 사례 공통점·차이점 표시 코드를 추가했다. 전체 카드 DB는 모델에 전송하지 않는다. 가져오기·갱신·토큰 예산·검증 한계는 [RIFTNARU_DATA.md](RIFTNARU_DATA.md)를 참고한다.
