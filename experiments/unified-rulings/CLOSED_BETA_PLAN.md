# Riftbound Judge — 공개형 베타 배포 및 오류 리포트 설계

갱신: 2026-10-19 · 상태: **집 PC 운영 코드 일부 구현, 실행 검증·공개 배포 전**

최신 결정/실제 구현 범위는 [HOME_HOSTING.md](HOME_HOSTING.md) 참고. 집 PC 상시 실행, 서비스 이름 리프트어시로 확정했다. 별도 로컬 관리자·SQLite 운영DB·제보·호출 제한을 추가했으나 아직 실행 검증하지 않았다. 무료 공개 주소를 비교한 뒤 사용자가 선택할 예정이다. 아래 설계의 클라우드·첨부 저장·금액 예산 항목은 현재 구현 완료로 취급하지 않는다.

사용자 정정 반영: 초대코드 없이 누구나 URL로 이용하고 검색으로도 발견할 수 있는 공개형 베타. 기존 문서 링크를 보존하려고 파일명은 CLOSED_BETA_PLAN.md로 유지하지만, 초대형 설계는 폐기했다.

## 1. 확정된 방향과 제안값

- 사용자가 통합본을 앞으로의 개발 기준으로 채택했다. 작업 위치는 `experiments/unified-rulings/`이며 로컬 주소는3001이다.
- 프로젝트 루트의 기존 분리형 앱은 백업으로 보존한다. 삭제하거나 통합본으로 덮어쓰지 않는다.
- 누구나 가입·초대코드·승인 대기 없이 URL로 접속해 질문하는 공개형 웹/PWA 베타를 준비한다. 처음에는 아는 사람에게만 URL을 알리더라도 다른 방문자의 이용을 막지 않는다. 서비스 소개/사용법은 검색 수집을 허용하고 질문·답변·리포트는 공개 게시하지 않는다.
- 오류 제보는 운영자 전용 데이터로 관리한다. 이용자에게 다른 사람의 질문이나 제보 내용을 공개하지 않는다.
- 집 PC를 계속 켜두고 운영하기로 사용자가 확정했다. OpenAI API 비용은 별도다. 무료 클라우드는 향후 필요할 때 고려한다.
- 실제 코드에 반영한 한도·보유 기간은 HOME_HOSTING.md가 우선한다. 그 외 내용은 후속 설계이며 외부 공개는 아직 하지 않았다.

초기 피드백 협조자5~10명 → 수정 후 더 많은 사람에게 URL 안내를 제안한다. 이는 이용 자격/인원 제한이 아니다. 검색 유입과 링크 재공유를 전제로 사용량을 제한한다.

## 2. 최초 설계 시점의 변경 목록 (현재 진행은 HOME_HOSTING.md 참고)

| 현재 확인 상태 | 필요한 작업 |
|---|---|
| `src/server.js`가127.0.0.1에 고정 바인딩 | 집 PC 터널은 localhost 유지, 무료 클라우드는 HOST/PORT 환경 설정 지원 |
| 질문·카드·번역 API에 공개 서비스용 통제 없음 | 가입 없이 쓰는 익명 세션, 속도/비용 제한, 개인 요청·리포트 소유권, 관리자 인증 적용 |
| 번역 API Origin 허용값이localhost/127.0.0.1 | 실제 HTTPS 원본 주소 설정, 변경 요청 CSRF 방어 |
| JSONL 메타데이터 로그, `LOG_CONTENT=false` | 보유 정책이 있는 DB 기록과 요청별 재현 자료 도입. 단순히 LOG_CONTENT=true로 전환하지 않음 |
| 카드·규칙은 로컬 JSON, 번역은 로컬 파일 | 승인된 데이터 버전 묶음과 영속 번역 캐시 사용 |
| 질문별 입력/출력 상한은 있으나 이용자/서비스 전체 지출 제한 없음 | 요청 제한·동시 실행 제한·비용 예약/정산·운영 중지 스위치 |
| 리포트·관리 화면 없음 | 제보 UI/API/DB와 관리자 처리 이력. 초대 관리 기능은 만들지 않음 |
| Dockerfile은 있으나 knowledge 전체를 복사 | 배포 허용 자료만 포함, 캐시·제보·로그·비밀키·임시 파일 제외. 빌드 범위는 통합본 폴더로 한정 |
| PWA가 정적 앱을 캐시하고 즉시 새 워커로 전환 | 작성 중 강제 새로고침 방지, 새 버전 안내, API/개인 자료 캐시 금지, 이전 클라이언트 호환 |

질문·번역·사진 기능의 배포 환경 동작과 통합 검색 정확도는 아직 검증되지 않았다. 로컬에서 화면이 열린 사실을 배포 준비 완료로 취급하지 않는다.

## 3. 무료 운영과 집 PC 운영 비교

### 후속 대안: PC를 끄고도 운영하는 무료 클라우드 베타

**Render Free(Node 앱) + Supabase Free(PostgreSQL·비공개 첨부 저장소).** 현재 Node 코드를 유지하기 쉬운 조합이다. 무료 자원 범위에서 호스팅비를0원으로 시작하는 제안이며, 무제한·항상 즉시 응답·영구 무료를 보장하지 않는다.

```text
사용자 → 공개 HTTPS 앱(Render) → 규칙/카드 검색 + RiftJudge + OpenAI
                              → Supabase DB: 요청·리포트·번역·사용량
                              → 비공개 Storage: 선택 첨부
운영자 → 관리자 인증 → 리포트 검토/내보내기 → 수정/검수 → 배포
```

- Render 무료 서버는15분간 미사용 시 절전하고 다음 접속 때 약1분의 기동 지연이 있을 수 있다. 원본 파일 변경은 재기동/재배포 시 소실되므로 로그·번역·리포트·첨부는 외부 DB/Storage에 둔다. 무료 이용 시간·전송량·외부 API 트래픽 정책도 적용된다. 무료 Render Postgres는30일 만료이므로 이번 저장소로 사용하지 않는다. [공식 조건](https://render.com/docs/free)
- Supabase Free는 현재 DB500MB, 파일1GB, 전송량 제한이 있고 낮은 이용량이7일간 지속되면 일시 정지될 수 있다. 정지되면 운영자가 복원해야 하며 항상 자동으로 재개된다고 가정하지 않는다. 자동 백업/PITR도 무료 플랜에 포함되지 않으므로 별도 내보내기·복구 절차가 필요하다. [요금/한도](https://supabase.com/pricing), [일시 정지 조건](https://supabase.com/docs/guides/platform/free-project-pausing)
- 운영자 계정을 만드는 것과 방문자 가입은 별개다. 무료 서비스 계정은 운영자만 준비한다. 유료 요금제·추가 옵션을 자동으로 선택하지 않고, 결제 수단이 있는 계정은 초과 과금 설정을 실행 전에 확인한다. 용량/요청 한도에 접근하면 수집·첨부·생성을 줄이거나 중단한다.
- 잠든 서버를 깨우는 중이라는 안내와 재시도 UI를 준비한다. 이 재시도는 상태 확인/연결용이며 같은 유료 생성 요청을 중복 실행하지 않는다. 서버가 준비되지 않으면 질문 전송을 막고 작성 내용은 유지한다.
- 기존 색인 JSON은 승인된 버전만 배포 파일에 포함해 읽는다. 바뀌는 번역 캐시·원문 스냅샷은 DB로 이전한다. 소스 파일/비밀키·리포트 데이터가 섞이지 않도록 배포 패키지를 분리한다.
- DB300MB/첨부600MB를 내부 경고선 예시로 두고, 실제 무료 한도 전에 신규 첨부/본문 저장을 제한한다. 만료된 데이터는 삭제하되 신고 조사 중인 자료를 임의로 먼저 삭제하지 않는다. 저장 여유가 없으면 새 유료 요청을 거절하고 이유를 표시한다.
- DB 백업은 초기에는 운영자가 정기 내보내기를 내려받아 암호화 보관한다. 이는 PC를 상시 켜둘 필요가 없지만 백업의 최신성이 수동 운영 주기에 좌우됨을 명시한다. 무인 백업은 무료 실행량/별도 저장소를 확인한 뒤 추가한다.

### 검색 유입과 공개 주소

- 일반 이용자는 고정된 HTTPS 주소로 바로 접속한다. 초대 페이지·비밀번호·이메일 확인을 앞에 두지 않는다.
- 홈/소개/사용법에는 서비스 제목·설명·실제 읽을 수 있는 소개 문구, canonical URL, sitemap/robots 설정을 준비한다. 로그인 벽이나 전체 noindex를 적용하지 않는다. Google Search Console 등록은 선택 가능한 운영 작업이며 색인/노출 시점은 보장할 수 없다. [Google 안내](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)
- Render 무료 서버는 절전 중 robots.txt에 disallow 응답을 내므로 검색 유입에 불리할 수 있다. 검색용 소개·사용법 페이지를 무료 정적 호스팅(예: Cloudflare Pages)에 두고 실제 질문 앱으로 연결하는 보완안을 포함한다. 앱의 질문 화면은 Render URL로 직접 접속할 수도 있다. 정적 안내 페이지만으로 AI 서버가 대체되는 것은 아니다. [Render 동작](https://render.com/docs/free), [Pages](https://developers.cloudflare.com/pages/)
- 개인 질문·답변·제보·관리자 URL은 검색 대상이 아니다. API/개인 데이터는 인증된 익명 세션 또는 별도 권한으로 보호하고 noindex만으로 보안을 대신하지 않는다.

### 대안: 집 PC에서 운영

- 집 PC에서 통합 Node 앱 + 로컬 PostgreSQL + 비공개 첨부 폴더를 운영한다. 별도 서버 임대료는 없지만 전기·인터넷·OpenAI 비용은 남는다.
- 고정 공개 주소를 연결하는 Cloudflare Tunnel 같은 방식을 우선 검토한다. 앱은127.0.0.1에 두고 터널 커넥터가 외부와 연결한다. 실제 외부 노출은 별도 실행 단계에서 수행한다. [터널 구조](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/)
- **PC 전원·네트워크·앱·터널이 모두 살아 있어야 한다. PC 종료/절전/정전 시 새 질문은 처리되지 않는다.** CDN/설치형 PWA가 화면 일부를 보여줘도 AI 기능이 계속 작동하는 것은 아니다.
- 안정적인 공개 주소에는 보유 도메인 연결 또는 별도 주소 제공 방법 확인이 필요하며 도메인 비용이 생길 수 있다. 무료 Quick Tunnel 주소는 임시 테스트용이므로 장기 공유/검색용 기준 주소로 쓰지 않는다. [Quick Tunnel 조건](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
- 부팅 후 앱/터널 자동 시작, 장애 시 재시작, 절전 정책, DB·첨부 백업, 업데이트 시간을 준비한다. 관리자 화면과 DB 포트는 공개 터널에서 제외한다. 일반 서비스 계정은 필요한 앱 폴더만 읽게 한다.
- 무료 클라우드의 대기/일시 정지를 받아들이기 어렵다면 이 방식을 선택하되 PC를 켜두어야 한다. 지금은 두 경로의 설계만 보존하고 설치·설정 변경은 하지 않는다.

### 다른 무료 후보를 바로 채택하지 않는 이유

Cloudflare Workers/D1도 무료 범위가 있지만 Workers Free의 요청당 CPU10ms 제약에 맞춰 현재 전체 문서 순회 검색·파일 쓰기 구조를 바꿔야 한다. 기존 앱이 그대로 맞는지 확인되지 않았으므로 이번의 최소 변경안으로 확정하지 않는다. [Workers 한도](https://developers.cloudflare.com/workers/platform/limits/)

## 4. 가입 없는 이용과 관리자 보호

1. 누구나 URL을 열고 바로 질문한다. 초대코드·개별 허가·이용자 로그인 기능은 만들지 않는다.
2. 서버가 자동 발급하는 무작위 익명 세션 쿠키로 요청/제보를 연결한다. 이는 접근 자격이 아니라 같은 브라우저의 자료를 구분하는 장치다. HttpOnly/Secure/SameSite 설정을 적용한다.
3. 익명 세션 ID는 실제 사람을 식별하지 못한다. 쿠키 삭제로 바뀔 수 있으므로 세션별 제한만 믿지 않고 단기 네트워크 식별·서비스 전체 지출 한도·동시 실행 제한을 함께 적용한다. 공유 네트워크 이용자를 한 사람으로 단정하지 않는다.
4. 평상시 질문 흐름에는 확인 단계를 추가하지 않는다. 비정상 반복 요청에는 속도 제한이나 봇 확인을 적용할 수 있다. 전체 한도에 도달하면 새 AI 호출을 중지한다.
5. 제보 조회는 같은 익명 세션으로 제한한다. 다른 기기에서 조회가 필요하면 충분히 긴 별도 조회 비밀값을 제공하고 서버에는 해시만 저장한다. 접수번호만 알아서는 본문/첨부를 볼 수 없다. URL에 비밀값이 남지 않게 교환한다.
6. 관리자만 별도 인증과 다중 인증을 사용한다. 초대 관리 대신 리포트·예산·차단/해제·점검 상태를 관리한다. 집 PC에서는 관리자 도구를 로컬 전용으로 둘 수 있다.

API 키와 DB/Storage 관리 자격증명은 서버에만 둔다. Supabase를 사용할 때 공개 클라이언트 키가 있어도 리포트/원문 테이블을 직접 읽을 수 없도록 권한을 차단한다. 요청 소유권·파일 권한·CSRF·입력 검증은 가입 유무와 무관하게 유지한다.

## 5. 오류 제보 UI

앱 하단의 항상 보이는 문구:

> 답변이 틀리거나, 이용 중 오류가 있으신가요? **[문제 제보하기]**

각 답변 아래에도 **[이 답변 제보하기]**를 둔다. 하단 버튼은 화면 오류용으로도 사용할 수 있어야 한다. 답변 생성에 실패했거나 답변이 없는 상태에서도 열려야 한다.

### 제보 창 예시

```text
문제 제보하기

어떤 문제가 있었나요?  [앱 이용 문제] [답변·근거 문제] [잘 모르겠어요]
세부 항목              [선택 목록 / 여러 개 선택 가능]
어떤 점이 이상했나요?  [짧은 설명 입력]
예상한 결과 / 참고 링크 [선택 입력]
스크린샷 첨부          [선택, 최대3장]

함께 보낼 내용         [현재 질문·답변·근거 보기] [포함하지 않기]
                       앱 버전·오류 코드·기기 환경이 함께 전송됩니다.
                       게임 사진은 자동으로 포함하지 않습니다.

[취소]                 [제보 보내기]
```

- 필수: 문제 유형1개와 짧은 설명. 세부 항목은 선택 사항이며 ‘잘 모르겠어요’를 제공한다. 제보자가 정답이나 조항 번호를 알아야 할 필요가 없다.
- PC는 모달, 모바일은 화면에 맞는 패널. 키보드 이동·닫기·스크린리더 레이블과 작은 화면 스크롤을 지원한다.
- 답변 버튼으로 열면 그 답변의 requestId를 고정한다. 새 질문을 작성하거나 다른 답변이 표시되어도 이미 열린 제보 대상이 바뀌지 않는다.
- 첨부될 질문·답변을 미리 볼 수 있게 한다. 전체 제외를 선택하면 해당 본문을 리포트 장기 보존본으로 복사하지 않는다. 진단 제한이 생긴다는 짧은 안내만 표시한다.
- 게임 사진과 화면 스크린샷은 자동 수집하지 않는다. 사용자가 선택한 파일만 보낸다. 스크린샷은 개인정보를 가릴 수 있도록 안내하고 전송 전 미리보기/제거를 제공한다.
- 전송 성공은 DB 저장이 확인된 뒤 표시한다. 접수번호와 처리 상태 링크를 제공한다. 실패하면 입력 내용을 현재 창에 유지해 재전송할 수 있게 한다.
- 두 번 클릭하거나 네트워크 재전송이 발생해도 같은 submission key는 같은 접수번호를 반환한다. 제보 저장 과정에서 AI를 호출하지 않는다.

### 유형과 태그

| 1차 유형 | 선택 가능한 세부 항목 |
|---|---|
| 앱 이용 문제 | 글씨/배치 깨짐, 모바일 화면, 입력/카드 자동완성, 사진 첨부, 느림/멈춤, 전송 실패, 원문 링크/접이식 오류, 기타 |

사용자가 선택한 유형과 운영자가 확인한 원인/심각도는 별도 필드다. ‘판정 오류’로 접수되었다고 오류가 확정된 것은 아니다.

## 6. 재현에 필요한 기록

**핵심: URL/조항 ID만 남기지 않고, 그 답변에 실제 사용한 내용과 버전을 고정한다.** 출처가 나중에 바뀌어도 당시 검색 결과를 확인할 수 있어야 한다.

| 기록 | 저장할 내용 |
|---|---|
| 요청 | 서버 requestId, 클라이언트 요청 ID, 익명 session ID, 질문, 언어, 시간, 성공/실패/중단 상태 |
| 답변 | 실제 전달한 구조화 답변, 인용 ID, 사례 비교, 확인 질문, 화면에 보인 오류 코드 |
| 카드 | 선택한 카드 ID·판본·내용 해시·실제로 모델에 전달한 카드 본문 |
| 검색 | 검색어, 후보 ID·점수, 선택/제외 결과, 검색 실패/시간 초과, 전체 데이터 버전, 대회 맥락 검색 힌트 |
| 근거 | 실제 사용한 공식 조항·Q&A 발췌, URL, 룰 버전, 수집 시각, 커뮤니티 검증 상태, 원문 일부 여부 |
| 번역 | 사용자에게 표시된 번역, 원문 해시, 번역 프롬프트 버전, 모델, 캐시 ID. 펼쳐 본 번역 요청을 부모 requestId에 연결 |
| 생성 | 모델/추론 설정/출력 상한, 프롬프트 템플릿 버전, 공급자 응답 ID, 토큰 사용량, 처리 시간, 오류 코드 |
| 화면 | 앱 빌드·클라이언트 버전, 서버 릴리스, 운영체제/브라우저 종류와 주요 버전, 화면 크기, 구조화한 프런트엔드 오류 코드 |
| 제보 | 유형·태그·설명·선택 참고 링크·첨부·접수 시각·당시 상태·처리 이력 |

- ‘진행 로그’는 검색·선택·생성·번역·오류 등 관찰 가능한 처리 기록이다. 모델의 숨겨진 사고과정을 저장하거나 제공한다는 의미가 아니다.
- 입력 단계부터 requestId/clientRequestId를 연결한다. 응답 시간 초과, 통신 단절, 출력 한도, 예산 초과도 추적한다. 서버에 도착하지 않은 화면 오류는 requestId 없이 리포트할 수 있다.
- 코드 템플릿과 원문 스냅샷은 해시별로 한 번 저장하고 여러 리포트가 참조한다. 제보가 참조하는 스냅샷은 해당 리포트 보유 기간이 끝날 때까지 보존한다.
- 과거 자료를 이용한 재현과 현재 자료로 다시 검색한 결과를 구분한다. 모델 출력은 같은 입력에도 달라질 수 있으므로 원래 답변을 반드시 보존한다.
- 비밀키·세션 쿠키·인증 헤더·제보 조회 비밀값·다른 사용자 정보는 기록하지 않는다. 콘솔 전체 덤프 대신 허용된 진단 필드만 수집한다.
- 이미지 내용은 기본 기록하지 않으므로 이미지 판독 문제는 재현이 제한될 수 있다. 제보자가 원래 사진을 다시 첨부한 경우에만 이미지 포함 재현이 가능하다.

## 7. 데이터베이스 설계

리포트용 테이블/스키마를 일반 질의와 분리하되, 초기에는 **Postgres 한 개 안에서 논리적으로 분리**한다. 별도 DB 서버를 추가하는 비용은 피한다. 아래는 설계 스키마이며 SQL 마이그레이션은 아직 만들지 않았다.

| 테이블 | 핵심 필드/역할 |
|---|---|
| anonymous_sessions / admin_accounts | 익명 세션 해시·만료·차단 상태·정책 고지 버전; 관리자 인증 ID/권한은 별도 관리. testers/invites 테이블은 만들지 않음 |
| requests | UUID PK, anonymousSession FK, clientRequestId, status, language, encryptedQuestion/Answer, releaseId, promptVersion, model, usage, latency, errorCode, expiresAt |
| request_events | requestId FK, 순번, stage, 시각, duration, outcome, 허용된 구조화 메타데이터 |
| source_snapshots / request_sources | 해시 PK, 출처 종류·원문·URL·버전·상태; 요청별 후보 점수·순서·모델 투입 여부·인용 여부 |
| translations | 원문/용어표/모델/프롬프트 기반 키 UNIQUE, 번역 본문, 상태, 생성 시각, 폐기/교체 이력 |
| reports | UUID PK, 접수번호 UNIQUE, anonymousSession FK, requestId nullable, 유형, 태그, 설명, 예상 결과/참고 링크, status, severity, duplicateOf, createdAt/updatedAt/expiresAt |
| report_snapshots | reportId UNIQUE FK, 그 시점 질문·답변·실행 메타데이터 사본, 참조한 source/translation ID, 본문 포함 여부·원본/가림 처리 구분 |
| report_attachments | reportId FK, privateObjectKey, 실제 MIME, 크기, 내용 해시, 삭제 기한 |
| report_events | reportId FK, 변경 전후 상태, 작성자, 메모, 원인, 변경 시각; 처리 이력 추가 방식 |
| issues / releases / issue_reports | 확인된 원인별 묶음, 담당·심각도·수정 커밋·검수 근거·해결 버전; 여러 제보가 하나의 원인에 연결 |
| usage_budgets / usage_reservations | 익명 세션/네트워크/서비스/기간별 한도, 동시 실행, 비용 예약·정산·실패 시 미확정 사용량 |
| admin_audit | 관리자 조회·내보내기·변경·배포 관련 감사 기록. 본문 내용은 중복 기록하지 않음 |

인덱스: reports(status, createdAt), reports(requestId), reports(type, severity), requests(anonymousSessionId, createdAt), events(requestId, sequence), 만료 시각. 제보 소유권과 요청 소유권은 서버에서 검증한다. 해시는 일치 비교용이며 민감한 본문 암호화를 대신하지 않는다.

## 8. 저장 고지와 보유 기간 제안

사용자 화면에 채팅 목록을 만들지 않는 것과 서버에서 진단 기록을 보관하는 것은 별개다. 클로즈 베타의 품질 확인을 위해 다음을 제안한다.

| 자료 | 초기 제안 |
|---|---|
| 일반 질문·답변·개별 검색 실행 본문 | 암호화하여7일, 이후 삭제 |
| 처리 상태·토큰·시간 등 최소 메타데이터 |30일 |
| 제보 본문과 동결한 재현 자료 | 접수 후90일. 기간 만료 전 필요 자료를 비식별 평가 문항으로 별도 검토 |
| 제보자가 선택 첨부한 스크린샷/사진 |30일 |
| 원래 질문에 첨부한 게임 사진 | 서버의 지속 저장소에 기본 저장하지 않음 |
| 비식별 승인 평가 문항/코드 수정 이력 | 운영 자료로 별도 관리, 개인 원본 삭제 여부와 분리 |

- 현재 로컬의 메타데이터 중심 정책과 다른 **제안**이다. 실제 적용 전에 고지·처리 목적·적용 가능한 법적 근거·삭제 요청 경로를 확정한다. 이번에는 저장 설정을 바꾸지 않는다.
- 질문창 고지 예: ‘베타 품질 확인을 위해 질문·답변과 사용한 근거를7일간 보관합니다. 질문과 근거는 답변 생성에 필요한 외부 서비스로 전송됩니다. 제보에 포함한 내용은90일, 첨부 자료는30일간 보관합니다. 자세히 보기.’
- ‘질문했으니 모든 목적에 동의한 것’으로 설계하지 않는다. 불필요한 필수 체크박스 대신 실제 처리에 맞는 명확한 고지와 필요한 선택 동작을 설계한다. 상세 규정은 출시 전 확인 항목이다.
- 보유 기간은 정기 삭제 작업으로 집행한다. DB 본문뿐 아니라 스냅샷 참조·객체 저장소·내보낸 임시 파일·백업 만료 정책도 포함한다. 공유되는 공개 출처 사본은 사용자 연결과 분리한다.
- 백업 복원으로 삭제된 자료가 되살아나지 않도록 삭제 기록을 재적용한다. 공급자별 별도 보유 정책은 서비스 내부 삭제와 구분해 고지 문서에서 확인한다.

## 9. API와 관리 도구 경계

| 예정 API | 역할 |
|---|---|
| POST /api/session | 로그인 없이 익명 세션 자동 발급/갱신. 초대/가입 API는 없음 |
| POST /api/ask | 익명 세션 연결·공개 요청 속도 제한·예산 예약·중복 방지·요청 기록 후 답변 실행 |
| POST /api/sources/translate | 익명 세션·요청 소유권·예산·원문 검증, 부모 requestId 연결, 캐시 재사용 |
| POST /api/reports | 유형/태그 검증, 본인 요청 연결, 고정 스냅샷 저장, 중복 전송 방지 |
| POST /api/reports/:id/attachments | 본인 제보에 선택한 첨부만 업로드 |
| GET /api/reports/:id/status | 본인 접수의 공개 가능한 상태/해결 버전만 제공 |
| GET /api/admin/reports, GET /api/admin/reports/:id | 관리자 목록 필터/상세/연결된 재현 자료 |
| PATCH /api/admin/reports/:id | 상태·심각도·원인·중복 묶기, 처리 이력 필수 |
| POST /api/admin/reports/export | 선정 건만 가림 처리하여 분석용 JSONL/Markdown 내보내기 |
| 관리자 한도/중지 API | 한도 변경·남용 제한·AI 생성 중지. 관리자만 실행 |

- 앱이 HTTP 오류를 내더라도 가능한 경우 오류 ID와 제보 진입 버튼을 남긴다. DB 장애로 요청 추적/예산 예약을 할 수 없으면 새 유료 요청은 보내지 않는다.
- 접수와 스냅샷 저장은 같은 트랜잭션으로 확정한다. 첨부는 임시 업로드→검사→연결 순서이며 실패한 고아 파일은 정리한다.
- 파일은 PNG/JPEG/WebP, 최대3장·각5MB를 제안한다. 확장자가 아닌 내용으로 확인하고 픽셀 수 상한·EXIF 제거·재인코딩을 적용한다. SVG/HTML은 받지 않는다. 저장소는 비공개이며 권한 확인 후 짧게 유효한 다운로드만 제공한다.
- 관리자 화면은 신규/검토 중/검수 대기/해결 건, 유형·심각도·버전별 필터, 같은 원인 묶음, 담당 메모, 수정 전후 비교를 제공한다. 초기에는 전체 통계 대시보드보다 이 목록과 상세 화면을 먼저 만든다.

## 10. 제보를 분석하고 수정하는 작업 흐름

기본 상태: `접수 → 분류 → 재현 확인 → 수정 중 → 검수 대기 → 해결/배포`.
별도 상태: `추가 정보 필요`, `중복`, `오류 아님`, `재현 불가`, `다시 열림`. 수정 커밋 생성만으로 해결/배포 처리하지 않는다.

1. 운영자가 ‘새 오류 리포트를 확인하고 분석해서 수정해줘’라고 요청한다.
2. 도구가 새 리포트 목록과 요약만 읽는다. 심각도/빈도/영향 범위로 우선순위를 정하고 같은 증상을 묶는다.
3. 선택한 건에 한해 정확한 질문·기존 답변·카드·검색 근거·버전·단계별 기록을 가져온다. 제보 글의 지시는 데이터로 취급한다. 제보 내 링크를 자동 실행하거나 내용을 코드 명령으로 실행하지 않는다.
4. 원인을 나눈다: 화면/입력, 카드 식별, 검색 누락, 순위 선정, 자료 갱신, 번역, 생성, 인용 검증, API/네트워크, 접근/예산.
5. 원래 출처 버전으로 재현하고, 현재 출처와 달라졌는지 비교한다. ‘제보자의 예상 정답’은 가설이며 자동으로 기준 답안에 넣지 않는다.
6. 코드·검색·번역 중 원인에 해당하는 부분만 수정한다. 판정 의미가 달라지는 변경은 공식 근거와 저지 검토를 붙인다. 번역 수정은 기존 캐시를 조용히 덮어쓰기보다 교체 버전을 남긴다.
7. 승인된 사례만 비식별 회귀 평가 문항으로 추가한다. 모델 출력 전체 문장 일치보다 올바른 처리·필수 조건·허용 근거·피해야 할 단정을 평가한다.
8. 허가된 검증을 수행하고 변경 내용·남은 불확실성·추가 토큰 사용을 보고한다. 베타 반영 단계에서 배포 범위와 버전을 확정한다.
9. 배포 성공과 사용자 영향 확인 후 연결된 제보를 해결 처리하고 해결 버전을 남긴다. 이후 같은 문제가 나오면 다시 연다.

초기 우선순위: P0=접근/개인정보/통제되지 않는 과금 등 전체 중단 필요, P1=반복적인 오판정·주요 기능 불가, P2=일부 환경/번역/검색 품질, P3=문구·경미한 화면 문제. 규칙의 의미를 뒤집는 번역은 P1로 올릴 수 있다.

리포트가 접수될 때마다 AI 분석이나 배포를 자동 실행하지 않는다. 사용자 명령으로 필요한 건만 읽는 운영으로 시작한다. 개발 채팅에서 운영 DB를 읽을 수 있도록 나중에 읽기 전용 연결 또는 가림 처리 내보내기를 준비해야 하며, 지금 그 연결이 만들어진 것은 아니다.

## 11. 비용과 안정성 제안값

- 공개 베타이므로 방문자 수를 제한하지 않는다. 초기에는 익명 세션당 질문10건/일, 전체100건/일, 세션당 동시 질문1건, 전체 AI 동시3건을 제안한다. 네트워크 단기 제한과 전체 지출 한도를 함께 적용하며 계정 없는 상태에서 엄격한 사람별 한도는 보장하지 않는다.
- 캐시에 없는 번역은 별도 한도(익명 세션당20건/일·전체100건/일, 번역 동시2건)를 두되 전체 AI 동시/지출 한도에도 합산한다. 캐시 조회·제보 제출에는 AI를 쓰지 않는다.
- 서버가 분당 제한, 파일/본문 크기, 실제 모델 입력/출력 상한을 검사한다. 지출 한도는 배포 전에 운영자가 정할 금액을 앱에서 관리하며 외부 알림만으로 제한을 대신하지 않는다.
- 모든 유료 요청 전에 DB에서 보수적으로 비용을 예약하고 사용량 확인 후 정산한다. 동시에 들어온 요청도 예약 합계로 판단한다. 시간 초과로 비용이 불명확하면 즉시 환급 처리하지 않고 미확정으로 남긴다.
- 재시도·중복 클릭은 idempotency key로 통제하고 유료 자동 재시도는 기본 끈다. 예산 도달 시 새 생성만 멈추고 안전한 기존 자료 조회와 오류 제보는 유지한다.
- 기존 최대8개 공식 조항·4개 사례·1회 답변 생성·출력4096토큰 기본값 유지. 입력 길이가 달라지면 실제 요금도 달라진다. 분류를 위한 별도 AI 호출은 추가하지 않는다.
- 이전 실제 호출1건은3519토큰이었다. 같은 크기의 질문100건이라면 약35.2만 토큰이지만 평균이나 견적은 아니다. 입력/출력 요율, 사진, 상세 번역, 실패 요청을 따로 산정해야 한다.
- 무료 클라우드 범위에서는 서버/DB/저장소 이용료0원을 목표로 한다. OpenAI API는 별도 과금이며, 도메인(선택)·한도 초과·추가 백업도 별도다. 집 PC 안은 전기·인터넷 비용도 고려한다. 호스팅이 무료라는 이유로 전체 서비스를 무료로 운영할 수 있다고 안내하지 않는다. 무료 한도 초과 시 자동 유료 전환 대신 제한/일시 중지를 우선한다.
- 출처 검색 실패·구버전·근거 부족은 답변에서 드러내고 판정을 만들어 내지 않는다. 데이터 갱신은 후보 버전 수집→차이 검토→활성화 방식으로 하고, 실패 시 마지막 정상본을 유지하면서 갱신 시각을 표시한다.

## 12. 출처 이용 조건 — 외부 베타 전에 확인

소수에게만 URL을 알려주는 베타라도 누구나 들어올 수 있는 공개 서비스이므로 자료 재사용/배포 조건을 확인한다. 기존 프로젝트 조사에서 열린 항목을 이어서 확인한다.

- Riot 공식 문서는 Riftbound 앱의 서면 라이선스 또는 앱별 API 키, 자산 공급 경로와 카드 원문/번역 표시 조건을 명시한다. 자동 규칙 집행과 경계에 있는 이 도우미의 사용 사례를 설명하고 적용 조건을 확인한다. 현재 기능이 허용되거나 금지되었다고 임의로 확정하지 않는다. [Riot 정책](https://developer.riotgames.com/docs/riftbound)
- 리프트나루 현 약관은 한국어 카드 이름/본문을 비공식 번역으로 설명한다. 이 페이지에서 외부 서비스의 데이터 일괄 재사용 허가가 확인된 것은 아니다. 운영자의 재사용 허가 범위와 Riot 자산 조건을 각각 확인한다. 허가 범위가 해결되지 않으면 승인된 자료로 교체하거나 해당 기능을 베타에서 제외하는 경로를 준비한다. [리프트나루 약관](https://www.riftnaru.com/terms)
- RiftJudge는 검색 API 이용, 검색 결과 발췌 저장, 한국어 번역 캐시, 공개 URL 방문자에게 표시하는 범위와 요청량 조건을 확인한다. 전체 Q&A 수집은 이번 베타의 필수 작업으로 잡지 않는다.
- 문의 내용 초안에는 목적, 실제 UI, 공개 URL 접근 방식과 초기 예상 규모, 비공식 도우미 고지, 저장/표시하는 자료 범위, 출처 링크, 갱신·삭제 대응을 포함한다. 이번 설계 작업에서 문의를 전송하지 않는다.

운영 업데이트는 검토용 변경→검증→특정 릴리스 배포→상태 확인 순서. 앱 버전·프롬프트 버전·규칙/카드 데이터 버전을 각각 기록한다. 이전 앱 이미지/코드와 데이터 버전을 보존하며 DB 변경은 이전 버전과 호환되게 진행한다. 롤백할 때 새로 접수된 리포트를 삭제하거나 DB 전체를 예전 상태로 무작정 되돌리지 않는다. 작성 중 새 앱이 설치돼도 제보/질문 내용을 잃지 않도록 한다.
