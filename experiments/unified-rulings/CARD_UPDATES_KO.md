# 카드 자료 갱신 사용법

2026-10-21. 현재 **파일을 받은 뒤 검사·반영하는 과정은 자동**, 리프트나루에서 새로운 파일을 내려받는 과정은 미연결이다. 관리 화면에서 원격 미연결 표시가 나오는 것이 현재 정상 상태다.

## 지금 사용할 수 있는 방법

1. 통합본 폴더의 `Open-Card-Import-Folder.cmd`를 실행한다.
2. 아래 형식의 새 카드 JSON 파일을 열린 폴더에 복사한다. 일반 웹페이지 저장 파일이나 카드 이미지는 가져올 수 없다.
3. 관리 프로그램이 켜져 있으면 별도 수집기가 약1분마다 파일을 검사한다. 한 주기당 한 파일을 처리한다.
4. 관리 화면을 새로고침하고 자료 관리의 카드 상태를 확인한다. 이후에는 ‘자료 상태 새로고침’을 누른다.

변경된 내용만 새 자료 묶음으로 게시하고, 실행 중 앱은 기존 자료 확인 주기(최대10초) 뒤 새 요청부터 사용하도록 연결돼 있다. 진행 중 답변은 시작 당시 자료를 사용한다. 동일 파일은 새 판본을 만들지 않는다. PC/관리 프로그램을 다시 켜면 남은 파일 처리를 이어간다. Windows 부팅 자동 실행은 설정하지 않았다.

- 성공한 파일: `source-updates/cards/archive/`
- 형식/내용 확인이 필요한 파일과 사유: `source-updates/cards/review/`
- 일시적인 파일 접근/게시 충돌: `processing/`에 보존하고 다음 주기에 재시도
- 현재 상태/최근 처리 결과: `status.json`, `last-result.json` (같은 cards 폴더)

검토 대상은 자동 승인하지 않는다. 사유를 확인하고 고친 파일을 다시 넣는다. 신규 변경분의 실제 운영 게시와 실패 시나리오는 아직 별도 검증하지 않았다.

## JSON 공급 형식

기존 2026-10-18 카드 내보내기와 같은 schemaVersion 1 형식이다.

| 필드 | 의미 |
|---|---|
| `schemaVersion` | 숫자 `1` |
| `capturedAt` | 실제 출처 수집 시점의 ISO 날짜·시간. 가져오는 날짜로 덮어쓰지 않는다. |
| `coverage` | 전체 목록이면 `all-1527-artwork-listings-observed-2026-10-18`처럼 실제 개수/날짜를 넣는다. 일부 카드 파일이면 `partial`. |
| `cards` | 최대20,000개 카드 객체 배열, 파일 전체25MB 이하 |
| 각 카드 | `id`, `code`, `nameKo`, `nameEn`, `aliases`, `set`, `type`, `domains`, `stats`, `textEn`, `textKo`, `textComplete`, `sourceUrl`, `imageUrl` |

`id`는 출처의 영문 소문자/숫자/하이픈 카드 식별자이며, 내부에서는 `riftnaru:` 접두사를 유지한다. `sourceUrl`은 `https://www.riftnaru.com/cards/<id>`와 일치해야 한다. `stats`는 energy/power/might 숫자 또는 null, `textComplete`는 완전한 본문 확보 여부의 boolean이다. 이름만 같은 다른 그림/판본을 합치지 않는다. 이미 알려진 이름·본문·수치가 누락되면 검토 대상으로 보존한다.

## 원격 제공 주소가 확보되면

제공 주소가 없는 대안도 있다. 2026-10-21 후속 조사에서 일반 브라우저의 공개 카드 목록·영한 본문을 읽을 수 있음을 확인했다. 독립 브라우저 수집기 구성과 무인 실행 검증은 아직 하지 않았으며, 현재 예약 수집에 적용된 기능은 아니다. 기동 시/24시간 주기 연결안은 `plans/card-browser-update-2026-10-21.md`를 참고한다.

현재 직접 HTTP 요청은429 확인 화면을 반환했다. 확인 화면 우회·반복 수집은 하지 않았으며 사용 가능한 공개 API/JSON 주소도 확인되지 않았다.

운영자가 제공하는 주소와 사용 조건을 받은 뒤, 응답 형식·카드 ID·전체 목록 여부를 맞춘다. 현재 어댑터는 **www.riftnaru.com의 HTTPS JSON, 위 전체 목록 형식**만 지원한다. 다른 도메인·인증 방식·페이지네이션 API는 어댑터 수정이 먼저다. 임의 주소를 넣는 것만으로 모든 API와 연결되지는 않는다.

조건이 맞으면 `source-updates/cards/config.json`에서 `mode`를 `provided-json`, `remoteUrl`을 제공 주소로 바꾼다. `enabled: true`, `intervalHours: 24`를 유지한다. 다음 확인 주기에 설정을 읽으므로 앱 재시작은 필요 없다.

- 기본24시간마다 확인. ETag/Last-Modified가 제공되면 변경 없을 때 다운로드를 줄인다.
- 최소7일마다 조건부 헤더를 빼고 전체 JSON을 다시 요청한다. 원격 공급은 전체 목록 형식을 요구한다.
- 관리자 ‘지금 자료 갱신’은 연결된 카드 출처에도 요청한다. 출처가 요구한 대기 시간은 수동 요청도 지킨다.
- 실패하면 최소24시간 또는 Retry-After 중 더 긴 시간 뒤 재시도하고 기존 카드를 유지한다.
- 새 영문 본문에 이전과 같은 한국어가 붙어 있으면 오래된 한국어를 사용하지 않고 번역 확인 대상으로 둔다. 자동 번역 API는 호출하지 않는다.
- 출처에서 사라진 카드는 삭제하거나 사용 금지로 판단하지 않는다. 별도의 누락 이력을 남긴다.

## 일시 중지와 복구

명령 실행 환경에서 `node scripts/card-sync.js pause` / `resume`으로 카드 갱신을 멈추거나 재개할 수 있다. 또는 config.json의 enabled를 false/true로 바꾼다. 다음 주기부터 적용되며 이미 진행 중인 처리는 완료될 수 있다. 카드 자동화 전용 관리 버튼은 아직 추가하지 않았다.

자료 복구가 필요하면 카드 갱신을 일시 중지하고 진행 중 처리가 끝났는지 확인한 뒤, 기존 관리 화면에서 이전 자료 묶음을 선택한다. 자료 묶음 복구는 카드뿐 아니라 규칙·사례도 그 판본으로 돌아가므로 선택 내용을 확인한다.

## 비용과 한계

파일 검사·비교·색인·갱신은 생성 AI를 호출하지 않는다. 평소 질문에 답변하는 AI 요금과 별개다. 이미지 파일 전체를 내려받거나 카드 전체를 재번역하지 않는다. 수집 성공이 공식 판정·번역 검수 또는 데이터 사용 허가를 뜻하지 않는다.
