# 한국어 카드 번역 개발 계약

이 기능은 v0.3.0 개발 환경의 후보 생성기다. Riot Production API 승인과 실제 DTO·locale·이용 권한은 확인되지 않았다. 합성 카드와 모의 공급자만 실행·검증했으며 실제 OpenAI 호출은 없다. 운영 전환은 별도 승인 대상이다.

## 흐름과 저장

1. `riot-adapter`의 검토된 canonical 자료를 `riot-converter`가 정규화한다. 실제 입력은 Riot API URL·매퍼 버전·출시 상태가 필요하다. 미발매 자료는 공식 공개 여부, 공식 공개 URL과 버전이 있어야 수집·변환된다. 도메인 검사만으로 공개 사실이나 이용 허가가 입증되지는 않으므로 매퍼 검토가 필요하다.
2. `official-card-locales`가 공식 한국어를 확인한다. 전체 한국어가 입력에 있으면 출처·영어 대응 버전을 검사한다. 없으면 매퍼가 명시한 `officialKoreanStatus: absent` 또는 주입된 `officialLookup(request, {signal})`의 결과가 필요하다. 누락·조회 실패·버전 불일치는 AI로 우회하지 않는다. 조회 함수 계약은 `status: available|absent`, `sourceKind: riot-api`, `englishVersion`, 공식 `url`, 제공 시 `text`, `version`, 선택 `name`, `keywords`다. 실제 HTTP 조회기는 아직 없다.
3. `createCardTranslationEngine`은 공식 한국어를 우선한다. 없을 때만 카드별 `translation`과 `modelInput` 권한, 공급자 활성화·예산을 검사해 `generate(request, {signal})`를 호출한다. 요청은 이름·문장별 효과·키워드·비용·능력치·기호·용어집·선별된 공식 예제를 분리한다. 사용자 질문은 사용하지 않는다. 응답 계약은 `nameKo`, `clauses[{id,textKo}]`, `keywordsKo[{en,ko}]`, 원문 그대로의 `cost`, `stats`, `symbols`, `uncertainties`다.
4. `proposeCatalog`는 영어를 보존하고 새 번역을 `translationProposal`에 둔다. 같은 영어의 기존 승인 번역은 유지한다. 원문이 달라지면 이전 번역을 현재 번역으로 노출하지 않는다. 과거 원문·번역·후보의 전체 기록은 `translation-review.json`, 카드에는 `translationHistory`의 불변 ID를 보존한다. 출처가 없는 기존 한국어는 `legacy`로 기록하며 공식/AI로 추정하지 않는다.
5. `writeCandidate`는 격리 루트의 `card-translations/candidates/<id>/`에 카드·검토 큐·해시 manifest를 추가한다. `stageTranslationCandidate`는 검증된 기준 릴리스의 규칙·저지 사례를 바이트 그대로 복사해 **미게시** knowledge 후보를 만든다. 운영 DB나 `active.json`을 쓰지 않는다.

`translationRecord`는 공급자·모델(공식 번역은 모델 없음), 생성/관측 시각, 생성 당시 `sourceVersion`, 적용 당시 `appliedToVersion`, `englishHash`, 용어집·스타일·검사 버전, 필드별 출처, 공식 출처 버전/URL, 검증과 검토 참조를 가진다. 공식 이름과 AI 효과를 혼합하면 필드별 출처가 다르다. 공급자 모델 식별자는 현재 어댑터의 선언값이며 실제 연결 시 응답의 모델과 일치하도록 검증해야 한다.

## 캐시와 재시도

`card-translations/cache/`는 원문 이름·효과·키워드·비용·능력치·기호의 해시, 공급자 모드/ID/모델, 용어집·예제 digest, 엔진·스타일·검사 버전과 `retryRevision`으로 구분한다. 영어가 같고 원문 버전만 바뀌면 기존 생성 시각/버전을 유지해 재사용한다. 공식 번역 여부는 캐시보다 먼저 확인하므로 나중에 공식 한국어가 생기면 AI 재호출 없이 교체 후보가 된다.

성공·검증 실패·공급자 오류·시간 초과도 저장하며 자동 재시도하지 않는다. 병렬 프로세스는 파일 잠금을 공유한다. 손상 캐시나 응답 저장 실패·프로세스 중단의 잔류 잠금은 유료 호출이 이미 발생했을 가능성이 있어 실패 처리한다. 운영자는 공급자 처리 상태·과금 여부와 저장소를 먼저 조사하고, 필요한 경우 새 `retryRevision`과 예산으로 명시적으로 재시도한다. 기존 결과·잠금을 자동 삭제하지 않는다. AbortSignal 무시는 제공자에서 해결해야 하며 로컬 시간 초과가 실제 공급자의 요청 취소/과금 취소를 보장하지 않는다.

개발 캐시·후보는 자동 만료하지 않는다. 공용 원문/번역만 대상으로 하지만 검토 참조·공급자/생성 메타데이터를 포함하므로 접근·백업·보관 방침이 필요하다. 로컬 설정·데이터 루트·실제 키는 Git에 넣지 않는다. 캐시는 중복 호출 방지 장치이며 전체 과금 한도/분산 작업 스케줄러는 아니다. 운영 어댑터는 공급자 차원의 한도도 설정해야 한다.

## 용어와 정확성

기본 용어집은 기존 버전이 정렬된 공식 규칙 용어를 사용한다. `buildGlossary`는 실제 공식 한·영 카드와 사용 권한, 영어 대응 버전, 원문 내 대응 표현, 관리자의 `reviewReference`가 확인된 매핑만 공식 카드 용어로 추가한다. 이 용어가 규칙 제목보다 우선하고 충돌은 검토 대상으로 남긴다. 사용 권한이 있는 공식 카드 예제 최대 3개를 문체 참고로 전달할 수 있다. **현재 실제 한국어 카드 예제를 수집·검증하지 않았으므로 한국어판 카드 문체 보정은 미완료**다. 임시 문체 지침이나 합성 예제는 공식 번역의 증거가 아니다.

자동 검사는 문장 ID/순서, 숫자·일부 수사, 비용·능력치·기호의 완전 일치, 키워드 정체성과 용어집, 문장별 부정/조건/선택/강제/대상/소유/타이밍, 뽑기·피해 수량 뒤바뀜, 묶음 키워드 일관성을 검사한다. 누락/변조가 확인되면 차단하고, 복잡한 `unless`, 미확정 용어·공급자 불확실성 등은 검토 대상으로 분류한다. 공식 번역의 숫자/기호 이상도 원문을 수정하거나 AI로 바꾸지 않고 경고한다.

검사는 휴리스틱이다. 동의어·복잡한 참조·범위·예외·대상 수·지속 효과·비용과 효과의 관계를 완전하게 증명하지 못하며 오탐도 가능하다. 별도 유료 모델 의미 검사나 역번역은 실행하지 않는다. 의미 일치는 반드시 사람이 영어/한국어, 규칙·정오표와 함께 판단해야 한다. 모든 AI 번역은 `checks-passed`여도 관리자 승인이 필요하다.

## 관리자 검토와 기존 기능

검토 화면은 새로 만들지 않았다. 관리자는 후보의 `translation-review.json`에서 현재·이전 영어, 이전 번역과 교체 후보, 필드 출처·경고를 확인한다. `reviewTranslation(card, {proposalId, expectedEnglishHash, reviewReference, acknowledgeWarnings, at})`는 정확히 일치하는 후보만 승인한 **복사본**을 반환한다. 차단 오류는 승인할 수 없고 경고는 각각 명시적으로 확인해야 한다. 이 함수는 파일·DB·포인터를 쓰지 않는다. 승인 복사본을 새 검토 후보에 저장하는 운영자 도구와 조직별 검토 기록 절차는 실제 연동 전에 준비해야 한다.

게시 후보의 `reviewRequired`를 무시해 즉시 공개하지 않는다. 기존 knowledge 활성화도 명시적인 검토 확인을 요구하고 번역 후보의 기준 릴리스가 바뀌었으면 거절한다. 실제 배포/활성화에는 별도 사용자 승인이 필요하다. 새 후보는 기존 카드를 병합하는 도구가 아니므로 컬렉션 범위·수량·누락 카드를 검토해야 한다.

`card-access`는 미승인 후보·과거 이력·locale 조회 자료를 공개 API에서 제외하고, 승인 번역도 현재 영어 해시와 일치할 때만 표시한다. UI는 공식/모의/비공식 RiftAssist AI 번역과 미발매 여부를 구분하고 원문과 한국어를 따로 보여준다. 카드 검색은 승인 한국어 이름으로 가능하다. AI 판정은 기존 영어를 근거 입력으로 유지하며 번역 출처/검토 메타데이터만 덧붙인다. 비용/능력치/기호도 별도 전달한다. 공식 규칙·저지 사례 검색 및 제보·관리 API는 기존 경로를 유지한다.

## 승인 후 연결 순서

1. Riot 승인 범위와 카드 텍스트·이미지·번역/제3자 AI 전송·저장·재배포 권한, 출처 표시 조건을 확인한다. API 승인이 모든 번역 권한을 자동 부여한다고 가정하지 않는다. 리프트나루 1,527개 자료의 권한 문제는 기존 감사 보고서에 남아 있으며 공식 데이터로 재분류하지 않는다.
2. 실제 영문/한국어 DTO·버전 연결·locale 부재 표현·정오표·공개 출시 상태를 확인한 매퍼와 공식 조회 함수를 추가한다. 키는 승인 후 비밀 저장소/프로세스 주입으로 공급하고 본문/로그에 남기지 않는다.
3. 허용된 공식 한·영 카드의 검토된 용어/문체 예제와 골든 테스트를 구성한다. 다양한 조건·예외·기호·비용·타이밍, 미발매 표시, 공식 교체를 한영 규칙 검토자가 검증한다.
4. 운영자가 선택한 번역 공급자 어댑터를 별도로 구현한다. 타임아웃·AbortSignal·구조화 응답·확인된 모델·비밀 주입·계약/보관/국외 이전·요청별/계정별 비용 한도를 확인한다. 명시적 활성화와 소량 예산으로 격리 환경에서 검증한다. 현재 예시 설정을 읽어 자동 활성화하는 경로는 없다.
5. 후보만 생성하고 관리자 검토, 카드 검색·판정·모바일 회귀와 데이터 무결성 검증을 통과시킨다. 이후 별도 배포 승인을 받는다. 운영 v0.1.7·DB·키·공유 포인터를 보존하는 기존 [배포/롤백 계획](../../artifacts/riot-v0.3.0-2026-10-28/deployment-and-rollback.md)을 따른다.
