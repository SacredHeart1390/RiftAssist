# 신규 카드·에라타 동기화 개발 계약

현재는 **격리된 개발 환경 + 합성 카드 + 모의 페이지 응답**만 허용한다. 기존 `createRiotAdapter`에 `collectSnapshot()`을 추가했다. `mode: riot-api` 동기화는 승인 여부·키 존재와 관계없이 거절한다. 실제 Riot DTO·endpoint·locale·권한은 확인되지 않았으며 모의 계약을 실제 API 명세로 주장하지 않는다.

## 실행과 일정

새 개발 환경을 `npm run dev:prepare`로 준비한 뒤 `npm run sync:mock`으로 한 번 검사하고 `npm run sync:status`로 실패·재시도 상태를 확인한다. 재실행은 동일 자료의 번역/후보 생성을 생략한다. 기존 번역 캐시·용어집·모의 제공자·후보 저장기를 재사용한다. 운영 자료를 복사/덮어쓰지 않으며 키 CLI 옵션도 없다.

`createCardSyncEngine.runDue()`는 `enabled: false`가 기본이며 활성화해도 `nextAttemptAt` 이후에만 검사한다. 기본 간격은 6시간이다. `startCardSyncScheduler`는 별도 호출로 시작하며 중복 tick·프로세스 경합을 차단한다. 앱/관리자 시작 경로에 연결하지 않았다. 중지하면 새 tick을 막고 진행 중 검사는 제한 시간 안에 끝난다. 외부 cron도 다음 시각을 지켜야 한다. 예시 JSON은 계약이며 읽기만으로 자동 시작하는 설정 로더는 없다.

## 완전한 수집

모의 페이지는 `snapshotId`, 단조 증가 정수 `revision`, 불투명 문자열 `version`, `publishedAt`, `sourceUrl`, `expectedCount`, `complete: true`, `cards`, `nextCursor`를 가진다. 마지막은 `nextCursor: null`이다. 페이지의 완전 표시만 믿지 않고 모든 페이지의 동일 메타데이터·종료 커서·총수 일치를 확인한다. 기본 최대 100페이지(설정 상한 1,000), 전체 15초, 카드 20,000개, 원문 약 16MB로 제한한다. 검사가 끝나기 전에는 변환·번역·후보 생성을 시작하지 않는다.

카드별 ID·영문 이름/효과·버전/단조 revision·공개/수정 시각을 요구하고 수집 시각을 별도 관측한다. 공개일을 수집일로 추측하지 않는다. 미발매 카드는 기존 공식 공개 근거 검사를 통과해야 한다. 정수 revision이 실제 Riot 필드라고 가정하지 않으며 승인 후 매퍼가 변경 순서를 입증하는 방식으로 연결해야 한다. 버전 문자열을 사전순 비교하지 않는다.

부분 응답·페이지 불일치·커서 반복·수량 불일치·중복 ID·비정상 카드/시각·미공개 프리뷰·시간 초과·네트워크/호출 제한을 거절한다. 같은 전체 revision의 다른 자료/버전, 전체/카드 revision과 공개/수정 시각 역전도 거절한다. source scope 변경은 기존 관측에 혼합하지 않는다. 실제 API의 delta/304 응답은 현재 구현하지 않았으며 완전한 목록으로 간주해서는 안 된다.

## 변경 비교와 번역

새 카드, 영문 이름/효과/키워드/비용/능력치/기호 변경, 에라타, 공식 한국어 추가/변경/제거, 출시/철회/공개 상태, 기타 메타데이터, 삭제 의심, 재등장을 구분한다. 영어 해시와 변경 전후 원문·한국어·정오표·상태·출처를 남긴다. 모의 locale은 `sourceKorean`으로 생성 번역과 분리하고 `simulated: true`, 출처 `mock`을 유지한다. 실제 공식 한국어 분류는 합성 canonical 자료로만 검사했다.

목록에서 빠진 카드는 **삭제·철회하지 않고 후보에 보존**한다. 최초 누락·관측 횟수·마지막 확인/목격 시각과 삭제 의심을 기록한다. 완전한 빈 목록도 기존 카드를 유지하며 반복 누락만으로 같은 후보를 계속 만들지 않는다. 명시적 철회도 별도 검토 후보일 뿐 자동 적용하지 않는다. 실제 삭제 도구는 없다.

변경 없는 카드는 기존 번역 기록을 복사해 적용 버전만 갱신한다. 신규·영문·한국어·에라타 변경만 기존 번역 `proposeCatalog`로 보내며 영어가 같으면 캐시를 재사용한다. 영어가 바뀌면 과거 한국어를 현재 본문에서 제외하고 이력을 보존한다. 에라타는 영어가 같아도 기존 승인을 무효화해 재검토한다. 공식 우선·수동 승인·의미 위험 검사는 [기존 엔진](card-translation.md)을 재사용한다. 실제 모델 호출은 없다.

수집 시각·전체 버전만 바뀌거나 카드 순서/페이지 분할만 달라지면 새 후보를 만들지 않는다. 카드별 revision/버전만 바뀌어도 의미 변화가 없으면 관측 상태만 갱신한다. 모델/용어집 변경만으로 전부 자동 재번역하지 않으며 별도 번역 검토 작업을 사용해야 한다.

별도 에라타 메모를 효과 본문에 임의로 합치거나 한국어로 자동 재작성하지 않는다. 매퍼가 제공한 현재 영문 효과와 원문 메모를 보존하고 관리자가 의미와 적용 시점을 대조해야 한다. 버전만 전진해 후보를 만들지 않은 변경도 관측의 `changes`에 기록한다.

## 저장·검토·복구

`DATA_ROOT/card-sync/`에 체크섬 상태, 불변 관측과 시도 기록을 저장한다. `lastGood`는 **완전하게 수집해 필요한 후보 준비까지 성공한 마지막 관측**이며 운영 활성 자료가 아니다. 수집 원문/번역 후보와 카드별 영어 해시·버전·공개일·최초/최종 목격·누락 상태를 포함한다. 실패는 정상 참조를 바꾸지 않는다. 상태는 임시 파일 rename, 불변 자료는 배타적 생성으로 보호한다. 파일시스템 소유자는 신뢰 경계다. 손상 상태나 외부/상태 심볼릭 링크는 거절한다.

기존 `card-translations/candidates/sync-<digest>/`에 카드·번역 검토와 **`sync-review.json`**, 해시 manifest를 저장한다. 기존 `stageTranslationCandidate`가 같은 ID의 미게시 knowledge 후보에 기준 규칙·저지 사례를 그대로 복사하고 수집 revision·검토 후보 참조를 남긴다. `active.json`은 전후 일치를 확인할 뿐 쓰지 않는다. 결정된 후보 ID로 완성 후보 이후 상태 갱신 실패 시 같은 후보를 재사용한다.

관리자는 두 검토 JSON에서 전후 원문·정오표·한국어·출시 상태·출처·누락과 번역 경고/과거 기록을 확인한다. 번역 승인 함수는 복사본만 반환한다. 승인본을 별도 검토 후보로 저장하는 도구와 전용 관리자 웹 화면은 아직 없다. 카드 범위/수량/누락과 규칙 기준도 검증해야 한다. `reviewRequired` 플래그만으로 관리자 승인이 완료됐다고 간주하지 않는다.

실패 시 기본 1분부터 최대 6시간의 지수 백오프와 다음 시각·연속 실패 수·오류 코드를 저장한다. 모의 `rate-limit.retryAfterMs`가 크면 우선하며 30일 초과는 자동 재시도를 막고 수동 점검을 요구한다. 오래 sleep하지 않는다. 원시 오류 본문·커서·키는 저장하지 않는다. 성공 시 실패 횟수를 초기화한다.

손상 상태·잔류 run 잠금·불완전 후보는 자동 삭제/덮어쓰기하지 않는다. 완성 후보 이후 관측 저장 실패는 재시도할 수 있지만 불완전한 디렉터리는 추가 복구 도구가 필요하다. 번역 실패/시간 초과는 기존 캐시 정책에 따라 자동 유료 재시도하지 않는다. 디스크 고장·호스트 재난에 대한 fsync/백업 복구와 공유 파일시스템 잠금은 별도 검증이 필요하다. 관측·시도·검토 자료는 자동 만료하지 않으므로 보관/용량 정책도 정해야 한다.

기준 활성 포인터가 다른 릴리스로 바뀌면 자동 rebase하지 않고 중단한다. 관리자는 승인된 활성 자료와 마지막 관측을 대조해 별도 루트에서 재기준화 절차를 마련해야 한다. 운영 배포·지속 운영의 자동 전환기는 제공하지 않는다.

## 승인 후 연결 작업

1. Riot 승인과 카드/번역/이미지/AI 입력·저장/재배포 권한·출처 조건을 확인한다. 리프트나루 1,527개 미확인 카드는 혼합하지 않는다.
2. 실제 전체 목록·페이지 일관성·ETag/304·delta·호출 제한·공개/출시·정오표·한국어 locale·변경 순서를 확인해 transport/DTO 매퍼를 작성한다. 실제 모드 차단은 승인된 별도 변경으로 해제하고 단조 revision/완전성의 근거를 검증해야 한다.
3. 공식용 격리 staging·비밀 주입·권한·과금 한도·보관/모니터링을 준비한다. 모의 관측/revision을 공식 자료와 재사용·혼합하지 않는다. 실제 번역 공급자와 공식 한국어 용어/문체 보정도 남은 작업이다.
4. 실제 데이터 추가/변경/누락·정오표·공식 한국어 교체·장애/반복 수집을 검증하고 관리자 도구·재기준화·복구를 준비한다. 별도 배포 승인 후 [분리 배포/롤백 계획](../../artifacts/riot-v0.3.0-2026-10-28/deployment-and-rollback.md)을 따른다. 운영 일정 실행기 연결도 별도 승인 대상이다.
