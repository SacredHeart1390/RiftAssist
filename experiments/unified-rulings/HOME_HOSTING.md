## 1. 도메인을 사지 않아도 된다

도메인은 사람들이 입력할 주소이며 서버는 앱이 실행되는 컴퓨터다. 아래 모든 방식에서 앱·규칙 색인·운영 DB는 집 PC에 둘 수 있다. 무료 주소/연결 서비스를 이용해도 PC 전원·인터넷·OpenAI API 비용은 별도로 필요하다. 접속자의 PC에는 프로그램 설치나 초대코드가 필요 없다.

| 방법 | 주소 예시 | 초기 준비 | 제약 |
|---|---|---|---|
| ngrok Free | `자동배정이름.ngrok-free.app` | 운영자 가입, Windows 에이전트 인증, 배정 주소 연결 | 원하는 이름 선택 불가. 방문 안내 화면. 월 1GB 외부 전송·20,000 HTTP 요청 |
| DuckDNS + HTTPS | `riftassistant.duckdns.org` | 사용 가능한 이름 등록, IP 갱신, 공유기 포트 연결, HTTPS 프록시 | 집 회선에서 외부 접속이 가능해야 함. 공유기/방화벽 설정 필요. 이름 선점 여부 미확인 |
| Tailscale Funnel | `riftassistant.계정영역.ts.net` | Personal 계정 적용 가능 여부 확인, 집 PC 설치·인증·Funnel 활성화 | 주소가 길고 정해진 도메인만 사용. 베타 기능·대역폭 제한 |
| 개인 도메인 + Cloudflare Tunnel | `riftassistant.선택한확장자` | 도메인 등록/갱신, DNS 연결, 집 PC 터널 설정 | 도메인 비용. 이름·확장자별 가격과 사용 가능 여부를 따로 확인 |
| Cloudflare Quick Tunnel | `임시이름.trycloudflare.com` | cloudflared 실행 | 계정·도메인 없이 사용 가능하지만 재시작마다 주소가 달라져 일시적 공유용 |

ngrok의 HTTP 요청은 질문만 세는 것이 아니다. 페이지·카드 검색 요청도 포함된다. 방문 안내에서 한 번 계속을 누르면 같은 도메인에서 7일간 안내를 생략하는 쿠키가 사용된다. 기존 자동완성의 잦은 검색 때문에 이 앱에서는 HTTP 요청 한도가 먼저 문제가 될 수도 있다.

DuckDNS는 주소를 IP에 연결하는 서비스다. HTTPS 서버나 외부 연결 터널을 대신 제공하지 않는다. 일반적인 구성은 공유기의 외부 80/443 → 집 PC의 Caddy → `127.0.0.1:3001`이다. 외부에서 들어올 수 없는 회선/통신사 공유 IP 환경이면 이 방식을 바로 쓸 수 없으므로 터널 방식을 선택한다. 앱 포트3001이나 관리 포트3100을 직접 공개하는 구성이 아니다.

현재 선택: 계정·도메인 없이 Quick Tunnel 임시 주소로 시험하고, 만족하면 개인 도메인과 고정 Tunnel로 전환한다. 임시 주소의 이름을 정하거나 같은 주소를 구매 도메인으로 승격하지는 못한다. 주소를 바꾸면 브라우저 쿠키/PWA 설치는 새 주소에서 다시 시작한다. 기존 서버 DB는 유지할 수 있다.

검색 노출은 URL 공개와 별개다. 안정적인 주소가 정해진 후 검색 서비스에 사이트를 등록한다. 수집·노출은 보장되지 않으며 임시 주소나 방문 안내 페이지는 지속적인 검색 유입용으로 적합하지 않다.

## 2. 추가한 로컬 운영 기능

운영 기능은 통합본 폴더에만 적용했다. 원본3000 앱은 수정하지 않았다. **격리 환경의 로컬 점검56개, 실제 통합본 시작과 제보 화면 확인을 완료했다. 유료 호출·외부 공개는 하지 않았다.**

1. `Open-Manager.cmd`를 더블클릭한다. Node.js가 PATH에 없으면 현재 집 PC의 Codex 번들 Node 경로를 사용한다. 권장 Node24 LTS, 최소22.13.
2. 최초 실행기는 해당 통합본의 PID 기록·실행 경로가 일치하는 기존 서버만 종료하고 별도 관리 프로세스를 숨겨서 시작하도록 작성했다. 다른 앱/루트 백업은 종료하지 않는다.
3. 인증된 관리 화면 `http://127.0.0.1:3100/`이 열린다. **서버 켜기**를 누르면 앱3001을 자식 프로세스로 실행한다. 꺼도 관리 화면은 유지한다.
4. 처음에는 로컬 모드다. Quick Tunnel은 `private/tools/cloudflared.exe`를 준비하고 **Cloudflare 임시 주소**를 선택·저장한다. 서버 켜기에서 주소를 자동 발급해 앱 허용 주소에 적용한다. 서버 끄기는 앱과 터널을 함께 중지한다. 다른 연결 모드에는 실제 HTTPS 주소가 필요하다. 외부 연결 모드는 이미 별도로 설치한 프록시/터널이 필요하며 자동 구성하지 않는다.
5. 관리 화면에서 AI 생성 중지/허용, 일일 호출 한도, 사용 토큰, 제보 목록·상세·상태·메모·JSON 내보내기, DB 백업을 이용하도록 구현했다.

관리 화면은127.0.0.1에 바인딩하고 로컬 파일의 인증키→HttpOnly 세션으로 인증한다. Host/Origin을 제한하고 프록시 전달 헤더를 거부한다. 키는 실행 링크의 fragment로 전달해 사용 후 주소에서 제거한다. 관리자 페이지와 운영 자료는 이용자용 public 디렉터리 밖에 있다. 관리 주소·인증키 파일은 다른 사람과 공유하지 않는다.

PC 부팅 시 자동 시작은 아직 등록하지 않았다. 당분간 실행 파일 열기 → 서버 켜기를 사용한다. 관리 프로세스가 실행되는 동안 브라우저 창을 닫아도 서버는 계속 실행한다. Windows 로그아웃·재부팅·절전은 서비스에 영향을 준다.

## 3. ngrok를 선택한 경우 남은 연결 작업

- 운영자가 공식 ngrok 계정에 로그인하고 무료 배정 주소를 확인한다.
- 공식 Windows 실행 파일을 `private/tools/ngrok.exe`에 준비하고, ngrok 공식 설치 안내에 따라 해당 Windows 사용자 계정에 인증 정보를 저장한다. 인증 토큰은 채팅·소스·로그에 적지 않는다.
- 관리 화면에서 서버를 끄고 연결 방식 ngrok와 실제 HTTPS origin을 저장한다. 끝의 `/`나 경로를 붙이지 않는다.
- 서버 켜기 후 터널 상태를 확인하고 별도 기기의 외부 인터넷에서 접속을 확인한다. 관리 화면의 '터널 연결됨'만으로 외부 접속 성공을 판단하지 않는다.
- ngrok HTTP 본문 검사 기능은 실행 인수 `--inspect=false`로 끄도록 구성했다. 계정의 클라우드 로그/수집 설정도 실제 연결 전에 확인한다.

ngrok는 대안으로 보존한 코드이며 현재 선택이 아니다. Cloudflare Quick Tunnel의 실제 연결을 확인했다. 개인 도메인의 고정 Tunnel 설정은 추후 별도로 진행한다.

## 4. 제보와 데이터 보관

- 입력 하단과 답변에 제보 버튼. 유형: 앱 오류/룰링·근거 오류/번역/잘 모르겠음. 세부 태그, 문제 설명, 기대 답변·근거 링크(선택).
- 답변의 서버 발급 requestId와 익명 세션 소유권을 대조한다. 모달을 열었을 때의 요청 번호를 고정해 이후 새 질문과 섞이지 않게 한다.
- 질문·답변·검색된 실제 근거/카드/번역·모델/프롬프트 버전·사용 토큰을 연결한다. 내부 비공개 사고과정은 저장하지 않는다.
- 접수 시 당시 자료를 독립 복사한다. 관리자만 상세를 보고 상태 이력을 남기거나 분석용 JSON으로 내보낼 수 있다. 방문자에게는 자기 브라우저 세션의 제보 번호·상태만 제공한다. 쿠키 삭제/만료 후에는 이전 세션 제보 조회가 되지 않는다.
- SQLite WAL을 사용한다. `private/operations.sqlite`의 질문·답변·제보 내용은 AES-256-GCM으로 암호화하고 키는 `private/storage.key`에 둔다. 서버 계정/디스크 접근 권한과 복호화 키 보호도 필요하다.
- 새 DB 자료: 질문·답변 7일, 처리 메타데이터30일, 제보·연결 자료90일. 시작 시 및 실행 중 매시간 정리한다. 질문 이미지 원본은 저장하지 않는다. 번역 캐시는 공개 출처 자료로 별도 유지한다.
- 기존 개발용 JSONL 파일은 이번 보존 정책으로 소급 삭제하지 않았다. 수동 백업은 자동 정리하지 않으므로 운영자가 기간에 맞춰 관리한다.
- 제보 이미지 업로드는 이번 구현에 포함하지 않았다. 질문 이미지 자동 첨부도 하지 않는다. 향후 선택 첨부를 추가하면 별도 검증·비공개 저장·보존 정책을 적용한다.

## 5. 비용과 운영 제한

초기값: 전체 질문100회/일, 답변 생성30회/일, 새 번역30회/일, 익명 세션 질문10회/일·번역10회/일, AI 동시3개. 제보100건/일·세션5건/일. 최초 접속 세션 발급2,000개/일. 모두 한국 시간 기준이며 관리자 화면에서 호출·제보 한도를 조절한다.

시도 횟수를 DB 트랜잭션으로 먼저 예약하므로 재시작/동시 요청으로 전체 제한을 넘기지 않는다. 익명 세션 한도는 쿠키를 바꾸면 우회할 수 있어 전체 제한을 항상 함께 적용한다. 캐시 번역은 새 과금 호출에서 제외한다. 실패/통신 끊김도 예약 횟수는 되돌리지 않아 비용을 과소 집계하지 않는다. 입력 글자·출력 토큰 상한은 기존 값을 유지했다.

이 제한은 **달러 단위 결제 상한이 아니다.** 실제 사용 토큰이 반환된 경우만 집계하고 알 수 없는 사용량은 따로 표시한다. OpenAI 프로젝트의 지출 알림·결제 설정은 별도로 관리한다. 자동 유료 재시도는 추가하지 않았다.

## 6. 공개 전 남은 작업

1. Quick Tunnel 파일과 연결·공개 HTTPS는 확인 완료. 휴대폰 모바일 데이터 접속과 실제 답변을 확인한다. 계정/도메인은 이 임시 시험에 필요 없다.
2. 로컬 관리·질문·제보·중복/소유권·백업 복원은 격리 자료로 확인했다. 보존 기간의 시간 경과/정리 전 과정과 실제 운영 자료 장애 복구는 별도 확인이 남았다. 유료 답변 품질도 별도다.
3. 외부 URL·HTTPS·휴대폰 접속 확인, 관리자3100과 private 파일이 외부에서 제공되지 않는지 확인.
4. 외부 터널 사업자의 데이터 처리 고지, 운영자 문의/삭제 요청 경로, 실제 공개 전 보유 정책 문구 정리.
5. 팬 사이트 카드 자료의 공개 재사용 조건 및 공식 원문 대조 등 기존 공개 전제 확인. 로컬 수집 허가가 외부 공개 재사용 허가를 대신한다고 가정하지 않는다.
6. 저지 검수 결과 반영, 검색 등록과 공개 안내. 평가 데이터·개인 제보는 검색 대상에 넣지 않는다.

복구: 관리자와 앱을 중지한 상태에서 같은 백업 폴더의 DB와 storage.key를 함께 복원해야 한다. 실행 중인 DB 파일 위에 덮어쓰지 않는다. 현재 백업은 운영DB용이며 앱·규칙·카드·.env 백업은 별개다. 격리 점검에서 백업 사본을 열어 제보·상태 이력 복호화를 확인했으며 실제 운영 DB를 교체하지는 않았다.
