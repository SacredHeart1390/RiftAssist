## 적용한 개선

### 답변과 화면

- 일반적인 오류 가능성 안내를 사이트 하단에 한 번 표시한다.
- 답변마다 붙던 별도 안내 영역과 카드 업체 이름의 반복 노출을 없앴다.
- 모델 지시에서도 반복적인 출처·권위 고지를 줄였다. 실제로 판정을 바꾸는 자료 누락·충돌·불확실성은 계속 알리도록 했다.
- 내부 출처·카드 판본·해시·제보용 기록은 유지한다.
- 버전이 붙은 화면 파일과 서비스 워커를 사용한다. 열려 있는 질문 화면을 강제로 새로고침하지 않는다.

### 검색과 자료 추출

- 카드 장수, 덱 구성, 폐기장과 패의 관계를 검색 단서로 분석한다.
- 이런 질문에는 코어룰 103.3.b 및 관련 조건·대회 절차를 먼저 연결한다. 효과 설명이 필요할 때만 카드 효과로 검색을 확장한다.
- 조항의 부모 문맥도 모델에 전달한다. 필수 조항이 누락되면 판정 생성을 보류한다.
- 근거 최대 8개, 사례 최대 4개와 기존 모델·출력 한도를 유지한다.
- 검색 후보·선정 이유·자료 버전을 운영 기록에 남긴다. 모델의 비공개 추론 과정은 저장하지 않는다.
- PDF의 번호 열과 본문 열을 구분하고 중복 조항 정의를 차단한다.
- 대회 703.4.a.5의 정의·예외와 703.4.c.5의 연결 문장을 복구했다.
- 잘못 생성됐던 대회 `128` 항목은 본문의 코어룰 참조였다. 본래 문장에 합쳐져 전체 항목이 3,488개에서 3,487개로 바뀌었다.
- 공식 PDF의 언어별 추출 수는 코어 EN 2,494 / KO 2,493, 대회 EN 975 / KO 976이다. 언어별 본문이 없는 항목을 새로 지어내지 않았다.

### 자료 교체

- 완성된 자료를 별도 버전 폴더에 저장한 뒤 활성 포인터를 교체한다.
- 해시·구조·시행일·핵심 조항을 확인하며, 관리자 검토가 필요한 후보는 확인 없이 적용하지 않는다.
- 앱은 최대 10초 간격으로 새 버전을 확인한다. 다운로드·작성 중 파일을 직접 사용하지 않는다.
- 질문 하나는 시작 시 잡은 자료 버전을 끝까지 사용한다.
- 새 자료가 손상됐으면 현재 자료를 유지한다. 이전 정상 버전은 관리자에서 다시 선택할 수 있다.
- 여기서 자료의 `validated`는 파일·구조 검사를 뜻한다. 저지의 판정 정확도 검수 완료를 뜻하지 않는다.

### 앱 전환

```text
공개 주소 → Cloudflare → 고정 연결 창구 3001 → 앱 3011 또는 3012
관리 페이지 3100 → 새 앱 준비 / 전환 / 자료 적용 / 제보 확인
```

- 새 앱의 준비 상태를 확인한 뒤 새 요청부터 전환한다.
- 진행 중 응답은 기존 앱에서 끝내며, 기존 앱을 기다리는 기본 시간은 90초다.
- 실패한 질문을 다른 앱으로 자동 재전송하지 않는다.
- 앱 시작이 실패하면 기존 앱을 유지한다.
- 운영 DB·사용량 한도·키는 두 앱이 같은 위치에서 사용한다.
- **관리 프로그램, 연결 창구, PC·네트워크를 재시작하는 경우까지 무중단인 것은 아니다.**

## 자동 자료 확인의 정확한 범위

별도 프로그램이 6시간마다 공개 변경 목록을 확인한다. 관리자 시작 시 실행하며, 앱의 질문 처리와 분리돼 있다. PC 재부팅 시 자동 시작하는 Windows 작업은 등록하지 않았다.

| 공급원 | 이번 확인 | 현재 자동 처리 |
|---|---|---|
| 공식 영문 Rules Hub | 관련 링크 10개 | 링크·목록 변경 발견 및 기록 |
| 공식 한국어 Rules Hub | 관련 링크 9개 | 링크·목록 변경 발견 및 기록 |
| RiftJudge | 공개 주소 11,729개 | 사이트맵 주소·수정일 변화 확인. 질문별 실시간 사례 검색은 계속 사용 |
| 리프트나루 | 기존 1,527판본 유지 | 자동 제공 경로 미연결. 수동 가져오기 필요 |

**새 PDF·Q&A 본문 전체 수집 → 의미 검수 → 자동 반영까지 완료된 상태는 아니다.**
목록이 바뀌면 검토 대기로 남긴다. 동일 URL의 PDF 내용만 바뀌는 경우를 본문 해시로 정기 감시하는 후속 작업도 남아 있다.

첫 자료 확인 실패는 제한된 실행 환경의 네트워크 접근 거부(EACCES)였다. 정상 네트워크 권한으로 다시 실행해 성공했고, 현재 관리 프로그램에서 시작한 확인 프로그램도 성공했다.

## 관리 방법

1. 기존 `Open-Manager.cmd`로 관리 화면을 연다.
2. **자료 버전과 갱신**에서 현재 자료·출처 확인 상태를 본다.
3. 준비된 자료의 상세 기록을 확인한 뒤 **선택한 자료 적용 / 복구**를 사용한다.
4. 향후 준비·점검된 앱 버전은 **앱 버전 적용**에서 전환한다. 이때 서버 끄기 버튼을 먼저 누르지 않는다.
5. **서버 끄기**는 앱과 터널을 종료한다. 다시 켜면 Cloudflare 임시 주소가 바뀔 수 있다. 자료 변경 확인 프로그램은 별도로 유지된다.

코드 위치:

- 실제 앱: `releases/v0.1.2/` — 다음 변경은 새 앱 버전으로 만든다.
- 관리 프로그램: `src/manager.js` 및 `src/app-host.js`.
- 자료: `knowledge-releases/`, 활성 선택: `knowledge-releases/active.json`.
- 출처 확인 기록: `source-updates/status.json`, 프로그램 기록: `source-updates/monitor.json`.
- 제보·기존 질문 기록: 기존 `private/operations.sqlite`.
