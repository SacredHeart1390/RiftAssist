# v0.2.0 신규 카드·에라타 동기화 검증

2026-10-28, `feature/riot-api-v0.2`에서 기존 Draft PR #1의 번역 엔진 커밋 `1e3885b`를 이어 개발했다. 실제 Riot/OpenAI 호출 없이 합성 자료와 모의 transport로 검사했다. 운영 v0.1.7·운영 DB/키·사용자 기록은 사용하지 않았다. 개발 릴리스는 `ready: false`를 유지한다.

## 구현

- 기존 Riot 어댑터에 완전한 스냅샷 수집 경계를 추가했다. 모의 다중 페이지의 동일 스냅샷/버전/시각/총수·종료 커서·중복 ID·자료 형식·공개 근거·시간/크기 한도를 검증한다. 실제 동기화 모드는 승인 전 차단되어 있다.
- 기존 변환기에 카드별 원본 ID·버전/revision·공개/수정/수집 시각·에라타를 연결했다. 모의 원본 한국어와 생성 한국어를 분리해 승인된 AI 번역을 상위 출처의 한국어 변경으로 오인하지 않는다.
- 신규·영문 변경·에라타·공식 한국어 추가/변경/제거·출시/철회/공개 상태·기타 메타데이터·삭제 의심/복귀를 구분하고 원문 해시와 변경 전후를 보존한다. 문자열 버전을 사전순 비교하지 않는다.
- 변경 카드만 기존 번역 엔진에 전달한다. 변경 없는 번역은 그대로 재사용하고, 영어가 같은 에라타/locale 변화는 기존 영속 캐시에 적중한다. 영어가 바뀌면 기존 한국어를 현재 본문에서 제외하며, 에라타는 영어가 같아도 기존 승인을 재검토한다. 별도 에라타 메모를 효과에 임의 합성하지 않는다.
- 목록 누락은 삭제/철회하지 않고 후보 안에 보존한다. 최초 누락·관측 횟수·마지막 목격을 기록하고 반복 누락만으로 새 후보를 계속 만들지 않는다. 완전한 빈 목록도 기존 카드를 유지한다.
- 기존 번역 후보 저장기와 knowledge 후보 생성기를 확장했다. `sync-review.json`과 번역 검토 JSON을 해시로 보존하고 기준 규칙·저지 사례를 바이트 그대로 복사한다. 활성 포인터를 쓰지 않는다. 결정된 ID로 완성 후보 이후 상태 기록 장애가 발생해도 같은 후보를 재사용한다.
- 별도 격리 파일 저장소에 마지막 정상 관측·실패/재시도·일정·잠금을 저장한다. 실패는 정상 참조를 바꾸지 않으며 원시 오류·커서·비밀값을 로그에 넣지 않는다. 상태 손상/잔류 잠금·불완전 후보는 자동 삭제하지 않는다.
- `sync:mock`(한 번 검사), `sync:status`를 추가했다. 일정 엔진은 기본 비활성이고 별도 시작해야 한다. 실제 앱/관리자 시작 경로에 연결하지 않았다. 기본 6시간 검사·실패 지수 백오프·호출 제한 지연 우선·과도한 지연의 수동 점검을 제공한다.
- 브라우저 검증에서 비동기 카드 인식이 열어 둔 상세를 접는 기존 동작을 발견해 v0.2.0에서 펼침 상태를 보존했다. 재렌더링·모바일·언어 변경 뒤 비공식 번역/영어 원문 표시를 검사한다. 개인정보 처리방침에 격리 관측·후보·시도 기록의 저장과 자동 만료 부재를 한영으로 반영했다.

주요 신규 파일은 `src/card-sync.js`, `card-sync-diff.js`, `card-sync-store.js`, `riot-snapshot.js`, `scripts/sync-mock-cards.cjs`, 설정 예시와 `tests/card-sync.test.cjs`다. 기존 어댑터·변환기·카드 스키마·번역/후보 모듈과 UI·검사 안내도 보완했다. 상세 계약은 [card-sync.md](../../releases/v0.2.0/card-sync.md)에 있다.

## 데이터·Git 보존

`baseline.json`과 `preservation.json`으로 v0.1.7 추적 파일 65개가 원격 main과 동일함을 확인한다. 공유 활성 포인터·활성 지식 manifest/카드/규칙/저지 사례와 기존 추적 SQLite 캐시 3개의 해시를 유지한다. 기존 1,527개 카드는 삭제/교체/공식 재분류하지 않았다. 운영 DB·암호화 키·사용자 기록은 열거나 수정하지 않았다. 검증 중 새 DB/키는 모두 임시 테스트 루트에만 생성한다.

경로·DB 형식·토큰/개인키/자격증명 패턴으로 변경 후보와 staged blob을 검사한다. 값 자체는 출력하지 않고 비기능 테스트 문자열 4개만 예외로 허용한다. 이 검사는 모든 비밀정보나 Git 전체 이력을 보장하지 않는다. 기존 SQLite 추적 제외/이력 정리는 별도 작업이며 이번 변경에 포함하지 않는다. main 병합·Azure 변경·배포·자동 병합 설정·유료 호출은 금지 상태를 유지한다.

## 실제 승인 후 연결·남은 한계

1. 실제 Riot 전체 목록·페이지 일관성·ETag/304/delta·rate limit·정오표·한국어 locale·공개/출시·변경 순서를 확인해 transport/DTO 매퍼를 구현해야 한다. 현재 정수 revision은 모의 계약이다. 키를 주입하는 것만으로 실제 수집이 켜지지 않으며 실제 모드 차단 해제는 별도 승인된 변경이다.
2. Riot의 번역·제3자 AI 입력·저장/재배포·이미지·출처 조건을 확인해야 한다. 기존 리프트나루 권한은 미해결이며 공식 흐름에 혼합하지 않았다. 실제 번역 제공자·과금/계약/국외 이전·공식 한국어 용어/문체 보정도 남아 있다.
3. 자동 의미 검사는 완전한 등가성 증명이 아니다. 원문/정오표·복잡한 조건/타이밍·공식 한국어 교체·누락/철회·후보 수량은 관리자가 대조해야 한다. 전용 관리자 검토 UI와 승인본 저장 도구, 활성 자료 변경 후 명시적인 재기준화 도구는 추가 작업이다. 기준이 달라지면 현재 엔진은 안전하게 중단한다.
4. 관측·검토·시도 기록은 자동 만료하지 않는다. 디스크 용량·보관/백업·원자적 기록/fsync·공유 파일시스템·손상 상태/불완전 후보·잔류 잠금의 운영 복구를 검증해야 한다. 손상/불명확한 과금 상태에서 자동 삭제·유료 재시도하지 않는다. 명시적 실제 삭제 기능은 없다.
5. 실제 데이터/부하/장애/실기기 검증과 사용자 배포 승인이 필요하다. 자동 수집 성공으로 배포하거나 활성화하지 않는다. 운영 일정 연결도 별도 승인 대상이며 [기존 분리 배포/롤백 계획](../riot-v0.2.0-2026-10-28/deployment-and-rollback.md)을 유지한다.
