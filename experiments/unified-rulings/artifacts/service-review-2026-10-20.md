## 집 PC 종료

현재는 이용자 → Cloudflare 임시 연결 → 집 PC 앱3001 → 집 PC 규칙/DB 및 외부 AI 순서다. PC 종료·절전·인터넷 단절 때 새 질의응답을 제공하지 못한다. PWA 캐시로 이전 화면이 보일 수는 있다. Cloudflare나 구매 도메인이 앱 실행을 대신하지 않는다. PC를 꺼도 유지하려면 앱/DB/연결을 별도의 상시 기기나 호스팅으로 옮겨야 한다.

공식 참고: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/ — 로컬 서비스 연결이며 cloudflared 종료 시 URL 접속이 끝난다.

## 현재 패치 제약

- 화면 파일은 요청 시 읽지만 서비스 워커가 cache-first, 일반 정적 파일은 max-age300이다. 수정 시 캐시 버전/자산 버전과 새로고침 안내가 필요하다. 파일만 바꾸면 모든 기존 화면이 즉시 바뀌지는 않는다.
- 서버 코드·프롬프트는 프로세스가 시작할 때 읽는다. 현재 변경 반영에는 재시작이 필요하다.
- 규칙/카드 색인은 initialize에서 한 번 읽는다. 파일만 교체해도 실행 중인 검색 색인은 바뀌지 않는다.
- 관리자의 stopService는 터널과 앱을 함께 끈다. 현재 버튼 흐름으로 코드 재시작하면 서비스가 잠시 중단되고 임시 URL도 바뀔 수 있다.

### 제안: 연결을 유지하는 배포

터널 → 고정 로컬 중계 → 현재 앱 구조로 바꾸고 터널 수명을 앱 수명에서 분리한다. 별도 릴리스 폴더/포트에 새 앱을 시작해 준비 상태 확인 → 새 요청을 새 앱으로 전환 → 진행 중인 이전 요청이 끝나면 구 앱 종료. 실패하면 이전 앱으로 돌린다. 두 버전의 DB 구조/API 호환성, 자산 버전, 중복 호출 방지와 전환 중 요청 처리를 함께 설계해야 한다. 고정 도메인이 필수인 것은 아니지만 안정적인 장기 주소에는 별도 고정 Tunnel을 사용한다. PC·OS 재부팅까지 무중단이 되는 구성은 아니다. 현재 미구현.

## 제안: 자동 갱신 순서 (아직 미설정)

1. 관리 프로그램이 매일1회 공식 영한 허브의 Core/Tournament PDF, 패치 노트, 정오표 변경을 확인한다. PC가 꺼져 놓쳤다면 다음 시작 시 보충한다. 관리자 '지금 갱신'도 제공한다.
2. URL/버전/본문 해시를 비교해 바뀐 자료만 받는다. 게시일과 실제 적용일을 구분하고 한국어 지연·불일치를 표시한다. 변경 탐지/파싱에는 생성 AI가 필요 없다.
3. 실행 중인 자료와 별도 위치에 새 색인을 만든다. 규칙 번호 중복/대량 누락/파싱 실패/버전 불일치는 자동 적용을 보류하고 기존 정상본을 유지한다. 의미 판단이 필요한 큰 변경은 관리자 검토 대상으로 둔다.
4. 검증된 새 색인을 한 번에 활성화한다. 각 질문은 시작 시 선택한 색인 스냅샷을 끝까지 사용하고 다음 질문부터 새 자료를 쓴다. 버전/최종 확인/실제 수집 시각과 되돌리기 기능을 제공한다. 현재 메모리 재로딩 기능 추가가 필요하다.
5. RiftJudge는 현재 질문별 실시간 조회를 유지한다. 전체 자체 색인을 추가할 때 사이트맵으로 최초 목록을 만들고, 이후 신규/변경 사례만 제한된 속도로 갱신한다. lastmod만으로 상태/삭제 변경을 모두 보장하지 않으므로 실제 사용 사례를 재확인하고 주기적으로 대조한다. 실패와 삭제를 구분한다.
6. 번역은 실제 펼친 변경 자료만 만들고 기존 번역은 재사용한다. 전체 문서를 매번 모델에 전달하거나 전부 다시 번역하지 않는다.

권장 구현 순서: 공식 자료 자동 발견·갱신 검증 → 규칙 색인 무중단 교체 → 관리자 최신화 상태/되돌리기 → 앱 배포 시 터널 유지·요청 전환 → Q&A 전체 증분 색인 확장. 이번에는 조사만 했고 위 기능을 구현/예약하지 않았다.
