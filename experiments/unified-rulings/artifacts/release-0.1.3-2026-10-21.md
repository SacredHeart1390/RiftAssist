# v0.1.3 — 규칙·Q&A 본문 자동 갱신

## 적용 상태

- 다음 서버 시작 버전: **v0.1.3**. 관리 화면의 **서버 켜기**로 실행한다. 이번 작업에서 운영 앱과 Cloudflare 터널은 시작하지 않았다.
- 실제 자료: 공식 코어룰 2,494개 + 대회 규칙 976개 + 기존 공식 보충 자료 17개. 영문/한국어와 조항별 출처·페이지·문서 날짜를 유지한다.
- 초기 Q&A 수집은 진행 중이다. 2026-10-21 06:39 KST 무렵 공개 사이트맵 11,731건 중 본문 1,227건 확보, 수집 오류 0건. 적용된 첫 정상 스냅샷에는 970건이 들어 있다. 이후 누적 약 1,000건 단위 또는 초기 수집 완료 시 자동 반영한다. 정확한 현재 값은 관리 화면의 **자료 상태 새로고침**에서 확인한다.
- 백그라운드 수집기는 앱과 별개로 실행된다. PC를 끄면 멈추며, 관리 프로그램을 다시 열면 저장한 대기 목록부터 이어간다. Windows 부팅 자동 실행은 설정하지 않았다.

## 동작

1. 6시간마다 공식 영문/한국어 Rules Hub에서 현재 PDF 주소를 발견한다. 파일 변경 확인에는 ETag/Last-Modified를 사용한다.
2. 전체 PDF를 내려받아 좌표 기준으로 조항을 분리한다. 버전, 중복 ID, 누락, 급격한 내용 변화, 핵심 조항 문맥, 미래 날짜를 확인한다. 실패한 자료는 기존 정상본을 유지한다.
3. RiftJudge 공개 사이트맵 전체를 읽고 각 사례의 질문·답변 본문·검증 상태·룰 버전·링크를 저장한다. 댓글·계정 프로필은 수집하지 않는다. 동시에 2건, 초당 최대 4건으로 제한한다.
4. 변경된 기존 사례와 신규 사례를 우선 수집하고, 기존 본문도 7일마다 다시 확인한다. 접근 제한·일시 장애는 대기 후 재시도한다. 404/410을 두 번 확인하면 삭제 상태로 구분하고 이전 본문은 보존한다.
5. 구조 검사를 통과한 자료를 별도 버전으로 저장하고 포인터를 교체한다. 앱은 최대 10초 뒤 새 질문에 반영한다. 이미 답변 중인 질문은 시작 시점의 자료를 유지한다.
6. 사례는 로컬 본문 검색을 우선 사용한다. 초기 수집 중이거나 결과가 부족하면 기존 RiftJudge 원격 검색으로 보완한다. 폐기/삭제 사례는 일반 근거에서 제외한다.

전체 DB를 매 질문마다 AI에 보내지 않는다. 공식 근거 최대 8개, 사례 최대 4개를 유지하고 모델에 보내는 긴 사례 본문을 제한하며 부분 발췌임을 표시한다. 원본 본문은 로컬에 보존한다. 수집·색인 자체의 OpenAI 호출은 0회다.

## 관리 방법

- **지금 자료 갱신**: 수집기에 즉시 확인을 요청한다. 현재 배치가 끝나면 처리하며, 앱을 재시작할 필요가 없다.
- **자료 상태 새로고침**: 수집 건수, 적용 버전, 오류, 다음 재시도 상태를 확인한다.
- **선택한 자료 적용 / 복구**: 이전 정상 자료로 수동 복구한다. 자동 수집기가 계속 켜져 있으면 다음 갱신에서 새 자료가 다시 적용될 수 있으므로 장기 고정이 필요할 때는 수집기 중지도 함께 진행한다.
- 이전 앱 **v0.1.2**와 원래 백업 앱은 보존했다. v0.1.3 실행 파일은 `releases/v0.1.3/`, 수집 DB는 `source-updates/content.sqlite`, 상태는 `source-updates/content-status.json`이다. 비밀키와 사용자 운영 DB는 종전 위치를 유지한다.

## 확인한 범위

격리 점검 7항목 통과: 실행 파일 구문, 실제 Q&A 본문 추출/ID 검사, 재개·변경·삭제 재시도, 로컬 검색/폐기 사례 제외, 영한 조항/부모 문맥, 손상 자료 교체 거부, 실제 앱 시작/카드 검색/비공개 파일 차단. 결과는 `releases/v0.1.3/content-verification.json`.

유료 AI 호출 0회. 운영 앱·터널 시작 0회. 수집기만 재시작해 저장된 큐 재개를 확인했다. 기존 API 키·모델·호출 한도는 변경하지 않았다.

## 남은 범위와 주의할 자료 상태

- 전체 사이트맵 주소 확보와 전체 본문 수집 완료는 다르다. 초기 수집 완료 전에는 상태를 `partial`로 표시한다. 접근할 수 없는 사례를 완료로 꾸미지 않으며, 제외된 주소 수를 따로 표시한다.
- `validated`는 구조·해시 검사 결과다. Q&A 판정의 정확성이나 커뮤니티 사례의 공식 권위를 보증하지 않는다. 기존 저지 검수는 계속 필요하다.
- 공식 대회 PDF는 영문 내부 날짜 2026-10-08, 한국어 2026-10-09로 서로 다르다. 기존에 사용하던 양쪽 전체 본문과 동일함을 확인한 경우에만 기존 번역 연결을 유지하며 날짜를 각각 저장한다. 새 내용에서 날짜가 달라지면 자동 연결을 보류한다.
- 기존 보충 기사 17개와 카드 DB 1,527개는 보존한다. 이번 전체 본문 자동 갱신 대상은 코어룰 PDF, 토너먼트룰 PDF, RiftJudge 공개 Q&A다. 보충 뉴스 기사와 리프트나루 카드 자동 수집은 별도 후속 작업이다.
- 원본 사이트의 구조 변경·새 조항 번호 체계·큰 문서 개정은 안전하게 보류될 수 있다. PDF 해석 오류나 소스 차단이 있으면 관리 화면에 이유가 표시된다.
- 새 PC로 옮길 때는 자료·설정 외에 `tools/ingestion/`의 HTML 파서와 PDF.js 실행 환경도 함께 준비해야 한다.
