시작은 10월 22일, 중단 후 10월 23일 06:35 KST 적용 완료. 개발 기준은 `releases/v0.1.5/`. 통합본 루트의 오래된 `src/`를 수정본으로 오인하지 않는다.

## 확인한 원인

1. **재점령 득점:** 원래 기록은 점거 타이밍 383.4.d 등을 전달했으나 핵심 제한 472를 전달하지 않았다. 짧은 기본 조항이 단어 검색 상위 8개에서 밀렸고, 득점 쟁점을 기본 규칙에 연결하는 처리가 없었다.
2. **유성/후퇴:** 대상의 일시적 조건 변화 예외 359.3.e.3만 전달하고, 선택 변경 제한 355.15와 대상이 사라졌을 때의 기본 해결 규칙은 전달하지 않았다. 카드 본문은 정상 연결돼 있었다. 모델은 주장 반박 후 남은 대상의 처리까지 완성하지 못했다.
3. 부모 문맥은 인용 가능한 핵심 형제 조항을 보충하지 못했고, 필수 근거 검사는 색인 내 존재만 확인했다. 답변 지침에는 실제 처리 완료 기준이 부족하고 일부 저지 호출 지시가 있었다. 공식 인용 0건을 일반적인 판정 불가 문구로 덮는 후처리도 있었다.
4. 리프트저지의 verified 사례에도 유성의 과거 반사형 효과 문구가 섞여 있었다. 현재 카드 문구와 다른 사례를 그대로 적용해서는 안 된다.

## 구현

- 득점/점거/정복·대상/해결 관련 한영 검색어 및 쟁점 감지 추가. 기본 원칙을 먼저 확보하고 남는 자리를 단어 순위로 채운다. 부적법 대상의 세부 조항만 검색되면 일반 원칙도 보강한다.
- 보통 공식 근거 8개, 복합 쟁점은 필요한 경우 최대 12개. 실제 전달에서 빠진 필수 조항까지 추적. 전체 입력 50,000자와 생성 1회 제한 유지. 질문별 정답을 하드코딩하지 않는다.
- 게임 상황에서 무관한 대회 조항의 단어 점수 완화. 리프트저지에서도 실제 쟁점 일치를 확인하고, 관련 카드 및 득점 제한/대상 변경·부분 해결 사례를 우선한다.
- 결론에 실제 결과를 포함하고 `resolutionSteps`로 처리 순서를 반환·표시. 주장의 옳고 그름에서 멈추지 않도록 지침 추가. 기존 화면도 결론에서 결과를 읽을 수 있다.
- 일반적인 저지 문의로 답을 대신하지 않도록 변경. 실제 대회 절차가 공식 개입을 요구할 때는 적용 절차와 당장 할 행동을 설명한다. 중요한 정보가 부족하면 조건별 가능한 결과와 필요한 질문을 제시한다.
- 허용되지 않은 인용은 여전히 제거한다. 근거 없는 확정 답변이나 처리 순서 누락은 생성 오류로 기록하며 자동 유료 재시도하지 않는다. 검색 실패를 규칙상 판정 불가로 표현하지 않는다.
- 옛 UI 파일은 그대로 보존하고 새 `app-ui4.js`/`styles-ui4.css`와 서비스 워커 캐시를 사용한다. 기존 v0.1.4, 원본 앱, 운영 관리자 화면 보존.

## 검증 범위와 결과

- 검색 회귀 확인 12건 통과: 제보 2건, 상대 플레이어/다음 턴/다른 전장, 모든 대상 이탈/보드 이동/영문 질문, 복합 쟁점, 기존 덱 제한, 필수 조항 누락 감지. **변형 문항은 검색 검증이며 생성 답변의 정답 평가로 세지 않는다.**
- 문법 6파일 확인. 실제 카드 ID를 포함해 제보 2문항만 OpenAI로 각각 1회 생성했다. 모델/추론 설정 유지, 자동 재시도 없음. 입력 8,116 / 출력 1,975, 총 10,091토큰.
- 첫 답변: 같은 플레이어가 같은 전장에서 같은 턴 다시 득점할 수 없고, 상대의 득점은 제한을 초기화하지 않는다고 답함. 472 및 470/471.1/471.2 인용.
- 두 번째: 후퇴 먼저 → 손으로 복귀 및 소진 룬 1개 채널링 → 유성의 떠난 대상 지시 무시 → 남은 적법한 대상에 3피해 → 대상 재선택 없음. 355.15 및 359.3.e 관련 조항 인용. 옛 문구 전제 사례와 현재 카드의 차이도 설명.
- 최초 실행은 제한 환경의 네트워크 EACCES로 생성 실패했다. 해당 기록은 별도 보존했고, 정상 네트워크로 확인한 두 응답을 적용 판단에 사용했다. API 키는 출력/문서에 저장하지 않았다.
