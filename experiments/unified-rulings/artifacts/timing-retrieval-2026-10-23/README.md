# v0.1.7 — 복합 처리 순서 검색 누락 수정

2026-10-23. 기준 v0.1.6 보존, 새 구현 releases/v0.1.7. GitHub/클라우드 이전은 이번 작업 범위가 아니며 미실행.

## 확인된 원인

- 실제 질문 로그 3건(최신 fd50205a…)의 검색 분류는 targetResolution만 활성화했다. 필수 대상 조항8개가 근거8개 한도를 모두 사용해 다른 쟁점과 일반 순위의 근거가 전부 탈락했다. 인용은 359.3.d 또는340.1에 한정되었다.
- 2026-10-09 코어룰2494항목은 이미 active 자료에 있었다. 158.3/158.3.a/321/323.4/383.3과 피해418의 하위 조항도 존재했다. 개정 PDF 미수집이 이번 오류의 원인은 아니다.
- 기존 지침은 제공된 근거만 사용하게 했지만, 모델의 '제공 근거에 없다'는 출력을 재검색으로 되돌리는 경로가 없었다. confidence만으로 상태를 판단해 실질적인 답변 유보도 ruling-generated로 기록됐다.
- Q&A 검색은 대상 처리 필터 때문에 유발·정리 사례를 놓칠 수 있었다. 옛 재귀 유발 방식 사례는 현재 직접 지시 문구에 그대로 적용할 수 없다.

## 이 사례의 현행 규칙상 처리

1. 유성의 첫 지시, 두 번째 지시대로 서로 다른 두 유닛에 피해3을 표시한다(158.1, 418.1.b). 별개 지시라고 해서 사이에 정리나 다른 체인 항목 처리를 끼우지 않는다(158.3/158.3.a, 321).
2. 유성을 모두 처리하고 정리한다. 위력2에 피해3이 표시된 유닛 둘을 처치한다(142.4.b, 319.5, 323.4). 첫 피해 직후 바로 죽는다는 이전 처리 설명도 수정 대상이다.
3. 빅토르가 남아 있으므로 조건을 충족한 사망 둘에 대해 각각 유발한다. 동시에 유발한 둘의 순서를 통제자가 정하고, 미확정 항목을 확정한 뒤 정상 체인 순서로 처리한다(383.2.c.2, 383.3/383.3.d, 337.3, 340.1). 아무도 반응하지 않으면 기지에 위력1 신병 토큰 둘을 사용한다. 유발 스킬 두 개 전체가 반응 불가능한 하나의 효과가 되는 것은 아니다.

## 공통 변경

- 질문 및 선택 카드 본문에서 유발·피해·처치·정리·처리 시점을 함께 분석. 카드명을 하드코딩한 정답 분기 없음.
- 필수 일반 원칙을 먼저 확보하고 추가 검색 공간을 별도로 남김. 보통 최소12, 복합 쟁점은 필수수+6, 최대40조항. 공식 본문의 참조 정의와 관련 하위 조항도 확장.
- 타이밍 핵심 규칙은 번호뿐 아니라 현재 영어 원문의 의미 패턴을 확인. 유일한 의미 일치 조항이 있으면 재번호를 따라가고, 누락/다의성은 trace와 health의 unresolvedRuleAnchors에 표시. 규칙이 갱신되면 새 snapshot에서 색인도 다시 생성.
- 하나의 공식 문서에 서로 다른 버전의 조항이 섞인 자료는 거절. 요청마다 단일 자료 snapshot 고정; 문서 버전 및 확인 시각을 모델에 전달. 기존 6시간 공식 자료 확인/Q&A 수집 유지. 수집 프로세스 코드 자체는 이번에 교체하지 않았다.
- 유발·정리 사례의 검색 우선순위 보강, 직접 피해 지시와 충돌할 수 있는 재귀 유발 사례는 감점 및 적용 경고.
- 모든 질문에 evidenceAssessment를 받아 근거 누락·자료 충돌·실제 상황 정보 부족을 구분. 회피형 결론/인용·처리 순서 누락은 로컬 근거 재검색 후 최대1회 추가 생성. 네트워크/출력 한도/사용 한도 오류는 자동 재시도하지 않음.
- 각 생성 시도는 기존 일일/세션/동시 호출 한도를 별도로 예약·정산. 모델/추론 강도 유지, 입력50000자/출력4096 기본한도 유지, 전체 생성 경로85초 내 제한. 입력 초과 시 일반 사례부터 제외해 필수 규칙 보존. 유료 호출은 요청당 최대2회가 될 수 있음.
- 그래도 답변 완성에 실패하면 잘못된 판정 대신 기술적 검색 오류 상태로 기록한다. 실제 게임 정보가 필요한 경우는 조건별 처리와 구체적 질문을 허용한다. 무조건적인 정답 또는 모든 미래 질문의 정확성을 보증하지 않는다.
- 최초/보강 검색, 필수 조항, 후보/선택/참조 관계, 개정 버전, 생성 시도/사용량을 기존 암호화 요청 로그에 보존. 내부 사고과정 저장을 요구하지 않는다.
