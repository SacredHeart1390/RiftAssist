# v0.2.0 카드 데이터 관리자 검토·승인 검증

2026-10-28, `feature/riot-api-v0.2`의 동기화 커밋 `fda5d00`을 이어 구현했다. 기존 Draft PR #1을 유지한다. 실제 Riot/OpenAI·운영 DB/키·사용자 기록을 사용하지 않고 합성 카드와 임시 개발 루트에서 검사했다. 릴리스 `ready: false`를 유지한다.

## 구현 결과

- 기존 동기화/번역 후보·해시 manifest·knowledge 후보를 검증해 검토 bundle로 연결한다. 별도 번역 preview도 지원한다. 변경 전후 영어/한국어·카드 비용/기호·출처·경고·미발매/누락 상태·이전 번역을 비교할 수 있다.
- 카드 데이터와 번역을 별도 항목으로 개별 승인/거절/보류하고, 사유·설정된 관리자 식별자·시각을 영속 저장한다. 최대 50개 일괄 결정을 모두 검증한 뒤 한 번에 반영한다. 오류 번역은 승인할 수 없고 경고는 명시적으로 확인해야 한다.
- 항목 fingerprint·bundle revision·후보/기준 해시·마지막 동기화·현재 활성 버전과 작업 ID를 묶어 중복 승인, 오래된 후보, 재시도 중복, 동시 갱신 충돌을 막는다. 더 새로운 후보나 결정 변경은 기존 최종 승인 계획을 무효화한다.
- 승인 항목만 기존 knowledge 생성기로 별도 승인본을 구성한다. 미승인 항목은 정상 기준을 유지하고 신규 미승인 카드는 제외한다. 번역 보류 시 명시적으로 영어만 구성할 수 있다. 누락 의심 승인은 삭제를 하지 않으며 동일 결과는 새 릴리스를 만들지 않는다.
- 최종 활성화와 롤백을 별도 권한·확인·버전/manifest 해시가 필요한 명령으로 분리했다. 기존 원자적 포인터 전환과 이전 정상 자료를 보존한다. 일반 관리자/knowledge 경로에서 카드 표시 메타데이터를 제거해도 마커가 있는 v0.2.0의 카드 변경은 최종 승인을 우회하지 못한다. 모든 실제 활성화/롤백 검사는 임시 개발 자료에서만 수행했다.
- 활성화 의도를 먼저 감사 기록에 저장하고 결과를 나중에 기록한다. 포인터 변경 전후 장애는 미완료 의도로 남기고 새 쓰기를 차단한다. 운영자가 잠금/파일을 점검한 뒤 명시적으로 복구하면 포인터 상태를 확인해 결과만 기록한다.
- Control Center용 `riftassist-control-1` 서명 인터페이스와 전용 자식 프로세스 파이프를 제공한다. HMAC·nonce·세션 만료·권한별 검사·입출력 제한을 적용한다. 인증 자료는 전용 bootstrap 파이프로 메모리에만 주입하고 기존 관리자/API 키를 읽지 않는다. HTTP/TCP 포트와 공개 관리자 화면을 추가하지 않았다.
- 추가 전용 파일 저장소에 순서/이전 해시로 연결된 평문 JSON 감사 이력을 보존한다. read/거절에도 감사 코드를 남기며 서명/키·원시 요청 본문은 저장하지 않는다. 개인정보 처리방침에 관리자 식별/사유·보관·암호화/접근 확인 사항을 한영으로 반영했다.

주요 신규 파일은 `src/card-review.js`, `card-review-auth.js`, `card-review-store.js`, `card-review-control.js`, `card-review-authorization.js`, `scripts/card-review-control.cjs`, 설정 예시와 안내 문서, `tests/card-review.test.cjs`, `tests/helpers/card-review-fixture.cjs`다. 기존 후보 저장/knowledge 활성화 경계와 공개 API 비노출 검사도 보완했다. [인터페이스·관리 절차](../../releases/v0.2.0/card-review.md)에 필드·권한·오류·복구 흐름을 정리했다.

## 보존과 Git

`baseline.json`/`preservation.json`으로 운영 v0.1.7 파일 65개가 원격 main과 동일함을 확인한다. 공유 활성 포인터·활성 manifest/카드/규칙/저지 사례·추적 SQLite 캐시 3개의 해시를 유지한다. 운영 DB/암호화 키·사용자 기록을 열거나 수정하지 않았다. 기존 리프트나루 1,527개 자료를 삭제/교체/공식 재분류하지 않았다.

개발 릴리스의 파일 해시를 갱신하고 `ready: false`를 유지한다. 변경 후보와 실제 staged blob을 경로·DB 형식·토큰/개인키/자격증명 패턴으로 검사한다. 정확한 비기능 테스트 문자열 4개만 예외다. 검사는 모든 비밀정보나 Git 전체 이력을 보장하지 않는다. 기존 SQLite 추적 제외·이력 정리는 별도 작업이다. main 병합·Azure 수정/재시작/배포·실제 유료 호출·자동 병합 설정을 하지 않는다.

## 남은 작업과 한계

1. **Windows Control Center:** GUI/설치본, 실제 관리자 신원/권한·Windows ACL/DPAPI·파이프 상속·실행 파일 신뢰/서명·C# canonical JSON/HMAC 교차 검증이 남아 있다. 현재 Linux Node 파이프 테스트 결과다. 서로 다른 두 사람이 반드시 승인하는 조직 정책은 아직 없다.
2. **공식 자료:** 실제 Riot 승인/번역·AI 입력·저장/재배포·출처 조건, 실제 DTO/locale·revision·권한·공식 한국어 품질을 확인해야 한다. 현재 검토 도구도 합성/mock만 허용한다. API 승인이나 키 존재로 활성화되지 않는다.
3. **감사·복구 운영:** 검토 이력은 별도 평문 JSON이며 자동 만료/삭제·회전/체크포인트가 없다. 보관/접근·백업/암호화·fsync·디스크 장애·공유 파일시스템·잔류 잠금의 운영 복구를 검증해야 한다. 해시 체인은 파일 소유자의 전체 재작성/끝부분 삭제까지 보장하는 외부 WORM 감사 저장소가 아니다. 현재 journal 10,000개/이벤트 16MB, 일괄 50개 한도와 매 작업 전체 재생 방식은 대규모 운영에 추가 설계가 필요하다.
4. **후속 흐름:** 활성 기준이 바뀌면 기존 동기화가 안전하게 중단한다. 승인/거절 subset과 마지막 수집의 재기준화·장기 수집 재개는 별도 도구가 필요하다. 승인본/번역 의미·에라타·누락·후보 범위는 사람이 검토해야 한다.
5. 실제 공식 자료·실기기·운영 연결·부하/장애·개인정보 법적 정보와 동의/계약 확인 후 별도 배포 승인이 필요하다. 기존 [분리 배포/롤백 계획](../riot-v0.2.0-2026-10-28/deployment-and-rollback.md)을 유지하며 이번 작업으로 라이브를 전환하지 않는다.
