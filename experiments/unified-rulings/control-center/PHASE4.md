# Control Center 4차 — 운영 관리자 읽기 전용·실행 패키지·아이콘

2026-11-02. v0.2.0 / feature/riot-api-v0.2 / 기존 Draft PR #1. 사용자가 3차의 Windows 10 → Azure SSH 상태 조회 성공을 확인했습니다. **이번 개발에서는 실제 Azure와 운영 관리자/사용자 자료에 접속하지 않았습니다.**

## 기존 운영 API 조사

운영 v0.1.7 src/manager.js는 기본 127.0.0.1:3100에 바인딩합니다. loopback 소켓·Host 검사, POST Origin/JSON 검사, private의 기존 manager.key와 safeEqual 검증, rift_admin 쿠키 세션(8시간, 최대 20개)을 사용합니다. Control Center가 인증을 우회하거나 서버 키를 읽어오는 기능은 없습니다.

| 요청 | 기존 동작/4차 사용 |
| --- | --- |
| POST /api/login | 기존 키 검증, 메모리 세션/HttpOnly 쿠키 발급. 이 인증 요청만 POST 허용 |
| GET /api/status | AI 활성 여부·일자별 호출/토큰·한도·관리자가 관리하는 앱/최근 오류. 집계 GET은 DB 갱신 코드 없음 |
| GET /api/reports | 최대 최근 200개 ID·분류·처리 상태·접수 시각·연결 ID |
| GET /api/reports/{UUID} | 암호화된 제보/연결 질문·답변 스냅샷/처리 이력을 기존 서버가 복호화해 응답 |
| 기타 관리 API | 시작/중지/AI/한도/제보 수정/백업/버전/자료 활성화 등은 4차 운영 연결에서 전송 전 차단 |

기존 API에 별도 운영 로그/질문 전체 목록 엔드포인트가 없으므로 이번에는 최근 관리자 오류의 존재·고정 분류와 제보에 보관된 연결 질문/답변만 표시합니다. raw journal·서버 파일·DB·키를 SSH로 읽지 않습니다. systemd와 CPU/HTTPS는 기존 독립 SSH 상태 조회를 유지합니다. 관리자 appRunning은 관리자가 실행한 자식 앱의 상태이며 외부 systemd 앱 실행 여부와 다를 수 있어 별도 표시합니다. 사용량은 기존 일별 calls 집계이며 실제 OpenAI 청구 금액/모든 질문 수로 확대 해석하지 않습니다.

## 연결/보안 구조

Windows OpenSSH의 기존 엄격한 호스트 키/키·agent 인증/ProgramData 환경 수정을 재사용합니다. 별도의 고정 정책으로 **ssh -W 127.0.0.1:3100** 표준입출력 채널을 사용합니다. -W는 원격 direct-tcpip 연결이며 원격 셸/명령을 실행하지 않습니다. Windows에 로컬 수신 포트를 열지 않고 서버 3100을 외부에 공개하지 않습니다. 사용자 config/ProxyCommand·포워딩 상속은 계속 차단하며 목적지를 고정합니다.

HttpClient는 이 SSH 스트림만 사용하고 직접 HTTP 접속/프록시/리다이렉트로 우회하지 않습니다. Host/Origin은 기존 서버가 요구하는 http://127.0.0.1:3100이며 기존 로그인/쿠키를 그대로 통과합니다. 기존 관리자 키는 **쓰기 권한도 가진 전체 관리자 자격증명**입니다. 이번 읽기 제한은 Control Center의 경로·HTTP 메서드 제한이며 서버가 발급하는 독립적인 읽기 전용 역할은 아닙니다. 전용 읽기 자격증명/서버 측 scope 추가는 v0.1.7 변경 없이 제공할 수 없으므로 후속 검토 사항입니다.

키는 PasswordBox에서 입력 즉시 비우고 로그인 요청 본문 바이트는 사용 후 지웁니다. 키·쿠키를 설정/명령 인수/환경/로그/파일에 저장하지 않습니다. 관리 키는 Windows OpenSSH 인증용 SSH 개인키와 다른 값입니다. 일반 SSH 설정은 기존 6개 비밀이 아닌 메타데이터만 저장합니다. 쿠키는 클라이언트 메모리에서 최대 10분만 사용하고 프로필/모드 변경·연결 해제·실패 시 폐기합니다. 30초 간격의 로컬 만료 검사에는 네트워크 조회가 없으며 화면 자료도 지웁니다. 서버의 기존 8시간 세션을 취소하는 logout API는 없으므로 로컬 폐기가 서버 세션을 즉시 철회한다는 뜻은 아닙니다. 관리 키 문자열/표시 자료의 .NET 메모리 전체 보안 소거를 보장하지는 않습니다.

상태 응답은 필요한 집계만 투영하고 오류는 존재 여부/고정 분류로 표시합니다. 제보는 선택 시 메모리에 읽어 내용·질문·판정/근거·처리 이력만 네이티브 텍스트로 표시하며 내부 trace·예상하지 못한 필드/자격증명을 통째로 직렬화하지 않습니다. 운영 제보 JSON 내보내기/수정, 운영 AI 변경/백업은 비활성 상태입니다. 읽기 실패 시 화면 자료를 지우고 재인증을 요구합니다. 인증 실패·HTTP/응답 검증·시간 초과·SSH 실패/연결 실패를 분리하며 민감한 오류 원문을 표시하지 않습니다. SSH LogLevel=ERROR가 forwarding 상세를 숨길 수 있어 일부 실패는 forwarding 거절/관리자 미실행을 완전히 구별하지 못하는 일반 연결 오류로 표시합니다.

## 승인 이후 사용자 연결 방법

1. 실제 운영 제보/질문을 열람할 권한·필요 범위와 기존 전체 관리자 키 사용을 운영자가 승인해야 합니다. 개발 중에는 합성 자료만 사용했습니다.
2. 기존 SSH 설정과 verified known_hosts를 준비합니다. 기존 상태 조회 성공이 SSH direct-tcpip forwarding 허용까지 보장하지는 않습니다.
3. **이미 실행 중인 기존 관리자**가 올바른 운영 RIFTASSI_DATA_ROOT와 127.0.0.1:3100을 사용하는지 운영자가 별도 확인합니다. 없으면 앱에서 시작/설치/재시작하지 않습니다.
4. 특히 기존 v0.1.7 manager.js는 시작 및 주기적 복구에서 ensureSourceMonitor()로 구형 수집기를 기동합니다. 관리자 시작은 단순 읽기 작업이 아니며 수집기 부작용을 검토한 별도 승인이 필요합니다. 이번 작업에서 실행하지 않았습니다.
5. sshd forwarding이 거절되면 설정 변경을 자동 실행하지 않습니다. PermitOpen/AllowTcpForwarding 등 최소 허용 정책은 운영자가 별도 검토·승인해야 합니다. 관리자 포트를 인터넷에 공개하지 않습니다.
6. 승인 후 Azure 대시보드의 관리자 키 입력 → **관리자 읽기 연결**을 직접 누릅니다. 상태/AI 집계만 우선 조회하고, **운영 제보 목록 조회**와 행 선택으로 필요한 상세만 읽습니다. 조회에 확인 팝업은 없습니다. 시작/설정 저장/타이머가 원격 접속·로그인을 실행하지 않습니다.
7. 오류 공유는 표시 코드/종료 코드·고정 분류로 제한하고 실제 키·쿠키·질문/제보·응답·서버 오류 원문을 GitHub에 붙여넣지 않습니다.

## 패키지와 아이콘

다운로드 아티팩트 이름은 **RiftAssist-ControlCenter-v0.2.0-win-x64**이며 GitHub가 같은 이름의 ZIP을 제공합니다. ZIP 루트에 RiftAssist.ControlCenter.exe와 DLL, runtime/node.exe, backend/v0.2.0, 무결성 manifest가 있습니다. 검증 보고서/스크린샷은 별도 아티팩트로 분리해 EXE 상위에 다른 공통 폴더가 생기지 않게 했습니다. EXE만 다른 곳으로 옮기지 말고 전체를 풀어 실행합니다. 수동 Node/백엔드 경로 설정은 필요 없습니다. SSH 개인키/known_hosts 설정은 계속 사용자별 필요합니다.

Publish-Windows.ps1의 Node 버전/아키텍처·라이선스·manifest 검증을 유지합니다. CI에서 includeBaseDirectory=false ZIP을 만들고 루트 경로를 검사한 뒤 새 폴더에 풀어, 그 추출본의 backend/Node 통합 검사와 실제 EXE 시작/종료를 수행합니다. GitHub에는 추출본 단일 디렉터리의 내용만 실행 아티팩트로 업로드합니다.

운영 v0.1.7 public/index.html의 rel=icon은 /icon.svg입니다. 이 원본을 수정하지 않고 Inkscape SVG 래스터화/Pillow 크기 변환으로 **16/24/32/48/64/128/256px** ICO를 만들었습니다. 출처/해시는 Assets/icon-origin.json에 기록합니다. EXE ApplicationIcon과 WPF Window 스타일(창·작업표시줄)에 같은 ICO를 사용합니다. Chrome 로고를 사용하지 않습니다. Windows CI는 ICO 리소스 프레임·WM_GETICON·EXE shell 아이콘 추출을 검사합니다. 실제 Windows 10 Explorer/작업표시줄의 아이콘 캐시·DPI는 사용자 기기 확인 사항입니다.

## 검증 범위와 한계

기존 v0.1.7 manager.js를 바이트 그대로 테스트 fixture로 읽되 저장소 코드를 수정하지 않습니다. HTTP/auth 라우터는 그대로 실행하고 DB·키·앱/수집기/서비스 모듈과 타이머는 합성 구현으로 대체합니다. Host/Origin/쿠키의 성공·거절, 인증 전 무접속, 금지 경로, 제보 한글/예상하지 못한 필드 제외, 401/리다이렉트/잘못된 JSON/크기 초과/취소/끊김을 검사합니다. 임시 키를 생성한 127.0.0.1 모의 SSH 서버로 실제 OpenSSH -W → 합성 관리자 HTTP 연결과 거절을 검사합니다. 운영 DB/키·실제 사용자 자료·실제 API는 사용하지 않습니다.

검증 집계와 최신 패키지 링크는 [4차 보고서](../artifacts/control-center-phase4-2026-11-02/README.md)에 기록합니다. Windows CI 성공은 Windows 10 실기기/실제 운영 API 접속 성공을 뜻하지 않습니다. main 병합, 실제 Azure 접속/수정·재시작·배포, 운영 DB/키 변경, 유료 Riot/OpenAI 호출은 하지 않습니다.
