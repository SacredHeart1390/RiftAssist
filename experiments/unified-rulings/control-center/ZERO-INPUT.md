# SSH 기반 관리자 자동 인증

2026-11-02 · v0.2.0 Control Center · 개인 관리용

## 실행 방법

기존 Windows 사용자 계정에서 새 패키지를 풀고 최상위 `RiftAssist.ControlCenter.exe`를 실행합니다. 유효한 SSH 설정이 저장되어 있으면 서버 상태 → 관리자 키 읽기 → 기존 `/api/login` → AI 사용량·호출 한도·활성 여부·제보 목록 순서로 자동 조회합니다. 키 입력, 복사, 연결 버튼, 이전 DPAPI 자동 연결 옵션이 필요하지 않습니다.

SSH 설정이 없는 최초 설치에서는 앱이 정상 실행되고 자동 접속하지 않습니다. 설정 탭에 서버 주소·사용자·포트·기존 개인키 경로·known_hosts·HTTPS 주소를 저장한 뒤 **연결 복구**를 누르거나 앱을 다시 실행하세요. 개인키 내용은 복사하지 않습니다. 기존 Windows OpenSSH 키/agent, 잠금 해제된 개인키와 사전에 확인한 known_hosts가 필요합니다. BatchMode이므로 SSH 암호·키 암호를 묻는 창으로 우회하지 않습니다.

같은 사용자 프로필의 기존 설정 경로를 재사용하므로 ZIP을 교체해도 설정을 다시 입력할 필요가 없습니다. Windows 로그인 시 앱을 시작하는 서비스·예약 작업은 추가하지 않습니다. 설정 저장 자체는 접속을 시작하지 않습니다. 앱 시작 또는 연결 복구가 자동 조회를 시작합니다.

## 고정 키 읽기와 인증

서버에서 읽는 파일은 다음 하나로 고정됩니다.

`/home/azureuser/RiftAssist/experiments/unified-rulings/private/manager.key`

허용한 SSH 인수와 표준입력 스크립트를 검사합니다. 임의 경로·범용 명령 입력, sudo, 파일 권한 변경, 서버 설치는 제공하지 않습니다. 정규 파일·심볼릭 링크 여부·읽기 권한·크기를 검사하며 최대 67바이트만 수신합니다. 키는 64자리 ASCII 16진수이며 선택적인 LF/CRLF 끝줄만 허용합니다. 파일 없음·권한 없음·형식 오류는 고정 코드와 한국어 안내로 실패합니다. 오류를 해결하려고 서버를 자동 수정하거나 관리자 프로세스를 시작하지 않습니다.

키 값은 SSH 명령 인수, 화면, 로그, 설정 JSON, Git, 클립보드에 넣지 않습니다. 검증한 바이트를 메모리의 짧은 수명 객체로만 전달하고 기존 로그인 API가 성공하면 즉시 지웁니다. 로그인 요청은 기존 SSH `-W 127.0.0.1:3100` 통로를 사용하며 관리자 포트를 외부에 열지 않습니다. Host·Origin·쿠키 인증을 그대로 적용합니다. 로그인 외에는 허용한 GET 상태/제보 목록/제보 상세만 가능합니다. 운영 변경 API는 계속 차단합니다.

제보 목록은 기존 API의 최대 200개 범위를 표시하며 상세·연결 질문·답변은 항목을 선택할 때 읽습니다. 실제 사용자 자료와 쿠키는 메모리에만 두고 자동 파일 저장/내보내기/외부 전송을 하지 않습니다. 화면 로그에는 고정 작업명·오류 코드만 남깁니다. 이전 `client-admin-response` 제보 객체 형식 수정도 유지합니다.

## 실패·세션 만료·연결 복구

- 네트워크·관리자 미실행 등 일시적 오류는 최대 2회, 사이 간격 5초로 시도합니다. 한 번의 연결 시도 전체는 최대 60초, 키 읽기는 최대 20초이며 각 HTTP/SSH 조회에도 기존 제한을 적용합니다.
- SSH 인증·호스트 키·키 파일/형식 오류는 즉시 중단합니다. 서버 키가 로그인 직전에 바뀐 경우를 위해 관리자 인증 실패만 한 번 다시 읽을 수 있습니다. 민감한 stderr 원문은 표시하지 않습니다.
- 실패해도 앱은 유지됩니다. 재시도를 소진하면 타이머 재접속을 멈추고 **연결 복구** 또는 다음 앱 실행을 기다립니다. 무한 재시도하지 않습니다.
- 자동 연결된 세션이 만료되거나 조회에서 무효화되면 30초 주기의 로컬 점검에서 같은 SSH 인증으로 재연결합니다. 연결 시도 시작 간 최소 1분 간격을 두며, 한 복구 주기에도 같은 2회 제한을 적용합니다. 서버 세션 8시간과 별개로 기존 클라이언트 쿠키 수명은 최대 10분입니다.
- 연결 해제/취소는 현재 연결과 자동 복구를 중단합니다. 설정/대상 변경은 이전 세션·화면 자료를 지우고 이전 비동기 응답을 버립니다. 새 대상은 저장 후 연결 복구로 연결합니다. 앱 종료는 작업과 자식 프로세스를 취소합니다.

## DPAPI 호환성과 보안 한계

기존 DPAPI 파일과 삭제 기능은 유지하며 ‘기존 DPAPI / 수동 인증 (호환용)’을 펼쳐 사용할 수 있습니다. 자동 SSH 경로는 DPAPI 키를 읽거나 새로 저장하지 않고, 이전 자동 시작 옵션도 요구하지 않습니다. 저장된 로그인 정보 삭제는 기존 로컬 DPAPI 정보를 삭제하고 현재 세션을 끊습니다. 저장된 SSH 설정은 남으므로 다음 앱 실행에서는 고정 서버 파일로 다시 자동 인증할 수 있습니다. 자동 SSH 연결을 원하지 않으면 저장된 SSH 설정을 해당 사용자 프로필에서 별도로 제거해야 합니다. DPAPI의 보호 범위는 [이전 안내](AUTOLOGIN.md)를 따릅니다.

현재 서버 키는 **전체 관리자 권한**을 가집니다. 읽기 전용 제한은 이 클라이언트의 요청 허용 목록이며 서버 측 권한을 축소한 것이 아닙니다. SSH 계정은 이 파일을 읽을 권한도 갖습니다. 같은 Windows 사용자로 실행되는 악성 프로그램·관리자/시스템 권한·프로세스 덤프·디버거는 메모리 비밀과 조회한 사용자 자료에 접근할 수 있습니다. .NET 로그인 직렬화에 필요한 문자열/런타임 복사본의 완전한 소거는 보장하지 않습니다. 개인 사용이라는 이유로 이 위험이 사라지지 않습니다. PC 계정과 SSH 키를 보호해야 합니다.

`IManagerKeySource`와 기존 `IRemoteAdminReader`를 분리했으므로 향후 서버 측 읽기 전용 키/인증이 제공되면 별도 구현으로 교체할 수 있습니다. 현재 서버에 그런 권한이 이미 구현됐다고 가정하지 않습니다.

## 검증 범위와 사용자 PC 확인

실제 Azure, 운영 키·DB·사용자 기록에는 개발/CI에서 접근하지 않습니다. 합성 키와 모의 서버로 고정 명령·OpenSSH 성공/실패·기존 v0.1.7 인증 라우터·오류 분류·제한된 재시도를 검사합니다. Windows WPF 모의 시험은 저장된 SSH만 있는 첫 실행/재실행·세션 만료·인증 실패·관리자 미실행·복구 버튼·제보 상세·운영 변경 차단을 확인합니다. 기존 DPAPI/카드/번역/관리자 회귀도 유지합니다.

Windows Server CI 결과는 [최신 보고서](../artifacts/control-center-zero-input-2026-11-02/README.md)에 기록합니다. 실제 Windows 10 PC에서는 기존 SSH 설정으로 EXE 실행 → 상태/AI/제보 목록 자동 표시 → 상세 조회 → 재실행을 확인하세요. 네트워크 차단/복구 후 연결 복구와 세션 만료 후 재인증도 확인 대상입니다. 운영 관리자 프로세스가 이미 실행 중이어야 합니다. 미실행이면 이 앱에서 시작하지 말고 별도 운영 승인 절차를 따르세요. 구형 관리자 신규 시작의 자동 수집기 부수효과는 [4차 안내](PHASE4.md)에 기록되어 있습니다.

v0.1.7 소스, 운영 데이터/키, 서버 설정/서비스, 활성 카드 자료와 배포를 변경하지 않습니다. main 병합·실제 Riot/OpenAI 호출도 실행하지 않습니다. 이 문서는 평문 Markdown으로 보존하며 사용자 바탕화면에 클라우드에서 직접 저장했다고 주장하지 않습니다.
