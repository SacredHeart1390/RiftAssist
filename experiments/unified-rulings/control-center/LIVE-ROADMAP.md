# 확정 라이브 로드맵과 브랜치/태그

2026-11-09 한국. 순서: **v017 → 기존 카드 포함 v020 → v02n 라이브 개선 → Riot 허가 후 v030 공식 API 카드 연동 개발 → 최신 v02n + API 결과의 v040 통합 → v100 정식/SEO**. 이전 문서의 v03n 개발 차수 규칙은 보존하되 현재 출시 우선순위보다 앞세우지 않는다. 이번 작업에서는 새 branch/tag 생성·main 병합·develop 변경·미래 버전 코드를 실행하지 않는다.

## 지금: v0.2.0

release/v0.2.0에서 최소 공개 기능·검증된 수동 교체·백업/복귀만 마무리한다. feature/riot-api-v0.2와 Draft PR1, main, develop/v0.3.0은 보존한다. Control Center 자동 배포 UI나 permanent broker는 출시 gate가 아니다. 필요한 읽기 조사와 실제 운영 변경 승인은 구분한다.

## 출시 후: v0.2.n은 실제 라이브 패치

첫 승인된 출시 commit에 v0.2.0 tag를 만들고 배포 package/manifest/CI/직전 버전·백업 operation ID를 기록한다(이번에는 생성하지 않음). 첫 출시 후 release/v0.2.0은 초기 기준으로 보존하고, 승인받아 그 tag에서 **release/v0.2** 유지보수 branch를 준비하는 전략을 권장한다. 작은 작업은 fix/v0.2.1-설명 같은 작업 branch → release/v0.2 대상 PR → 검토/승인 → v0.2.1 tag/승인된 라이브 교체 순이다. main은 별도 승인 없이는 병합하지 않는다. PR1은 기존 통합 개발 이력으로 유지하고 패치 PR과 혼합하지 않는다.

관련 피드백2~3개를 묶어 정확도·근거·검색/용어·UI·응답 속도·제보/관리 편의성을 고친다. 매 차수 완료 후 v021/v022/...로 올리고 실제 해당 오류 재현·회귀·백업/복귀를 검증한다. 동작을 바꾸기 전에 재현 자료를 개인정보 제거 후 보관하며 실제 사용자 제보를 외부 AI에 무단 전송하지 않는다. 키/DB/사용자 내용은 Git/CI artifact에 넣지 않는다.

배포는 같은 수동 절차/검증/SQLite vault·독립 restore·기존 manager 인증/동일 systemd·Caddy를 재사용한다. 원본·새 기록을 보존하고 schema 변경 없는 패치를 우선한다. 현재 교체 엔진은 **v017→v020 초기 교체에 특화**되어 있어 v021 이후를 이미 지원한다고 주장하지 않는다. 첫 패치에서 previous-release receipt를 최초65개 기준 대신 직전 검증 package/태그로 받을 수 있도록 기존 모듈을 매개변수화하고 시험한다. 전체 시스템을 다시 만들거나 새로운 배포 체계를 요구하지 않는다. DB 역방향 덮어쓰기·무검증 migration은 하지 않는다. 버전/쿠키/데이터 family 변경은 따로 검토한다.

## Riot 허가 후: v0.3.0 개발 → v0.4.0 통합

v030에서 공식 API 카드 연동을 개발·검증한 뒤, 그때 실제 라이브인 **최신 안정 v0.2.n tag**에서 integration/v0.4.0을 시작한다. develop/v0.3.0 전체를 덮어쓰지 않고 adapter/공식 ID·언어 매핑/수집·정오표/번역 후보·검토 기능만 선택 통합한다. 라이브 정확도/사용성 개선과 운영 기록을 먼저 보존한다. 데이터/이미지/영어·한국어·비공식 번역·미발매 공개/외부 AI 입력 허가를 API 승인과 별도로 확인한다. 후보 생성·전체 회귀/동기화 실패·복구/ID 호환성을 검증하고 별도 운영 승인 후에만 전환한다. 자동 라이브 교체는 없다.

## v1.0.0 정식 공개

카드/언어·규칙/정오표·상호작용·동기화 복구·관리·보안/개인정보·실제 피드백을 반복 검증하여 통합 결과를 안정화한다. 충분한 실제 운용 증거를 갖추면 v100 정식 공개를 승인받는다. Google Search Console 등록/도메인 소유권, sitemap/robots/메타데이터/색인 허용, 접근성/모바일, 공개 소개·홍보를 이 시점에 수행한다. v020의 noindex는 의도적으로 해제·검증해야 하며 버전 이름만으로 자동 공개하지 않는다. 기본 법적 고지/개인정보·권리 검사는 v020부터 필수이고 v100에서 재확인/완성한다.
