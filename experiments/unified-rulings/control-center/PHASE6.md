# Control Center 6차 · 제보 분석·Codex 수정 요청

2026-11-02 · feature/riot-api-v0.2 · 기존 Draft PR #1

## 현재 사용할 수 있는 범위

질문·오류 제보 목록에서 운영 API/합성 개발 API/로컬 수동 제보를 선택하고 **AI로 오류 분석**을 누릅니다. 현재 분석기는 **로컬 예비 분석이며 실제 LLM을 호출하지 않습니다**. 개인정보를 제거한 입력을 직접 검토·편집하고 로컬 처리·암호화 저장을 승인합니다. 원래 질문·실제 답변/근거·지적 오류·기대 판정·관리자 메모·관련 카드 식별자/과거 규칙 근거·발생 버전을 다룹니다. 긴 필드는 생략 표시를 붙여 제한합니다. 기억 기반 요약을 유지합니다.

분석 창은 재현 여부, 관찰/근거, 원인 추정과 분류, 올바른 판정 후보, 코드/데이터/프롬프트 후보, 신뢰도·미확인 사항, v0.1.7 긴급 후보와 v0.2.0 개선 후보를 구분합니다. 공식 자료가 연결되지 않은 상태에서는 **재현 미실행·원인 미확정·정답 보류**로 표시합니다. 실제 서비스 오류를 찾아 고쳤다거나 공식 판정을 생성했다고 주장하지 않습니다. AI의 실제 의미 분석/판정은 외부 제공자와 승인된 현행 근거 연결의 후속 작업입니다.

기존 `retrieval.js`의 질문 분석/검색, `cards.js` 카드 스키마, `answer-policy.js` 버전을 검증된 번들에서 Node로 실행합니다. 서버/DB/수집기/외부 API를 시작하지 않습니다. 현재 공식 규칙·카드 원문은 연결하지 않고 빈 근거 인덱스로 검색 누락 메타데이터를 확인합니다. 과거 답변의 근거는 ‘제보에 기록된 자료’이며 현행 공식 자료로 인증하지 않습니다. 권한 미확인 리프트나루 카드 원문을 가져오거나 외부 모델에 넘기지 않습니다. 카드 이름/ID/authority와 규칙 ID/버전·제한된 발췌만 제보에서 투영합니다.

운영 v0.1.7에는 정수 revision과 발생 앱 버전이 없습니다. 허용한 분석 필드·상태·updated의 해시를 API revision으로 사용하고 앱 버전은 미기록으로 표시합니다. knowledge/card 버전과 앱 버전을 혼동하지 않습니다. 수동 제보는 기존 revision을 사용합니다. 분석/복사/모의 작업 전에 최신 제보를 다시 읽고 revision이 바뀌면 거절합니다. 이전 분석 이력은 보존하며 현재/이전 입력을 구분합니다.

## Codex 요청과 모의 수정

분석 후 **Codex에 수정 요청 · 프롬프트 복사**를 누릅니다. v020-improvement 또는 v017-emergency를 선택하고 완성된 작업 프롬프트를 미리보기에서 확인·수정한 뒤 복사를 승인합니다. 기존 Codex 클라우드 채팅에 직접 붙여넣을 수 있습니다. 이 경로에는 CLI 설치나 새 API 키가 필요하지 않습니다. 해당 채팅 서비스의 로그인/이용 권한/사용량 제한은 별도입니다.

프롬프트에는 근거/추정 구분, 비신뢰 제보를 명령으로 취급하지 않기, 독립 개발 공간, 재현/회귀 테스트, diff/위험 검토, v0.1.7 운영 코드·DB·키 보호, Azure/유료 API·main 병합·자동 Push/PR 금지와 별도 승인 조건을 넣습니다. v0.1.7 긴급 후보는 운영 파일 편집이 아닌 재현/수정 제안 보고서로 분리합니다. 실제 원격 실행·클라우드 작업 상태/비용/결과 조회는 제공하지 않습니다. ‘복사 완료’는 작업 시작/성공을 뜻하지 않습니다.

**합성 수정·테스트 흐름 실행**은 별도의 예/아니요 확인 후 앱 소유 폴더에 고정된 모의 JS 오류를 만들고 수정합니다. 실제 Node로 합성 재현/회귀 2건을 실행해 수정 전 실패·수정 후 통과를 확인합니다. 표시하는 unified diff는 그 고정 합성 파일의 전후 비교이며 실제 RiftAssist Git 저장소를 검사한 diff가 아닙니다. 실제 제보 입력·프롬프트·비밀정보는 작업 폴더에 쓰지 않습니다. 테스트 성공은 해당 실제 제보의 해결이나 프로덕션 회귀 통과를 증명하지 않습니다.

작업은 고유 ID와 lane, queued/running/testing/ready-for-review/failed/cancelled/uncertain 상태, 이벤트·파일·테스트·diff·위험·비용 구분을 보존합니다. 동일 분석/내용/lane의 작업을 자동 중복 실행하지 않습니다. 실패/취소/연결 끊김도 자동 재시도하지 않습니다. 재열기 시 활동 잠금이 없는 실행 중/복사 준비 상태는 미확정으로 바꾸고 실행을 재개하지 않습니다. 다른 창/프로세스의 활동 잠금이 있으면 진행 중 상태를 보존합니다. 현재는 동일 내용의 실패 작업 재시도/재개 UI도 제공하지 않습니다. 변경된 내용의 새 분석으로 새 후보를 만들거나 후속 복구 기능을 기다려야 합니다.

GitHub 버튼은 비활성입니다. 모의 테스트 통과 후 ‘모의 PR 검토 후보’를 볼 수 있지만 실제 브랜치/커밋/PR은 만들지 않습니다. 게시 계약은 사용자 승인을 작업ID·lane·diff·테스트 해시에 연결하도록 준비했으며 승인 값이 있어도 현재 실제 게시는 차단합니다. 클라우드 채팅에서 사용자가 별도로 수행한 중복 수정/커밋/PR은 앱이 추적하거나 차단할 수 없습니다. 이 앱의 작업 ID/승인 경계는 자동 실행 경로에 대한 설계이며 클라우드 연동 완료를 뜻하지 않습니다.

## 연동 방식·인증·비용 조사

2026-11-02 공식 문서 기준입니다. 이번에는 CLI/SDK/App Server를 설치·로그인·실행하거나 인증 파일을 열지 않았습니다. 개발 환경에 Codex 실행 경로가 있음을 확인한 것만으로 사용자 Windows PC의 설치/인증 상태를 가정하지 않습니다.

| 방식 | 선택과 필요한 후속 작업 |
| --- | --- |
| Codex CLI `exec --json --ephemeral` | 단일 수정 요청의 우선 연동 계약. stdin 프롬프트·JSONL 이벤트 상태 파서를 준비했습니다. 실제 프로세스 어댑터는 비활성/미구현이며 버전 고정·환경/권한 격리 후 연결 필요 |
| 공식 TypeScript SDK | Node18+에서 로컬 thread 시작/재개 가능. 번들 Node는 있으나 SDK를 설치하거나 실행하지 않음. 현재 .NET 단일 작업에는 필수 의존성으로 추가하지 않음 |
| App Server | stdio JSONL/RPC로 인증/승인/스트리밍을 다루는 깊은 네이티브 연동에 적합. 초기화·thread/turn/승인/인증 수명주기 구현은 후속 확장. 공개 포트는 열지 않음 |
| 프롬프트 복사 | 현재 실제 사용 가능한 수동 경로. 자동 상태 조회/코드 수정/테스트/PR 연동 없음 |

공식 CLI는 저장된 CLI 인증을 재사용할 수 있습니다. ChatGPT 로그인 캐시는 CLI/IDE 사이에서 공유되지만 브라우저의 웹 로그인만으로 CLI 인증이 준비되지는 않습니다. 향후 사용자 PC에서 공식 CLI 설치와 `codex login`/`codex login status`를 사용자 주도로 확인해야 합니다. 앱이 auth.json/토큰을 복사하거나 설정/인수/로그에 넣지 않습니다. SDK/CLI/App Server가 존재한다는 이유로 이 앱이 웹 계정의 쿠키를 가져오지 않습니다.

ChatGPT 인증은 해당 플랜·워크스페이스의 Codex 이용 권한/한도를 사용합니다. API 키 인증은 별도 Platform 사용량 과금이며 기존 RiftAssist 서비스 키를 재사용하지 않습니다. 정확한 사용자 플랜·잔여량·추가 결제 필요 여부는 확인하지 않았고 무료/무제한을 보장하지 않습니다. 현재 외부 호출은 0이며 키 입력·자동 결제/추가 크레딧 구매 기능이 없습니다.

CLI 설치·Windows10 호환성·샌드박스/네트워크 정책·기업 계정 정책은 실제 사용자 PC에서 별도 검증해야 합니다. 향후 계획 인수의 workspace-write는 단독으로 비밀 읽기/네트워크/Push를 완전히 차단하는 보장이 아닙니다. 실제 연동에는 저장소 allowlist 복제·운영 자료 제외·별도 자격증명 없는 프로세스·출력/쓰기 경로 검사·네트워크 제한과 승인 처리의 실증이 필요합니다. `--ephemeral`도 모든 OS/CLI 캐시/로그의 완전한 무기록을 뜻하지 않습니다. 위험한 full-access/승인 무력화나 브라우저 세션 탈취는 사용하지 않습니다.

근거: [비대화형 CLI·이벤트·인증 재사용](https://developers.openai.com/codex/noninteractive), [인증과 과금 방식](https://developers.openai.com/codex/auth), [SDK](https://developers.openai.com/codex/sdk), [App Server](https://developers.openai.com/codex/app-server), [Windows 샌드박스](https://developers.openai.com/codex/windows).

## 개인정보·보관

별도 `%LOCALAPPDATA%\RiftAssist\ControlCenter\IncidentAnalysis\{analysisId}.dpapi`에 입력 미리보기·결과·작업 이력을 저장합니다. 기존 ManualReports와 별개이며 전용 목적 entropy의 현재 사용자 DPAPI·사용자 ACL·잠금·revision CAS·원자 교체를 사용합니다. 제보 ID/revision은 암호문 안에 연결합니다. 원래 제보 전체/쿠키/trace를 통째로 직렬화하지 않습니다.

공백이 포함된 Authorization/Bearer·다중 Cookie 헤더는 줄 전체를 제거하며 키/PEM·알려진 API 토큰·64자리 16진수·쿠키/세션/요청/인증 필드·이메일/전화·UUID/IP·URL/개인 경로/DB 파일 표기를 가능한 범위에서 제거합니다. 이름, 간접 식별 정보, 임의 형식/인코딩의 비밀은 놓칠 수 있습니다. 사용자 검토는 필수이며 자동 제거를 비식별화 보장으로 간주하지 않습니다. 외부 전송 승인은 대상/내용 해시에 바인딩하고 내용 변경 시 다시 받아야 합니다. 현재 외부 AI/Codex 전송은 승인 객체가 있어도 차단합니다.

클립보드에는 검토 후 비밀 제거된 프롬프트만 명시적 승인으로 복사합니다. Windows 클립보드 기록/동기화·다른 프로그램 접근 위험은 남습니다. 사용 후 ‘복사한 프롬프트 지우기’를 누르면 이 창이 복사한 내용과 일치할 때만 지웁니다. OS 과거 기록까지 삭제한 것은 아닙니다. 같은 내용의 재복사는 새 작업을 만들지 않고 성공했던 작업 ID를 재사용합니다. 실패/미확정 복사는 자동 재시도하지 않습니다. 준비 상태를 먼저 기록하고 성공/실패를 구분합니다. 원문/프롬프트 임시 평문 파일은 만들지 않습니다.

작업 폴더 `IncidentAnalysis/Workspaces/{jobId}`에는 고유 marker와 고정 합성 코드/테스트만 있으며 입력·실제 사용자 내용은 없습니다. 자동 삭제는 하지 않습니다. 최대300개 분석/분석당20개 작업/파일256KiB 제한이며 초과 시 기존 자료를 보존하고 오류를 표시합니다. 자동 만료·백업/삭제 UI·암호문 마이그레이션은 후속입니다. 같은 사용자/관리자·메모리 접근 및 프로필/DPAPI 키 유실 위험은 기존 DPAPI와 같습니다. 문자열 완전 소거를 보장하지 않습니다.

비용은 analysis-local, codex-mock, codex-manual bucket으로 서비스 API 사용량과 분리합니다. 외부 호출 수는 현재0이며 토큰/금액은 미산정 또는 외부 미연동으로 기록합니다. 클립보드에 복사한 뒤 외부 채팅에서 쓴 비용을 앱이 0원으로 계산하지 않습니다.

## 실제 자동 수정 활성화 조건과 다음 단계

1. 운영자가 사용할 제공자/CLI·플랜·비용·전송 범위를 선택하고 **실제 외부 분석/수정 활성화를 별도 승인**해야 합니다. 이 패키지에는 설정으로 활성화하는 스위치가 없습니다.
2. 허가된 현행 공식 규칙·카드/번역을 버전별로 연결하고 분석 응답 스키마·인용/원인/신뢰도 검증, 실제 오류 재현/회귀 실행기를 구현해야 합니다.
3. CLI 버전/인증 상태·격리 복제·네트워크/자격증명/명령/출력 경계·타임아웃/취소/재시작 미확정 처리를 실제 Windows10에서 검증해야 합니다. 현재 실제 프로세스 실행·클라우드 thread 연결·재개·결과 가져오기는 미구현입니다.
4. 실제 수정 결과를 별도로 검토한 뒤 해당 diff/테스트·작업 대상에 바인딩한 **GitHub 반영 승인**을 받아야 합니다. 이 승인과 Azure 배포/운영 변경 승인은 별개입니다. AI 완료 이벤트나 테스트 통과만으로 정답·배포를 승인하지 않습니다.

v0.1.7 운영 코드·DB·키, 공유 active.json·카드 자료와 Azure 서버는 변경하지 않습니다. 실제 사용자 제보로 자동 테스트하지 않으며 실제 AI/Codex·유료 API도 호출하지 않습니다. main 병합·자동 운영 Push/Merge·새 PR 중복 생성은 없습니다. 기존 자동 SSH/설정·관리자 읽기/모의 제어·수동 제보·아이콘·ZIP 최상위 EXE와 Windows10 x64 대상을 유지합니다.
