# 관리자 로그인 기억·자동 연결·제보 상세 수정

현재 실행 동작은 [SSH 기반 관리자 자동 인증](ZERO-INPUT.md)이 우선합니다. 저장된 SSH 설정이 있으면 키 입력/버튼 없이 시작 시 상태·인증·AI 집계·제보 목록을 조회합니다. 이전 DPAPI 선택 저장은 호환용으로 유지합니다. [최신 검증 보고서](../artifacts/control-center-zero-input-2026-11-02/README.md). 아래 이전 자동 연결 조건은 당시 버전의 기록입니다.

2026-11-02 · v0.2.0 / 기존 feature/riot-api-v0.2와 Draft PR #1.

## 사용 방법

1. 기존 Azure SSH 설정을 확인하고 관리자 키를 최초 한 번 입력합니다. **이 컴퓨터에 로그인 정보 기억**을 선택하면 로그인 성공 후 Windows 사용자 범위 DPAPI로 암호화해 보관합니다. 기본값은 선택 안 함입니다.
2. 다음 실행부터 **저장된 정보로 연결**, 또는 키 입력을 비운 **관리자 읽기 연결**로 인증할 수 있습니다. PowerShell·클립보드 작업을 다시 할 필요가 없습니다.
3. **시작할 때 자동 연결**도 직접 선택한 경우에만 앱 시작 시 같은 대상에 한 번 로그인하고 상태/AI 집계를 읽습니다. 기본값은 꺼짐입니다. 첫 로그인 전의 선택은 로그인 성공 후 저장하고, 이미 저장된 키가 있으면 체크 변경을 즉시 저장합니다. Windows 로그인/부팅 시 앱을 실행하는 서비스·예약 작업·Run 레지스트리는 추가하지 않습니다.
4. 자동 연결은 제보 목록/상세를 자동으로 읽지 않습니다. 사용자가 목록 버튼·행을 선택할 때만 읽습니다. 실패나 화면 재진입 때문에 자동 재시도하지 않습니다. 세션 만료 후에는 저장된 정보로 다시 연결할 수 있습니다.
5. **저장된 로그인 정보 삭제**는 현재 SSH 대상의 암호화 파일과 자동 연결을 제거하고 현재 인증 세션/화면 자료도 정리합니다. ‘로그인 정보 기억’ 체크 해제도 동일하게 동작합니다. 다른 대상의 정보는 임의 삭제하지 않습니다.
6. 저장된 키의 인증이 거절되면 현재 대상의 저장 정보를 삭제하고 자동 연결을 끕니다. 새 키를 입력해 다시 등록합니다. 네트워크/SSH 오류는 저장 키를 보존하되 자동 연결을 해제합니다. 저장/복호화/권한 오류는 고정 오류 코드로 알리고 평문 저장으로 우회하지 않습니다.

일반 조회에는 확인창/사유 입력을 추가하지 않습니다. 기존 운영 시작·중지·AI/한도/제보 변경·배포는 계속 차단하며 로그인 POST와 허용한 GET만 사용합니다. 기존 SSH 키 경로/agent·known_hosts·엄격한 호스트 키 검증을 재사용합니다.

## 보관 위치와 업데이트

EXE 폴더가 아닌 현재 사용자의 고정 경로를 사용합니다.

- `%LOCALAPPDATA%\RiftAssist\ControlCenter\Credentials\{profileId}.dpapi`: DPAPI 암호문만 저장. 평문 관리자 키/쿠키/SSH 개인키 내용을 기록하지 않습니다.
- `%LOCALAPPDATA%\RiftAssist\ControlCenter\LoginOptions\{profileId}.local.json`: version, profileId, scheme, remember, autoConnect 5개 메타데이터만 기록합니다. 기본 자동 연결은 false입니다.
- 기존 SSH 설정은 기존 Settings\ssh.local.json의 6개 메타데이터를 유지합니다.

대상 ID는 SSH host/port/user·HTTPS origin·인증 방식 ID를 정규화한 SHA256입니다. EXE 위치·ZIP 이름·빌드 버전·SSH 개인키 파일 위치는 ID에 포함하지 않습니다. 동일 컴퓨터/동일 Windows 사용자 프로필에서 새 ZIP을 다른 폴더에 풀어도 기존 정보가 유지됩니다. 다른 서버/계정/포트/사이트/인증 방식에는 자동 재사용하지 않습니다. 인증정보가 없거나 옵션이 손상/일치하지 않으면 자동 연결을 실행하지 않습니다. 옵션 읽기/화면 초기화만으로 암호화된 키를 복호화하지 않습니다.

선택 저장 후 기존 사용자 프로필을 삭제/재설치하거나 계정·DPAPI 키가 손실되면 새 관리자 키 입력이 필요할 수 있습니다. 암호문을 새 PC에 복사하는 것만으로 재사용을 보장하지 않습니다. 앱 업데이트 때 Credentials/LoginOptions 폴더를 새 ZIP에 넣거나 Git에 올리지 않습니다.

## Windows 보호 범위와 남는 위험

- Windows CryptProtectData/CryptUnprotectData의 **현재 사용자 범위**를 사용하며 machine 범위 플래그는 사용하지 않습니다. UI_FORBIDDEN으로 OS 보호 실패를 대화 상자/평문 우회로 처리하지 않습니다. 프로필·인증 방식에 바인딩한 추가 entropy로 잘못 복사한 다른 대상의 암호문을 거절합니다.
- 저장 디렉터리의 상속을 끄고 현재 Windows 사용자 SID에만 접근 규칙을 부여합니다. 디스크에는 암호문만 쓰며 임시 파일도 같은 보호 디렉터리에 생성해 원자 교체합니다. 로그인 후 쿠키는 계속 메모리 전용/최대 10분이며 디스크에 저장하지 않습니다.
- 이 보호는 **같은 Windows 사용자 권한으로 실행되는 악성 프로그램, 계정 탈취, 관리자/시스템 권한, 프로세스 메모리 접근**을 막는 독립적인 비밀 장치가 아닙니다. Windows Hello/PIN 재확인이나 하드웨어 기반 금고를 구현한 것은 아닙니다. 현재 사용자 컨텍스트의 프로그램은 해당 암호문과 entropy를 읽어 복호화를 시도할 수 있습니다.
- DPAPI/Windows 프로필 백업·도메인/로밍 정책은 OS 관리 범위입니다. 저장 파일 삭제가 백업/디스크의 모든 과거 사본을 영구 소거하거나 서버의 기존 8시간 쿠키 세션을 철회한다는 뜻은 아닙니다. 서버 logout/revoke API는 없습니다.
- 암호화/복호화용 바이트 버퍼와 네이티브 버퍼는 사용 후 지우지만 PasswordBox에서 넘겨받거나 복호화한 .NET 문자열의 메모리 전체 소거를 보장하지 않습니다. 키/쿠키는 로그·JSON 설정·Git·실행 인수에 기록하지 않습니다.
- 기존 관리자 키는 서버에서 **전체 관리자 권한**을 가집니다. 이번 기능도 클라이언트 읽기 허용 목록이며 서버 측 읽기 전용 권한으로 바꾼 것이 아닙니다. 개인 사용/비공개 배포도 이 위험을 제거하지 않습니다.

`IAdminCredentialVault`, `SavedAdminLogin`의 인증 callback, 인증 방식별 reference/entropy를 분리했습니다. 현재 방식은 manager-key-v1이며 향후 서버 측 읽기 전용 인증이 제공되면 별도 reader/인증 방식 ID로 연결할 수 있습니다. 서로 다른 방식의 키는 같은 저장 슬롯을 공유하지 않습니다. 서버 read scope/API가 이미 구현됐다고 가정하지 않습니다.

## 제보 상세 client-admin-response 수정

사용자가 보고한 오류와 코드의 실제 응답 계약을 비교했습니다. 기존 v0.1.7 operations-store.js의 report()는 content를 `{description, expected, tags, language}` 객체로 저장하고 reportDetail()이 복호화한 객체를 반환합니다. 이전 4차 클라이언트와 모의 fixture가 content를 문자열로 가정해 정상 운영 응답도 검증 오류로 거절했습니다.

클라이언트는 실제 객체의 설명·기대 답변·태그를 표시하고 연결 질문/판정/근거·처리 이력을 유지합니다. 과거 합성 문자열과 없는 스냅샷도 호환합니다. 알 수 없는 필드/trace/자격증명은 통째로 표시하지 않으며 길이·태그·전체 응답 크기 검증은 유지합니다. 테스트 fixture도 실제 객체 형식으로 고쳤습니다. 운영 v0.1.7이나 실제 제보/DB를 수정하지 않았습니다. 실제 사용자 자료를 테스트에 사용하지 않았으며 새 패키지의 실제 조회 결과는 사용자 확인 대상입니다.

## 검증·운영 경계

합성 키·메모리 vault로 기본 저장/자동 연결 꺼짐, 선택 저장, 성공 후 저장, 시작 1회, 업데이트 재사용, 삭제·키 변경·네트워크 실패, JSON에 비밀 없음·프로필/방식 분리를 검사합니다. Windows CI에서는 임시 합성 키로 **실제 DPAPI 암호화/재읽기·암호문 평문 부재·entropy 불일치·현재 사용자 ACL·삭제**를 검사합니다. WPF에서도 옵션/수동 저장 연결/시작 1회/삭제를 확인하며 기존 카드·SSH·관리자·제보 회귀를 유지합니다.

이번 개발자는 실제 Azure/운영 관리자 조회, 서비스/설정 변경·시작/중지·재시작·배포, 운영 DB/암호화 키 접근·수정, 유료 API, main 병합을 실행하지 않습니다. 기존 관리자 신규 시작의 구형 수집기 자동 기동 위험과 별도 승인 조건은 PHASE4.md를 따릅니다. 이 앱에서 관리자 자동 연결을 선택하는 것은 그 사용자가 요청한 읽기 연결만 의미합니다.
