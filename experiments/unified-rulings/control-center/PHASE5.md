# Control Center 5차 · 관리자 제어 준비와 로컬 수동 제보

2026-11-02 · feature/riot-api-v0.2 · 기존 Draft PR #1 · 운영 변경 비활성

## 사용할 수 있는 기능

기존 자동 SSH 상태 조회·고정 manager.key 인증·AI/한도/제보 조회, 카드/번역 검토, RiftAssist 아이콘과 ZIP 최상위 EXE를 유지합니다. 새 패키지를 새 폴더에 전부 풀고 EXE를 실행합니다. 동일 Windows 사용자 LocalAppData의 기존 SSH/DPAPI 설정을 유지하면 다시 설정할 필요가 없습니다.

‘운영·개발 관리자 → 질문·오류 제보’에서 **수동 제보 등록**을 누릅니다. 제목, 6개 분류, 질문, 실제 AI 답변, 지적한 오류, 기대 판정, 공식 규칙 근거, 발생 버전, 4개 접수 경로, 처리 상태·관리자 메모를 입력할 수 있습니다. 정확한 원문이 없으면 **기억에 근거한 요약**을 선택하세요. 빈 질문/답변을 임의로 보완하지 않으며 규칙 근거도 관리자 입력으로 구분합니다. 제목과 오류 내용은 필수입니다.

목록의 출처는 **Azure · 운영 / 합성 · 개발 / 수동 · 로컬**로 구분됩니다. 수동 항목은 ‘선택 수동 제보 수정’으로 상태·메모와 나머지 필드를 편집합니다. Azure API 제보는 이 버전에서 읽기 전용이며 로컬 편집 경로로 가져오지 않습니다. 수동 항목을 기존 서버 제보 수정/합성 내보내기 버튼으로 전송하거나 평문 저장하지 않습니다. 목록 검색은 제목·출처·ID·분류·상태를 포함합니다.

수동 저장은 간단한 예/아니요 확인을 사용하며 조회는 확인창이 없습니다. 사용자에게 감사 사유를 추가로 요구하지 않습니다. Codex 분석용 출처·revision·원문 정확성·본문 DTO만 메모리에서 만들 수 있는 경계를 준비했으며 실제 Codex 연결/자동 수정/배포/자동 파일 내보내기는 없습니다.

## 기존 관리자 API와 제어 경계

v0.1.7 manager.js/operations-store.js를 읽어 계약을 확인했으며 수정하지 않았습니다.

| 기능 | 기존 API | 구현·검증 방식 |
| --- | --- | --- |
| 앱 시작/중지 | POST /api/start, /api/stop, 빈 객체 | 합성 환경에서 변경 후 GET /api/status의 appRunning 확인 |
| 재시작 | 전용 API 없음 | stop → 상태에서 중지 확인 → start → 실행 확인. 중간 실패 시 시작/재전송하지 않음 |
| AI 전환 | POST /api/ai, enabled 불리언 | 상태의 stats.aiEnabled 재확인 |
| 한도 변경 | POST /api/limits, 기존8개 정수 필드 | 1–1000, concurrent1–3 검증 및 모든 값 재확인 |
| 제보 상태·메모 | POST /api/reports/{UUID}, status/note | 기존8개 상태·메모3000자 제한, 상세의 상태/메모 이력 재확인. 메모만 추가할 때 현재 상태 유지 |

합성 제어는 기존 앱 소유 개발 폴더·Node 서명 인터페이스·관리자 로그인/쿠키·권한 검사·nonce·감사 기록을 재사용합니다. 여기에 C# 변경 계획·직렬 실행·확인·사후 검증을 추가했습니다. 일반 제어는 예/아니요로 확인하며 중지/재시작의 사이트·진행 요청 영향과 시작 경로의 모니터 부수효과를 표시합니다. 일반 작업의 사유는 작업명·격리 대상/제보ID로 자동 생성하며 메모/질문/답변을 별도 작업 로그에 복사하지 않습니다.

변경 실패, 인증 실패, 연결 단절, 응답 손실, 결과 불일치는 모두 결과 확인 필요로 남기고 **변경을 자동 재전송하지 않습니다**. 현재 상태 새로고침 전에는 추가 변경을 막습니다. 중지 후 시작에 실패한 재시작도 자동 복구하지 않습니다. 개발 백엔드의 미확정 감사 기록이 남은 경우에는 새로고침만으로 해당 잠금을 해제하지 않으며 격리 환경의 기록을 별도 점검해야 합니다. 클라이언트 검증 결과는 세션 로그, 실제 개발 API 단계의 감사는 기존 개발 폴더의 journal에 보존됩니다. 이 기록은 운영 서버 감사 로그를 새로 구현한 것이 아닙니다.

**Azure 운영 변경은 UI와 모델, coordinator target 검사, 기존 읽기 전용 HTTP 허용 목록에서 차단합니다.** 원격 쓰기 전송은 이 빌드에 제공하지 않습니다. 숨은 설정·명령 인수·승인 체크박스로 켤 수 없습니다. 실제 SSH/관리자 연결은 기존 읽기 전용 흐름을 유지합니다. 포트3100을 공개하거나 서버에 새 프로그램을 설치하지 않습니다.

## 운영 활성화 전에 필요한 확인·승인

1. 운영자가 실제 systemd 프로세스, manager가 소유한 앱 자식, 3001/3100 포트, 현재 appRelease 설정의 관계를 확인해야 합니다. `/api/start`·`stop`은 systemd 제어 API가 아닙니다. 별도 프로세스로 실행한 라이브 앱을 중지하지 못하거나 중복 실행/포트 충돌을 만들 수 있습니다. `/api/status`의 appRunning과 systemd active도 별개입니다.
2. 시작 경로의 구형 자료 모니터·수집 동작과 hosting 설정/터널 영향을 확인해야 합니다. 기존 관리자를 새로 시작하거나 앱을 시작하면 모니터가 기동할 수 있습니다. 이 개발에서는 이를 실행하거나 운영 v0.1.7 코드를 수정하지 않습니다.
3. 기능별 대상·영향·검증·실패 후 수동 복구 계획을 검토한 뒤 **실제 운영 연결 활성화에 대한 별도 사용자 승인**이 필요합니다. 이후 제한된 SSH 쓰기 어댑터를 구현/검증한 별도 빌드가 필요하며 현재 패키지를 설정만 바꿔 활성화할 수 없습니다. 활성화하더라도 각 변경은 예/아니요 확인을 거칩니다.
4. 기존 API에는 원자적 restart, 요청ID 기반 멱등성/서버 revision 충돌 검사, systemd 제어, 전용 읽기/쓰기 범위 인증키, 통합 운영 변경 감사 API가 없습니다. UI 중복 차단·서명/nonce와 사후 확인은 다른 관리자 클라이언트의 동시 변경을 막지 못합니다. 이 부분은 운영 API 변경의 별도 검토·승인 대상이며 임의 구현/배포하지 않습니다.

현재 키의 서버 전체 관리자 권한과 메모리/동일 Windows 사용자 권한의 위험은 [자동 인증 안내](ZERO-INPUT.md)에 유지합니다. 운영 시작/중지·설정 변경·재시작·설치·배포, main 병합, 운영 DB/키/사용자 기록 접근·변경, 실제 유료 API 호출을 이 개발/CI에서 수행하지 않습니다.

## 수동 제보 보관과 한계

`%LOCALAPPDATA%\RiftAssist\ControlCenter\ManualReports\{UUID}.dpapi`에 **Windows 현재 사용자 DPAPI 암호문**만 저장합니다. 별도 목적 entropy를 사용해 관리자 키 저장소와 구분하고, 디렉터리 ACL은 현재 사용자만 허용합니다. 키 파일·일반 설정 JSON·서버 DB에 제보를 기록하지 않습니다. 앱 업데이트·새 ZIP에도 같은 사용자 프로필의 저장소를 재사용합니다. 실제 운영 제보/질문을 자동으로 이 저장소에 복사하지 않습니다.

등록/수정 시 UUID·revision·작성/수정 시각과 상태·관리자 메모 이력을 암호문 안에 함께 저장합니다. 이전 본문 전체 버전은 보관하지 않습니다. 예상 revision과 파일 잠금으로 오래된 편집·동시 저장을 거절하고, 임시 파일도 암호화 후 원자 교체합니다. 암호화 실패/손상 시 평문 우회나 기존 파일 덮어쓰기를 하지 않습니다. 한 파일 손상 시 목록 오류를 알리며 임의 복구/삭제하지 않습니다. 로컬 오류가 원격 관리자 인증을 해제하지 않도록 분리했습니다.

보호 한도는 최대500개 제보, revision1000 이하, 파일256KiB 이하이며 필드별 길이 제한도 적용합니다. 용량 제한에 도달하면 기존 자료를 지우지 않고 오류를 표시합니다. 자동 삭제·Azure 업로드·평문 내보내기·Codex 전송은 없습니다. 빈 reports.lock은 비밀 없는 잠금 파일입니다.

같은 Windows 사용자로 실행되는 악성 프로그램·관리자 권한·메모리 덤프·계정 탈취에 대한 독립적인 보호는 아닙니다. 화면/메모리에는 복호화된 문자열이 있고 .NET 문자열 소거를 보장하지 않습니다. Windows 프로필/DPAPI 키를 잃으면 복호화할 수 없을 수 있으며 암호문을 다른 PC에 복사해도 사용을 보장하지 않습니다. 별도 내보내기/백업·삭제 정책 UI는 후속 과제입니다. 자동 보존 만료가 없으므로 운영자는 개인정보 최소화·동의/보관 책임을 직접 판단해야 합니다. 실제 사용자 내용은 테스트에 사용하지 않았습니다.

## 게시자 경고

프로젝트 매니페스트는 기존부터 `requestedExecutionLevel=asInvoker`, `uiAccess=false`입니다. 불필요한 관리자 권한 상승을 요구하지 않으므로 수정하지 않았습니다. Windows CI에서 **배포용 EXE의 내장 매니페스트와 Get-AuthenticodeSignature 결과**를 검사합니다. 실행 코드5856e6c의 실제 패키지 EXE는 Windows CI에서 **NotSigned**, 내장 **asInvoker/uiAccess=false**로 확인했습니다. 현재 유료/공인 코드 서명을 추가하지 않았으므로 ‘알 수 없는 게시자’/SmartScreen 경고를 제거했다고 주장하지 않습니다. UAC, SmartScreen, 회사 정책/보안 제품의 경고는 서로 구분해야 하며 실제 경고 종류를 개발자가 사용자 PC에서 확인한 것은 아닙니다.
