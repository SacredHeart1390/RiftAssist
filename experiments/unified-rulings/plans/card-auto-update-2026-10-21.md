# 카드 DB 자동 갱신 설계

상태(2026-10-21 후속): **파일 자동 처리·검사·게시 경로와 제공 JSON 예약 확인 코드를 적용. 원격 카드 수집은 제공 주소 미확보로 미연결.** 공개 앱·관리자·터널 재시작 없이 별도 수집기만 교체했다. 아래 항목은 최초 목표 설계를 포함하며, 실제 범위와 확인 결과는 `../artifacts/card-sync-2026-10-21.md`, 사용법은 `../CARD_UPDATES_KO.md`가 기준이다.

- 적용: 파일 대기열, 형식/누락/변경 비교, 이전 정상본 보존, 자료 게시 충돌 재시도, 기존 활성 규칙·사례와 병합, 관리 상태 표시, 제공 JSON 어댑터와 일정, 로컬 명령으로 일시 중지/재개.
- 미연결: 리프트나루 실제 원격 제공 주소(직접 요청 HTTP429 확인 화면). 다른 형식/API·도메인은 별도 어댑터 조정 필요.
- 후속: 실제 신규 자료의 게시·실패·동시 갱신 검증, 보류 건별 승인 화면, 공식 정오표 자동 대조, 페이지 단위 수집. 이 항목들을 완료된 기능으로 표시하지 않는다.

## 1. 현재 기반과 연결할 곳

- 현재 카드1527판본, 영문 본문1489개. 공백38개는 효과 없음/수집 누락을 아직 구별하지 못했다.
- 기존 가져오기 도구의 legacy `knowledge/cards.json` 수정 문제는 이번에 대기열→활성 `knowledge-releases` 게시 방식으로 전환했다. 옛 가져오기 웹 서버3001은 현재 운영 포트와 겹치므로 시작하지 않도록 안내용으로 바꿨다.
- 새 카드 수집기를 기존 `content-sync`와 자료 게시 절차에 연결한다. 규칙·Q&A·카드 중 바뀐 부분만 새로 준비하고, 나머지는 현재 활성 자료에서 가져온다.

## 2. 공급 경로

### 2026-10-21 안정성 재조사 — 장기 권고, 아직 전환하지 않음

- [Riot 공식 API 목록](https://developer.riotgames.com/apis#riftbound-content-v1/GET_getContent)에 riftbound-content-v1이 있다. [신청 안내](https://developer.riotgames.com/docs/riftbound)에 따라 앱별 키/승인 절차가 필요하다. 기존 OpenAI 키와 별개이며, 실제 호출·승인은 아직 없다. 필요한 효과 본문/최신 세트/언어/정오표 반영 범위는 실제 응답으로 확인한 후 기본 공급원으로 채택한다.
- [공식 Rules Hub](https://playriftbound.com/en-us/rules-hub/)는 카드 정오표를 별도로 제공한다. API 원문과 시행일이 확인된 정오표를 따로 저장하고, 정오표를 적용한 판정용 본문을 구성하는 안을 권고한다. API/갤러리에 정오표가 즉시 반영된다고 가정하지 않는다.
- [리프트나루 약관](https://www.riftnaru.com/terms)은 원천 동기화와 한국어 비공식 번역을 명시한다. 내부 공급원/API/실제 갱신 일정은 확인하지 못했다. 원천/버전/전체 목록 보장을 포함한 JSON 제공 협의가 가능하면 브라우저 화면 수집보다 안정적인 대안이다.
- 운영은 출처 확인 시각과 실제 데이터 버전을 구분하고 로컬 정상본을 계속 제공한다. 여러 공급원이 다를 때 다수결/최신 다운로드 시각으로 결정하지 않는다. 공식 정오표·적용일·정확한 카드 ID를 우선 확인하고 충돌을 보류한다.

우선순위: **운영자 제공 API/정기 JSON → 자동 접근이 허용되고 안정적인 공개 페이지 → 수동 내보내기 파일**.

2026-10-18 조사에서는 직접 HTTP가 확인 화면에 막혔다. 현재 제공 API나 안정적 자동 경로가 있다고 확인한 상태가 아니다. 구현 때 제공 경로부터 재확인한다. 확인 화면·로그인·403에 막히면 자동 수집을 보류하고 기존 DB를 유지한다. 429는 Retry-After를 따른다. 수동 JSON도 동일한 검사·게시 절차를 거쳐 반영한다.

운영자 문의에서 확인할 내용은 전체/변경분 제공 방법, 갱신 주기·호출 제한, 본문·한국어·이미지·AI 입력의 사용 범위와 표기 조건이다. 사용자의 기존 시험 사용 결정과 공급자의 허가는 별도로 기록한다.

## 3. 처리 흐름

`출처 버전 확인 → 변경분 수집 → 정규화·이전본 비교 → 검사 → 새 자료 묶음 저장 → 활성 포인터 교체`

- 기본 **24시간마다 변경 확인**, **7일마다 전체 목록 대조**. 관리자에게 ‘지금 카드 갱신’ 제공. 출처 제한이 있으면 그에 맞춘다.
- 버전·ETag·Last-Modified로 불필요한 다운로드를 줄인다. 변경 정보가 없는 출처는 하루1회 전체 내보내기를 받아 내용 해시로 비교한다.
- 페이지 단위 수집은 완료 위치/실패/재시도 시점을 SQLite에 저장한다. 기본 동시1건·요청 간격2초로 시작하고 출처 조건에 맞춘다.
- 카드명·본문·수치·이미지 주소 등 내용 해시와 수집 시각을 분리한다. 내용이 같으면 새 자료 버전을 만들지 않는다.
- 이미지 파일 전체와 모든 한국어 번역을 반복 생성하지 않는다. 카드 자동완성은 계속 로컬 검색으로 처리한다.

## 4. 카드 식별과 품질 검사

- 기존 앱 카드 ID는 유지한다. 출처 ID/세트/카드 번호/언어/그림 판본을 구분하고 이름만으로 병합하지 않는다. 같은 규칙상 카드의 판본 연결은 근거 있는 식별자로 관리한다.
- 언어별 출처 버전·내용 해시·수집일을 보존한다. 영문이 바뀌었는데 한국어가 이전 본문이면 최신 번역이라고 묶지 않는다.
- ID 중복, 필수 이름, 수치 형식, 본문/기호 누락, 페이지네이션 완료 여부, 파일 크기와 출처 URL을 검사한다. 새 ID로 바뀐 기존 카드는 무조건 신규 카드로 확정하지 않는다.
- 형식 정상이고 변경 근거가 확인된 신규·수정 카드는 자동 반영한다. 기존 본문의 갑작스러운 공백, ID 충돌, 공식 정오표와의 충돌은 해당 변경을 보류한다. 전체 목록10% 이상 감소/본문20% 이상 급변은 초기 보류 기준으로 제안하며 첫 실제 수집 결과로 조정한다.
- 불완전한 목록으로 기존 카드를 삭제하지 않는다. 전체 목록에서 두 차례 연속 사라지면 `sourceMissing`으로 표시하고 기록을 보존한다. 목록 누락을 대회 사용 금지로 해석하지 않는다.
- 출시 예정 여부, 대회 사용 가능 여부, 정오표 적용일은 각각 관리한다. 확인되지 않은 내용을 모델이 카드명으로 추측해 채우지 않는다. 공식 검증 상태를 자동 승격하지 않는다.

## 5. 서버를 유지하는 게시 방식

- 카드 후보를 준비한 뒤 **게시 직전 활성 자료 버전**을 다시 읽어 최신 규칙·Q&A와 합친다. 다른 수집기가 먼저 게시했으면 새 활성본으로 다시 합쳐서 자료가 되돌아가지 않게 한다.
- 후보 전체 검사 후 기존 `stageRelease`/`activateRelease`로 게시한다. 실패 시 현재 정상본을 유지한다. 반복 게시해도 내용이 같으면 새 묶음을 만들지 않는다.
- 앱은 기존 방식으로 최대10초 뒤 새 질문에 반영한다. 답변 중인 요청은 시작 시점의 카드·규칙·사례 버전을 끝까지 사용한다.
- 이전 카드 ID와 과거 제보의 근거 스냅샷을 보존한다. 질문 작성 중 선택한 카드가 바뀌거나 사라졌다면 재확인을 안내하며 다른 카드로 바꿔 넣지 않는다.
- 롤백 시 자동 수집기가 즉시 다시 덮어쓰지 않도록 카드 갱신 일시 중지/특정 후보 보류 상태를 둔다.

## 6. 관리 화면과 비용

표시: 적용 버전/마지막 성공/다음 확인/신규·수정·출처 누락·보류 건수/실패 이유/영한 본문 상태. 버튼: 지금 갱신, 변경 내용 보기, 보류 자료 검토, 이전 버전 복구.

**수집·변경 비교·자동완성의 AI 호출0회**를 기본으로 한다. 질문 시 선택한 카드와 관련 근거만 AI에 전송한다. 번역 캐시는 카드 본문 해시가 바뀐 항목만 무효화한다.

## 7. 구현 순서와 완료 기준

1. 공급 경로 확인과 어댑터 작성.
2. 기존 JSON 가져오기를 후보 생성 방식으로 전환하고 변경 비교/검사를 공통화.
3. 체크포인트·일정·재시도·동시 게시 충돌 방지 연결.
4. 관리자 상태/보류/복구 UI 연결.
5. 요청받은 검증 단계에서 신규·수정·공백·부분 목록·삭제 표시·실패 복구·동시 갱신·질문 중 버전 유지 확인.

안정적인 원격 경로가 실제 연결돼 정기 갱신과 앱 반영까지 확인되어야 ‘자동 갱신 완료’로 보고한다. 수동 가져오기만 연결된 상태는 따로 표시한다.
