## 낮 작업 우선순위

1. **검색 정확도 보강**: 이미 확보한 사례로 질문 조건과 실제 검색 결과를 비교할 진단 도구부터 준비한다. 비용/대상/타이밍/덱 문제를 구분하고 유사 사례의 다른 조건을 드러낸다. 저지 검수 전 초안을 확정 정답으로 취급하지 않는다. 평가 실행은 요청받은 범위에서 진행한다.
2. **자료 상태 화면 개선**: 현재 일반 앱의 LIVE 표기는 전체 로컬 색인 완료를 설명하지 못한다. 사례 수·확인 날짜·적용 버전을 사람이 읽기 쉽게 표시한다. 수집 완료와 판정 신뢰도는 별개로 표현한다.
3. **제보 상세 가독성 개선**: 현재 제보는 없으므로 분석 완료라고 보고할 내용도 없다. 다음 제보가 오면 원인을 바로 추적할 수 있도록 기존 저장 데이터를 정리해 보여준다.
4. **보충 기사·카드 갱신 확대**: 자동 수집이 연결되지 않은 부분을 별도 작업한다. 카드38판본의 영문 본문 공백은 원래 효과가 없는지 누락인지 확인할 대상으로 남아 있다. 제공 경로 없이 자동 수집 완료라고 표시하지 않는다.
5. **비용 화면 → 클라우드 이전 → 광고**: 기록과 운영 품질을 먼저 갖춘 뒤 진행한다. 기존 가격 예시는 최신 견적으로 취급하지 않는다.

## 운영 중 적용 원칙

- 개발과 검토는 새 릴리스 디렉터리에서 진행한다. 현재 사용자가 이용하는 버전을 실험용으로 바꾸지 않는다.
- 자료는 새 묶음을 완성한 뒤 교체하며 질문마다 자료 버전을 고정한다.
- 앱 코드는 새 작업 서버를 준비한 뒤 새 요청부터 전환한다. 기존 응답은 기본90초까지 기다린다. 공개 연결 창구/터널을 유지하는 경로를 사용한다.
- 관리 프로그램·연결 창구 자체의 재시작, 운영 DB 구조 변경, 호스팅 최초 이전은 같은 방식으로 무중단이라고 단정하지 않는다. 별도 전환·복구 준비가 필요하다.
- 코드 변경 전 백업, 범위가 명시된 점검, 적용 기록을 남긴다. 실제 답변 품질 확인을 위한 유료 호출은 요청받은 범위로 한정한다.
