# 사진 질문 기능 — 안정화 후 재검토

2026-10-21 사용자 결정: 베타 기간에는 사진 첨부를 중지한다. 다시 요청하기 전에는 켜지 않는다.

## 기존 구현과 보존 위치

- v0.1.3의 `public/app-ui2.js`: 한 장 선택, 이미지 미리보기, 10MB 제한, 질문 제출 시 data URL 변환.
- `src/server.js`의 `validateImage`/`askOpenAI`: PNG/JPEG/WebP/GIF 형식·크기 확인 후 Responses 입력 이미지로 전달하는 경로. 사진 자체는 DB에 저장하지 않고 첨부 여부만 기록했다.
- 사진 인식 정확도·다중 카드·필드 판별은 검증되지 않았다. 코드가 존재한다는 사실을 검증 완료로 해석하지 않는다.
- v0.1.3과 `backups/report-review-2026-10-21/`은 보존한다. v0.1.4는 새 UI에서 파일 입력·미리보기·전송 코드를 제거하며, 서버에서 이미지가 포함된 요청을 질문 저장/검색/AI 호출 전에 거절한다. 오래 열린 페이지에는 사진 제거 또는 새로고침 안내를 반환한다.

## 재도입 전 설계할 항목

1. 범위: 카드 텍스트 읽기 보조부터 시작할지, 전장 전체 분석까지 허용할지 먼저 정한다.
2. 카드 식별: 이미지에서 카드명 후보를 읽은 뒤 로컬 카드 ID와 연결한다. OCR 결과나 그림만으로 카드 효과를 확정하지 않는다. 판본·언어·비슷한 이름을 사용자에게 확인할 방법이 필요하다.
3. 상황 확인: 턴/우선권/유닛 상태/대상/추가 비용/숨겨진 정보는 사진만으로 확정할 수 없다. 불확실한 항목을 별도로 질문하도록 설계한다.
4. 비용: 긴 변 해상도·이미지 수·용량 제한, 전처리/압축·EXIF 제거, 호출 상한을 정하고 실제 사용량을 측정한다. 현재 모델 가격·지원 조건은 재도입 시 공식 문서로 다시 확인한다.
5. 안전한 입력: MIME 문자열 외 실제 디코딩/픽셀 수·애니메이션 제한 검토. 텍스트 안의 지시를 근거 데이터와 구분한다. 다른 사람의 얼굴·연락처가 포함된 사진 처리 안내를 준비한다.
6. 재현: 원본 사진을 저장하지 않으면 오답 분석에 한계가 있다. 인식한 카드 ID·확인된 상황·불확실 항목 등 필요한 기록을 최소화해 보관하고, 사진 보관이 필요하면 정책과 UI를 먼저 정한다.
7. 평가: 실제 휴대폰의 흐림·반사·기울기·겹침·한/영 판본과 여러 카드 사례로 식별/상황 해석/판정을 나눠 확인한다. 기존 기본형 21문항은 평가 기준으로 사용하지 않는다.

## 재개 절차

사용자가 재개 요청 → 범위/비용/기록 정책 확정 → 별도 앱 버전에서 구현 → 명시된 범위의 검증 → 기능 상태와 UI를 함께 전환. 서버 차단만 제거하거나 버튼만 다시 표시해 활성화하지 않는다. 이 문서 작성으로 API 사용·자동화·추가 수집을 시작하지 않는다.
