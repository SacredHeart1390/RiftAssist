# 제공 API 없는 카드 갱신 — 공개 화면 수집 대안

2026-10-21. 사용자 요청: 제공 주소 없이, 서버 기동 시 또는 날짜가 지나면 최신 카드 자료를 확인할 수 있는지 조사.

## 직접 확인한 범위

- 앱 내 브라우저에서 `https://www.riftnaru.com/cards` 정상 표시. 로그인/확인 화면 처리 없이 접근했다.
- 필터 없는 목록의 전체 표시는1527판본. 초기 DOM30개, ‘카드 더 보기’ 클릭 후60개.
- 한국어와 영문 모드를 각각 읽었고60개 ID가 일치했다. 영문 링크의 `?imageLocale=en-US`를 카드 ID에 포함하지 않아야 한다.
- 60개 중54개에 언어별 본문이 표시됐고 영문 화면에서 기호/키워드 접근성 라벨97개를 읽었다. 빈 본문6개가 원래 효과 없음인지는 별도 판정하지 않았다.
- 카드 번호·이름·유형·영역·수치·효과 본문·이미지 주소가 일반 카드 목록 DOM에 있다. 숨겨진 API/앱 상태/쿠키는 읽지 않았다.
- 같은 PC의 일반 서버 HTTP `/cards` 요청1회는429 Vercel 확인 화면. Retry-After 없음. 추가 자동 요청이나 확인 화면 우회는 하지 않았다. 기록: `source-updates/cards/public-page-observation.json`.
- 전체1527개 본문을 다시 수집한 것은 아니다. 카드 수가 같은 사실만으로 본문 최신성을 확정하지 않는다.

## 판단

제공 API는 필수가 아니다. 브라우저에 정상 표시되는 공개 카드 목록을 읽어서 기존 JSON 검사/게시 파이프라인에 넣는 경로가 있다. 다만 **현재 앱 내 브라우저에서 접근 성공**과 **독립적인 무인 브라우저 수집기 실행 성공**은 별개다. 일반 HTTP에서429가 나므로 단순 반복 요청 예약만으로 최신화가 가능하다고 판단하지 않는다.

현재의 정상 브라우저 경로는 Codex가 연결된 동안 수집을 돕는 임시 수단이다. Codex 대화/모델 호출에 의존하지 않는 상시 기능은 집 PC의 별도 브라우저 실행 환경을 구성하고 확인해야 한다. 별도 브라우저에서도 확인 화면이 뜨면 해당 실행은 중단하고 기존 자료와 실패 기록을 유지한다.

## 권장 실행 방식

1. 별도 수집기가 시작되면 마지막 완료 시점과 출처 대기 시간을 읽는다.
2. 마지막 완료 후24시간이 지났거나 성공 기록이 없으면 확인 작업을 예약한다. PC가 꺼져 놓친 일정은 다음 실행 때1회 처리한다.
3. 공개 서버 시작/이용자 응답은 기다리게 하지 않는다. 수집은 별도 프로세스에서 진행한다.
4. 계속 켜져 있으면24시간마다1회 처리한다. 서버 재시작을 반복해도 같은 날 계속 수집하지 않는다. 역일 자정 기준은 필요하면 Asia/Seoul 날짜로 변경할 수 있다.
5. 해당 기능과 함께 관리 프로그램의 기동 확인/운영 시작 요청을 연결할 수 있다. 현재 관리 백엔드에 새 기동 훅을 적용한 것은 아니다. 우선 별도 수집기의24시간 일정만으로도 사용자 요구의 날짜 경과 확인을 충족할 수 있다.

## 한 번의 수집

1. 수집 전용 브라우저/프로필로 공개 `/cards`를 연다. 사용자 개인 로그인 브라우저와 분리한다.
2. 필터 해제 상태·상세 보기·표시 총수·언어 선택 상태를 실제 화면에서 확인한다.
3. ‘카드 더 보기’를 순서대로 사용해 표시 총수만큼 수집한다. 진행 중 ID/개수/실패를 체크포인트로 보존하고 중복 실행은 잠금으로 방지한다.
4. 한국어·영어를 모두 읽고 URL의 pathname에서 추출한 카드 ID로 합친다. 서로 다른 언어에서 ID 누락/총수 불일치/본문 구조 변경이 생기면 적용을 보류한다.
5. 본문의 이미지 alt, role=img의 aria-label을 비용/영역/위력 기호로 보존한다. 영문 화면에 한국어로 표시되는 키워드 버튼은 접근성 라벨의 영어 이름을 이용한다. 단순 textContent만 저장하면 기호가 빠지므로 사용하지 않는다.
6. 가격·광고·페이지 스타일·다운로드 시각을 비교 대상에서 제외한다. 이미지 전체 파일은 내려받지 않는다. 카드 ID·이름·본문·수치·그림 주소 등의 의미 있는 필드만 이전 데이터와 비교한다.
7. 현재 source-updates/cards/inbox의 schemaVersion1 내보내기 형식으로 저장한다. 완전한 목록일 때만 all-N-artwork-listings-observed 표기를 사용한다.
8. 이미 구현된 카드 비교/보류/자료 게시 절차로 넘긴다. 변경 없음이면 새 자료 버전을 만들지 않는다. 변경 자료 게시 후 앱은 기존10초 확인 주기로 반영한다.

**카드 수·첫 페이지·웹페이지 ETag만으로 ‘변경 없음’을 판정하지 않는다.** 같은 ID의 효과 문구/번역/수치 수정까지 잡으려면 전체 본문 비교가 필요하다. 사이트가 신뢰할 수 있는 변경 시점/변경분을 공개하면 이후 최적화한다.

## 구현 전 확인할 점

- 독립 브라우저가 정상 공개 페이지를 열 수 있는지, 확인 화면 없이 반복 실행 가능한지.
- 전체 목록 로딩 중 DOM 개수/언어 선택이 바뀌지 않는지, 화면 구조와 수집 스키마가 기존1527개와 맞는지.
- 최대 실행 시간/페이지 수/응답 크기/메모리 제한. 제한을 넘으면 실패로 남기고 활성 DB 유지.
- 브라우저 종료와 프로세스 재개, 중복 실행 방지, 기존 수집기와의 게시 충돌 처리.
- 시간표·완료일·원본 수집일·갱신 실패를 관리 화면에서 구분.

실행 방식은 우선 화면을 표시하는 일반 브라우저로 접근 가능성을 확인한 뒤 결정한다. 백그라운드/헤드리스에서도 동일하게 열릴 것으로 가정하지 않는다. 브라우저 보안 우회 옵션·지문 위장·인증 쿠키 복사로 차단을 피하는 방식은 사용하지 않는다.

## 비용 및 현재 적용 상태

완성할 독립 수집기는 페이지 읽기/문자열 비교만 수행하므로 OpenAI API 호출이 필요 없다. 대신 브라우저 실행 중 PC 메모리·CPU·네트워크를 사용한다. Codex 예약 작업으로 매번 모델에게 읽게 하는 방식은 Codex 사용량이 생기므로 상시 운영의 우선안으로 삼지 않는다.

이번 후속에서는 조사/설계 문서만 반영했다. 서버/터널/수집기 재시작, 카드 DB 교체, 반복 수집 일정 등록, 테스트 실행, 유료 AI 호출은 하지 않았다. 현재 운영은 기존 `inbox` 모드 그대로다.
