# 실제 사용자 흐름 E2E

기존 Node `node:test` 러너와 임시 서버/DB 도우미를 재사용하고, Playwright Library 1.62.1로 실제 headless 브라우저에서 화면을 조작한다. 기존11개 회귀 테스트는 검색 조항·API 계약·복구/정산을 검사하고, 이5개는 실제 화면·폼·키보드·진행 상태·오류 회복·모바일 배치를 검사한다. 같은 백엔드 검사를 복사하지 않았다.

## 실행

`tests/`에서 일반 Node/npm 환경이라면 처음 한 번:

```text
npm install --ignore-scripts
npx playwright install chromium
npm run test:e2e
```

이미 설치된 Edge를 이용하려면 Windows PowerShell에서 `$env:RIFTASSI_E2E_CHANNEL='msedge'`를 지정한다. 이번 환경에는 번들 Playwright가 이미 있어 설치 없이 NODE_PATH로 재사용했다. 실제 실행은 Node24.19.0 + Playwright1.62.1 + headless Edge156.0.4314.42였다. 운영 중인 브라우저 프로필은 사용하지 않는다.

회귀 테스트는 기존 `npm test`로 별도 실행한다. 현재 GitHub Actions 워크플로는11개 회귀 테스트만 실행하며, E2E를 CI에 추가하는 변경은 이번에 하지 않았다.

## 발견 및 수정

**UI-001 초기 연결 실패가 무한 대기처럼 표시됨:** 기존 `app-ui5.js`는 `/api/health` 실패를 빈 catch로 무시해 ‘연결 상태를 확인하고 있습니다’와 비활성 버튼이 계속 남았다. 브라우저에서 상태 조회를 끊어 재현했다. 기존 안내 영역에 한국어/영어 연결 실패·새로고침 안내를 표시하고, 상태 조회 자체에도10초 제한을 적용했다. 언어를 바꿔도 실패 상태를 잃지 않도록 상태값을 보존한다. 새 버튼이나 기능은 추가하지 않았다. 서비스 워커 캐시 이름과 정적 파일 해시도 갱신했다.

초기 브라우저 실행은 시스템 프록시 때문에 로컬 주소 접속이 지연되었다. 테스트 브라우저에 `--no-proxy-server`를 지정한 뒤 앱 기준 실행에서3통과·2실패였다. 이 중02는 테스트가 공식 원문의 ‘턴마다’를 ‘한 턴’으로 가정한 작성 오류로, 고정 자료의 정확한 한국어 원문과 비교하도록 고쳤다. 나머지04가 실제 앱의 UI-001이었다. 수정 후5개 모두 통과했다. 초기 자료는 `../results/e2e-initial.tap`, 앱 기준 수정 전 결과는 `../results/e2e-baseline.tap`에 보존했다.

## 모킹·격리·한계

- 브라우저→실제 앱 HTTP/정적 화면→실제 질문 처리 코드까지 사용한다. 서버의 OpenAI fetch만 정해 둔 JSON 또는429 응답으로 바꾸고,1200ms 지연도 이 경계에서 만든다. 초기 연결 실패와HTTP503은 브라우저 라우팅에서 주입한다.
- 별도 임시 자료/DB/키/무작위 포트를 사용한다. 실제 API 키·운영 `.env`·사용자 기록을 읽거나 전송하지 않는다. 테스트 외부 요청은 차단하며 카드 이미지는 빈 응답으로 처리한다.
- PWA 서비스 워커는 요청 모킹을 우회하지 않도록 차단한다. 따라서 실제 오프라인 모드·캐시 갱신 과정은 검증하지 않았다.
- 모바일은390px 브라우저 에뮬레이션이다. 실제 iOS Safari/Android 단말, Firefox/WebKit, 공개 도메인/Tunnel, 실제 OpenAI 정확도·속도·요금은 검증하지 않았다. 이미지 입력은 현재 비활성화되어 대상에서 제외했다.
- 코드와 테스트를 로컬 파일에 반영했다. 운영 서버를 켜거나 재시작/재배포하지 않았다. 정적 화면 파일은 동일 릴리스에 있어 새 화면 로드 시 반영될 수 있으며, 이전 PWA 캐시가 있는 창은 새로고침이 필요하다.
