# 핵심 규칙 판정 회귀 테스트

현재 기본 대상은 **v0.2.0**입니다. `npm test`는 기존 회귀·정책·환경 28개, 카드 번역 28개, 동기화 34개, 관리자 검토 29개(총 119개), `npm run test:legacy`는 수정하지 않은 v0.1.7 회귀 11개, `npm run test:e2e`는 브라우저 13개를 실행합니다. 합성 자료·임시 DB/키·모의 외부 응답만 사용하며 실제 유료 API를 호출하지 않습니다. 관리자 검토는 서명/권한·일괄 결정·원문/번역/경고·충돌/오래된 후보·부분 승인본·최종 활성화/롤백·감사 장애 복구·자식 프로세스 파이프를 검사합니다. 최신 결과는 [관리 검토 보고서](../artifacts/card-review-2026-10-28/README.md), 기존 범위는 [동기화 보고서](../artifacts/card-sync-2026-10-28/README.md)와 [번역 보고서](../artifacts/card-translation-2026-10-28/README.md), 구조는 [v0.2.0 안내](../releases/v0.2.0/README.md)를 참조하세요. 아래는 최초 테스트 구축 당시의 자료·판정 근거 및 이력입니다.

대상: `releases/v0.1.7/src/`. 기존 테스트 러너나 테스트 파일은 없었으므로 Node 내장 `node:test`와 `assert/strict`를 사용한다. 패키지 설치나 운영 코드 변경은 필요 없다.

## 실행

이 폴더에서 Node 22.13 이상으로 `npm test`를 실행한다. npm 없이 실행할 때는:

```powershell
node --test --test-concurrency=1 ruling-regression.test.cjs
```

다른 릴리스에 적용할 때는 `RIFTASSI_TEST_RELEASE`를 지정한다. 기본값은 `v0.1.7`이며 운영 중인 릴리스나 자료 포인터를 자동으로 따라가지 않는다. Node 내장 기능만 사용하며 이번 실행 환경은 Node v24.19.0이다.

01/04는 검색 근거의 포함 여부, 05/09/10/11은 판정 보조 로직, 나머지5건은 테스트 전용 `server.js`를 띄워 HTTP 질문 요청부터 응답·기록까지 확인한다. 모의 답변의 정답을 그대로 되돌리는 것만 확인하지 않고, 실제 외부 호출 입력에 필요한 원문이 포함되는지, 인용 필터와 복구 횟수·정산이 맞는지도 확인한다.

AI의 새로운 의미 추론 능력·전체 판정 정확도는 이 모킹 테스트의 검증 범위에 포함되지 않는다. 기존 사례6960의 피해 사이 반응 가능 설명은 현행158.3 및 현재 유성 문구와 충돌하므로 정답 자료에서 제외했다. 출처 없는 카드 조합, 불명확한 신규 정오표, 확정되지 않은 최신 판정은 정답을 추측해 추가하지 않았다.

## 격리 및 모킹

- 각 HTTP 사례는 별도 임시 DATA_ROOT, 별도 SQLite·키, 임의 로컬 포트의 자식 서버를 사용한다. 실행 중인3001/3012 서버·운영 DB·`.env`·관리자에 접근하지 않는다.
- 자식 프로세스에 실제 API 키와 NODE_OPTIONS를 상속하지 않는다. `--require helpers/mock-external.cjs`가 `fetch`를 교체한다. OpenAI는 지정된 응답만, RiftJudge 검색은 고정 빈 목록만 반환한다. 그 외 요청과 계획하지 않은 추가 AI 호출은 테스트 실패로 처리한다.
- 임시 서버를 종료한 뒤 생성 위치를 확인하고 임시 폴더만 정리한다. 운영 파일·지식 자료는 읽거나 변경하지 않는다. 테스트에 사용하는 고정 원문은 이 폴더의 fixture에 한정한다.

## 실행 결과와 남은 문제

최종 실행: **11개 모두 통과**, 실패/skip/todo0. 결과 원문은 `results/latest.tap`.

최초 테스트 구축 때는8통과·2실패였다. 03번은 테스트의 JSON 줄바꿈 비교 오류를 수정했다. CI 구축 전 재실행에서는9통과·1실패로 RULE-001을 재확인했고, `answer-quality.js`의 한국어 불확실성 정규식을 판정·결론·시점·순서 등의 문맥으로 좁혀10번이 통과했다. 실제 근거 부족도 계속 감지하는11번을 추가했다. 상세는 `KNOWN_ISSUES.md`에 기록했다.

실패를 skip/todo나 잘못된 동작을 정답으로 바꾸어 숨기지 않았다. 현재 테스트 명령은 종료 코드0을 반환한다. 수정은 로컬 소스에만 적용했고 운영 프로세스 재시작·배포는 실행하지 않았다.

## GitHub Actions CI

브라우저 사용자 흐름은 별도 `npm run test:e2e`로 실행한다. [E2E 안내](e2e/README.md)에5개 시나리오·환경·모킹·결과와 한계를 정리했다. E2E에는 개발 의존성 Playwright1.62.1이 추가되었지만, 기존 회귀 테스트 명령과 CI는 계속 Node 내장 기능만 사용하므로 설치·캐시 단계가 필요 없다.

저장소 루트 `.github/workflows/rules-tests.yml`에서 모든 Push와 Pull Request의 생성·업데이트·재오픈, 수동 실행을 처리한다. Ubuntu와 Node24에서 위와 동일한 명령을 실행한다. checkout깊이1, 읽기 권한, 같은 PR/브랜치의 이전 실행 취소,5분 제한을 적용한다. 의존성이 없어 설치·캐시·빌드·Secrets 설정은 생략한다.

현재 작업 폴더 전체 구조를 저장소 루트로 삼는 경로다. 업로드 시 `.github/workflows/rules-tests.yml`, 테스트 폴더 및 `experiments/unified-rulings/releases/v0.1.7/`의 필요한 앱 파일을 포함한다. 통합본을 저장소 루트로 재배치한다면 workflow의 working-directory를 `tests`로 조정해야 한다.

아직 로컬 프로젝트는 Git 저장소가 아니므로 GitHub 실행 결과는 없다. 저장소에 파일을 올리고 Actions 사용이 허용되어 있는지 확인한다. Secrets는 추가하지 않는다. 필요하면 첫 실행 후 브랜치 보호/Ruleset에서 **Rules regression**을 필수 검사로 선택한다. GitHub 설정과 Secrets는 이번에 변경하지 않았다.

참고: [GitHub Node 테스트 안내](https://docs.github.com/en/actions/tutorials/build-and-test-code/nodejs), [setup-node v6의 캐시 설정](https://github.com/actions/setup-node/blob/v6/README.md).
